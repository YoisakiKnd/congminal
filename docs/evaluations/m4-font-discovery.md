# M4 字体发现：资源准入与查询复用

2026-10-25。字体目录、发现时读取的表头/name 表、名称解码和保留的字体记录已接入 `font-discovery-reserved`。不再先收集所有文件路径；名称只在发现时转换为小写，查询返回共享记录，常规/粗体选择也不再创建候选数组。没有新增 Rust 包、线程或运行时子进程。**这是字体发现阶段的验证，不代表完整字体管线、完整 M4、完整堆/RSS 或原生交互延迟已验收。**

## 资源与工作边界

扫描或显式文件读取先申请 1 MiB 临时工作额度，失败直接返回标记为不完整的空目录，不开始文件 I/O。这份预留覆盖路径、同时存活的有限表缓冲、解码及转换临时请求；返回的目录索引、路径、原始名称、小写名称和 Arc 控制块另外持有按实际容量计费的票据。目录索引扩容先预留旧、新块的重叠费用。

记录通过私有 Arc 共享；最后一个拥有者先销毁控制块，再释放名称/路径，最后归还票据。查询结果或选中的字体可以比扫描目录活得更久，不提前归还额度。四个并发拥有者的最后释放经过八轮回归。小写转换保留 Rust 原有 Unicode 上下文规则，例如希腊文末尾 Sigma，没有改成逐字符近似转换。

| 范围 | 上限 |
|---|---:|
| 目录递归 | 根目录深度 0，最多深入到 6 |
| 扫描条目 / 字体文件 | 65,536 / 8,192 |
| 一个 TTC 的 face | 64 |
| 返回目录的 face / 记录元数据 | 8,192 / 16 MiB |
| 路径 / 每个名称 UTF-8 / 每个 face 名称数 | 16 KiB / 1,024 B / 64 |
| 单次前缀读取 / 单个 name 表读取 | 64 KiB / 256 KiB |
| 累计 name 表读取 / 名称解码输入工作 | 64 MiB / 16 MiB |
| 表目录查找与名称描述符的累计记录额度 | 1,048,576 |

记录元数据的 16 MiB 是目录内保留记录的限制，索引和临时工作另计；正在构造、尚未插入的一个记录也先经过全局准入，不能把这项软限制当作整个发现阶段的 16 MiB 峰值。名称解码按两遍输入工作计费，固定小表跳过重复原始区间，防止反复引用同一段数据放大解析；表目录查找只遍历前缀实际包含的完整记录。超出限制或准入失败设置 `limited`，字体加载汇总一次警告，沿用已有字体/点阵降级规则。

Unix 文件以非阻塞标志打开后检查是否为普通文件；元数据只查询一次。但文件系统 open/stat/read 仍可能在内核内等待，标准库目录枚举与文件析构也未证明可在硬期限内取消或确认 close。这轮不关闭慢盘/NFS、原生窗口延迟及目录隔离候选的待办。

## 分配与失败回归

[当前工具链](m4-font-discovery-allocation.json)与 [Rust 1.88](m4-font-discovery-allocation-msrv.json)均使用临时副本中的全线程、按 epoch 标记的 Rust 请求计量器，保守计入 realloc 的旧、新请求重叠。测试框架、预算上下文首次初始化、环境/文件夹及输入夹具预先建立；不包含计量器附加头、分配器保留、C/OS、实际栈和全部字体加载对象。

- 合成 sfnt 经真实文件、表头和 name 表路径读取 64 个 1,024 B 名称：存活请求 134,864 B，账本 134,880 B；请求峰值 266,722 B，账本峰值 1,314,528 B。目录释放后共享记录仍保留 134,352 B 请求，最后引用释放后请求与额度均归零。
- 本机系统目录存活请求 247,519 B，账本 260,367 B；当前工具链请求峰值 346,802 B，1.88 为 346,787 B，均在预留内。只保留选中记录时请求/账本为 263/279 B，最后归零。控制块使用保守费用，账本比实际请求多出的空间没有解释成实际 RSS。
- 满额度拒绝文件读取时没有新增分配。名称数、描述符、累计解码、表头扫描、目录条目、face 数、目录元数据上限和并发释放另有六项常规回归。
- 新增的独立短 Unicode 查询探针发现 `İ` 的 2→3 B 小写转换会同时请求 2+8 B，旧预留只有 6 B，账本峰值 8 B，见[保留的失败](m4-font-discovery-unicode-before-reserve.json)。现预留增加小字符串最小扩容空间；两工具链七种空/ASCII/Unicode/1,024 B 查询均通过，`İ` 请求峰值 10 B、预留峰值 14 B，长查询 3,072/3,080 B，最终均归零。9 B 根额度在转换前拒绝，不先分配后补票。

[完整回归](m4-font-discovery-build.json)：普通版 **536** 项、预览主程序 **539** 项及认证 helper **18** 项通过；专用忽略分别 38/39 项，并非全都执行。Rust 1.88 的字体相关 47 项、三目标静态 Clippy、格式和默认 release 构建通过。Windows/Linux 交叉检查继续只算静态证据。

增加资源分类使本机 Budget/Stats 变为 272/224 B。[文件任务额度回归](m4-font-discovery-file-quota.json)仍保留 9 MiB I/O 余量，16 MiB 子池没有提高；最大字段请求 2 个运行、11 个排队后由额度拒绝，最终请求及父预留归零。[Workspace 回归](m4-font-discovery-workspace.json)覆盖实际目录选择、路径/源审阅、重试、66 个记录、认证与退出及迟到输入；请求峰值 1,957,933 B，最后请求、子池、SFTP 父预留均归零。预热后的各模态直接绘制仍零新增分配。这些夹具的成功不代替真实 SSH/SFTP 原生窗口验收，也不能推广为整个应用每帧零分配。

## 同负载性能与成本

[最终性能记录](m4-font-discovery-cost.json)把完全相同的夹具分别注入[改动前冻结源码](baselines/m4-font-discovery-before.tar.gz)和当前临时副本，均使用生产 System 分配器。每个场景、每个版本先做两次整次预热，再五组交替；使用本机相同系统字体环境。每次扫描五个新目录、查询五批各 1,000 次、加载五次默认 Fonts；查询计时只含 `find` API，不含后续指纹验证和结果析构，加载计时不含随后用于验证的实际字形生成。不是冷盘、首次启动或原生输入到显示测量。

| API 场景 | 五组配对耗时中位变化 | 配对范围 |
|---|---:|---:|
| 新目录扫描 | −1.53% | −6.18% ～ +0.71% |
| 已缓存目录的混合名称查询 | −98.01% | −98.08% ～ −97.95% |
| 默认字体加载 | −6.87% | −8.92% ～ −6.02% |

查询的每次 API 耗时按各批总时间折算，中位约从 55.4 µs 降到 1.10 µs，包含逐次 Instant 开销。扫描改善较小且存在波动，不宣称稳定的大幅加速。每轮目录均为 **803 face / 1,161 名称**，当前没有触发限制；所有目录、查询结果及默认字体的 A/中文/雪人/ZWJ 家庭字形指纹一致。覆盖的是本机字库与这些样本，不能据此宣称所有字体完全等价。

macOS `/usr/bin/time -lp` 同时记录整个测试进程的 CPU 和 RSS 高水位，包含框架、验证、析构及字体映射/缓存。扫描、查询、加载的 RSS 配对中位变化分别 **+112 / +64 / −16 KiB**，范围分别为 0～+176、−16～+96、−112～+48 KiB。保留小写名称和共享记录增加了元数据成本，没有把查询提速写成零内存代价。CPU 差值中位分别约 0、−0.27、−0.01 秒，系统工具只有 0.01 秒分辨率，尤其短扫描/加载不能精确归因。无运行时子进程增量；这不是稳态 RSS 或完整资源上限。

早期的[扫描成本](m4-font-discovery-cost-before-metadata-reuse.json)和[分配记录](m4-font-discovery-allocation-before-directory-budget.json)保留各自当时源码身份，不用来代替最终结果。[证据核对](m4-font-discovery-audit.json)核对六份当前报告的源码、清单、工具/注入夹具、归档原始源码与资源、指纹及释放状态。
