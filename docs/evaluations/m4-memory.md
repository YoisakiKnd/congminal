# M4 共享账本第一批评估

日期：2026-10-21；macOS arm64，Rust 1.99.0，offline release。新增 Cargo 依赖为零，采用标准库 Mutex/Arc/OnceLock 与所有权票据；没有新增采样线程或后台轮询。实现、配置、计费范围和缺口见 [资源准入说明](../execution-m4-memory.md)。

## 方案与边界

按需准入，而非每帧扫描全部终端。进程默认共享一份 512 MiB 混合额度，覆盖画布容量/扩容峰值、队列预留、缓存成本模型和字体堆回退；字体映射单独默认 1024 MiB / 128 个。LatestTask 工作线程继承父任务的额度上下文。测试各自使用同样的默认额度避免并行测试互相耗尽；小额度测试显式共享一个实例，以验证跨会话拒绝和线程归还。

本批不是完整受管堆或 RSS 账本：历史、网格、解析/重排/解码临时缓冲、哈希桶等索引仍有缺口。队列有保守预留，缓存也包含估计；即便 `used` 没达到限额，也不能据此推断实际堆/RSS 尚有对应空间。当前继续最多 8 会话、64 MiB 工作区历史池，不上调到路线图的 16 会话/128 MiB 目标。

缓存最初为每条记录保存票据，增大了条目。改为每个缓存一张汇总票据后，条目布局与之前一致，命中不更新账本。行索引中间版本也保留 [混合基准](m4-memory-bench-index.json) 与 [独立重排组](m4-memory-reflow-index.json)。初始结果保留在 [第一轮](m4-memory-bench-initial.json)，汇总票据版本在 [中间对照](m4-memory-bench-aggregate.json)。两次均观察到历史重排较基线变慢；[独立重排对照](m4-memory-reflow-isolated.json)确认该现象，虽然当时重排源文件与基线逐字节相同，仍继续优化其行索引分配，不将未修改源码当作通过性能门槛的理由。

在 [冷路径隔离前的构建](m4-memory-bench-pre-cold.json) 中还观察到整帧约 18% 回退。缓存插入/淘汰与额度更新改为冷路径、查找保留内联提示后，再次交替测量；此改动保持资源所有权和限额规则不变。各轮原始记录均保留。

## 微基准

基线是本批开始时的本地源码快照 `/tmp/congminal-memory-baseline-01a158a4`，包括已完成的 M4 布局持久化；不是远端 alpha.5。五轮交替先后顺序，独立执行相同 release 忽略基准，源码校验值和完整样本见 [最终数据](m4-memory-bench.json)。各轮延迟先排序取 P95/P99，再取五轮中位数；事件计时只含处理/入队，不含原生输入或呈现。

重排同时包含本批的硬行快路径和行索引分配优化，不把其收益归因于记账本身。工作区渲染基准为 1600×900 四窗格，单会话全帧为 3616×2416；不能跨尺寸直接比较。

| 指标（五轮中位数） | 修改前 | 当前 |
|---|---:|---:|
| VT 吞吐 MiB/s | 66.2 | 66.4 |
| 3616×2416 整帧 ms | 6.293 | 6.352 |
| 单行更新 ms | 0.645 | 0.670 |
| 事件入口 P95 µs | 0.209 | 0.250 |
| 事件入口 P99 µs | 3.000 | 2.583 |
| 工作区入口 P95 µs | 0.208 | 0.208 |
| 四窗格整帧 µs | 1169 | 1168 |
| 四窗格局部更新 µs | 49 | 49 |
| 64 MiB 硬行重排 P50 ms | 1.895 | 0.898 |
| 硬行重排 P95 ms | 3.131 | 1.125 |

整帧约 +0.9%，单行约 +3.8%；事件 P95 增量约 0.041 µs，P50 均为 83 ns，不能把纳秒级采样差值解释成端到端输入变化。硬行重排总时长变化约 -53.7%，收益包含专门的硬行快路径与索引优化，不能外推到长软行。release 二进制为 1,793,816 → 1,849,064 字节（debug=1，相同配置）。


## 本机 GUI、空闲与压力

[最终六轮 GUI 对照](m4-memory-runtime.json)使用同一临时配置：启动当前配置 Shell，写标记后 exec sleep；计时是进程启动到 Shell 标记，不是首帧。首个样本未剔除，没有清空系统缓存。[初始组](m4-memory-runtime-initial.json)保留各自源码校验值，只在组内比较。

| 指标（六轮中位数） | 修改前 | 当前 |
|---|---:|---:|
| 启动至 Shell 标记 ms | 212.71 | 229.52 |
| 主进程 RSS MiB | 110.289 | 110.398 |
| 主进程线程 | 14 | 14 |
| 空闲单核 CPU % | 0.01084 | 0.01047 |
| 子进程 RSS MiB | 1.016 | 1.016 |
| 子进程单核 CPU % | 0.00000 | 0.00000 |

默认没有新增线程；唯一子进程为测试 Shell 的 sleep。RSS 中位数差约 +0.109 MiB，空闲 CPU 差约 -0.00037 个单核百分点。当前组启动变化约 +7.9%，初始组约 -4.8%，方向不一致，尚不能确认稳定的启动成本或宣称通过 5% 启动门槛；该项仍需扩大受控样本。两组均保留原始值，启动/RSS 绝对值也不与此前异时的 M4 评估拼接。


[一分钟四窗格压力](m4-memory-stress.json)：4 个实际 PTY，每 67 轮调整宽度、每 257 轮创建并关闭第五个会话，共 632,478 轮。历史约 53,280,000 B；临时第五个会话会缩减历史配额，淘汰内容不会在关闭后恢复，不解释成已装满 64 MiB。

共享已用额度约 42.77–42.77 MiB，记录的准入峰值 54.93 MiB；映射 39.18 MiB / 2 个，拒绝尝试 0。每次五秒报告都验证 canvas 额度等于所有实际画布容量，且总额度/映射数量没有越界。工作区销毁后等待后台拥有者释放，used 与 mappings 均归零；这不等于分配器将所有页立即交回操作系统。

主进程 RSS 在 20–40 秒为 111.08–111.08 MiB，40–60 秒为 111.08–111.08 MiB；起始阶段达到高水位后，20–60 秒保持稳定；一分钟结果仍不能证明长期无泄漏。采样线程 14–14，1 Hz 采样可能错过瞬时峰值。观察到 tick 最大 71 µs、按键处理最大 54 µs，仅为此负载的处理时间。

场景包含真实 PTY echo 和直接网格追加，不代表全部窗格无限刷屏的原生端到端延迟；压力 RSS 只记录主进程，未同步采样所有临时 Shell。30 分钟长测仍待完成。


压力数据采集于冷路径属性调整前，源文件校验值已保存在压力记录中；随后仅改变插入/查找的编译提示，资源所有权和压力测试逻辑未变，并重新完成普通回归、交叉检查和上述性能对照。

## 正确性与限制

本机 debug/release 回归 222 通过、11 项手动基准/压力默认忽略；fmt、本机及 Linux x86_64 / Windows GNU 的 all-targets clippy `-D warnings` 通过。跨平台编译不等于真机验收。

新增验证包括：共享额度并发/溢出/失败原子性、映射数量与重复持有、画布扩容新旧峰值和失败保留、队列容量及最后拥有者、会话准入失败不执行新 Shell、保留焦点/布局/历史配额、自然结束只读会话归还额度、后台取消/过期结果的上下文及归还、字体映射拒绝不改用堆副本、堆回退读取失败回收，以及重排索引不因追加屏幕/多插一行而倍增。

真实系统 mmap 失败、Windows/Linux GUI/ConPTY 运行、平台慢调用、30 分钟启停和完整全局回收顺序仍待完成。缓存成本模型/桶索引、字体解析和光栅化等未覆盖项继续列在计划中。低额度可能拒绝新窗格/放大画布，缓存拒收也可能影响缺字降级；本批不承诺内存不足时所有视觉行为完全不变。

最终源文件和 release 产物校验见 [构建记录](m4-memory-build.json)。改动尚未发布，不改写原 alpha 标签。
