# 原生全局 CPU/内存与 macOS 进程采样（2026-10-29）

继续内存边界与性能工作。本轮冻结上一轮未提交源码后实施；未提交、推送、合并或发布。CPU/内存和 macOS 进程路径已替换；第三方磁盘、Linux/Windows 进程及完整应用边界仍待继续。

## 实现

- 全局 CPU/内存改为原生汇总接口，不创建每核心 Vec、CPU 名字、品牌或频率对象。macOS 用固定 Mach 统计结构，缓存逻辑核心数、物理内存量及页大小；每次取得的 host send right 由作用域拥有者归还。Linux 只读 `/proc/stat` 首行（最多 2048 字节），`/proc/meminfo` 最多 64 KiB；输入完整性、数值溢出、单位和重复字段均校验，兼容没有 MemAvailable 的旧内核。Windows 用固定 GetSystemTimes/GlobalMemoryStatusEx 结构。
- CPU 按两次 busy/idle 差值计算；首次采样、计数器回退/溢出、核心数变化会重建基线，避免伪造 100%。失败明确返回 Local 错误，后台采样暂停，刷新/重开或相关配置变化才重试。Linux 读取循环在 IO 前检查取消；内核调用仍是软取消，不能保证任意系统调用的硬期限。
- [Microsoft GetSystemTimes 文档](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getsystemtimes) 明确指出，多于 64 个处理器时只返回调用线程所在处理器组。本轮检测到多组就停止该采样并提示超出支持范围，避免把部分核心显示为整机。多组 Windows 的原生完整实现仍未完成。
- 审计发现锁定的 sysinfo 0.38.4 在 macOS `System::new` 取得 host right，结构没有对应 Drop。冻结基线的独立进程诊断记录 32 次构造/销毁后增加 32 个 send refs。应用原来的进程刷新每次新建 System，不能只看 Rust 堆归零。本轮 macOS 改为 `proc_pidinfo(PROC_PIDTASKALLINFO)` 固定结构，直接读已选 PID 的名字、驻留内存、累计 CPU 时间与微秒级启动标识；不再构造这个第三方 System。时间单位按 Mach timebase 用 u128 换算，PID 重用不会混合旧计数。
- macOS 仍最多选择 512 个 PID，前 5 条进入结果。名字输入最多 32 字节、保留最多 24 个 UTF-8 字节；至多一份旧/新 512 项计数向量重叠。工作预留由 32 MiB 改为 **64 KiB**，在 PID 列表、原生记录读取及向量分配前取得；旧计数在采样器基础预留中，新计数接管后释放旧向量，结果由已有回复预留承接。拒绝/权限不足/进程退出报告部分采样。Linux/Windows 的选定 PID 仍走 sysinfo，保留 32 MiB 工作模型，本轮没有证明它们在任意主机上的全部内部工作上界。

磁盘本轮保留原有最大可写外层卷选择规则和降频，尚未替换其枚举及属性读取。采样器基础预留仍为 256 KiB；不能把本机结果当成任意磁盘/挂载规模的完整上界。

## 依赖与成本

没有新增软件包或版本。已在锁文件内的 libc 0.2.191 变为 Unix 直接依赖，提供固定 ABI 类型/调用；sftp-libssh2 不再单独激活它，Windows 不引入这项 Unix 依赖。`Cargo.lock` 与基线相同，sysinfo 继续供磁盘及 Linux/Windows 进程使用。没有新线程、子进程或动态运行服务。

冻结前/当前源码在同一台 macOS arm64 上交替测量，System 分配器；每项两组预热，再五组配对。CPU 汇总计时每次间隔250 ms，超过旧库的 CPU 缓存间隔，配对前核对核心数及物理内存总量一致。

| 路径 | 修改前中位 | 修改后中位 | 五组配对变化中位数 |
| --- | ---: | ---: | ---: |
| 汇总 CPU/内存实际读取 | 101.541 µs | 31.958 µs | −69.27% |
| 新建 CPU/内存源及首次读取 | 35.583 µs | 8.542 µs | −75.91% |
| 完整采样器连续无磁盘调用 | 0.9 µs | 1.2 µs | +33.33% |
| 完整采样器带磁盘调用 | 10607.1 µs | 10634.1 µs | −0.003% |
| macOS 进程采样 | 3501.8 µs | 264.6 µs | −92.32% |

连续调用中旧库会合并200 ms内的 CPU 刷新，新路径每次读汇总计数，所以这一微基准增加约 **0.3 µs**；生产采样最短1秒，不能将这个缓存内连调用回退当成生产1 Hz成本，也不隐去它。带磁盘查询仍由第三方卷属性读取主导。进程集合会变化、权限失败会跳过且提示部分采样，不能把进程计时当成完全相同 PID 数据的加速证明。

完整监控测试命令的 RSS 差中位数为 −966656 字节，CPU 时间差中位数 −0.02 秒（0.01秒分辨率）；包含夹具、初始化与释放，不是 UI 稳态/RSS上界或输入尾延迟。全部配对原始值保留在 cost.json，不据此宣称整个程序都提升同样比例。

## 分配与所有权证据

生产使用 System 分配器；计量器仅注入临时副本，记录所有线程 epoch 内 Rust 请求字节，包含 realloc 旧/新重叠。稳定工具链和 Rust 1.88 分别执行。输入、调用方取消令牌和父账本在 epoch 外预建；native malloc、内核、实际线程栈、allocator 元数据与 RSS 不在该计量范围。

两套工具链得到相同结果：

| 路径 | 保留请求字节 | 峰值请求字节 | 保留费用 / 峰值费用 | 最后释放 |
| --- | ---: | ---: | ---: | ---: |
| 原生首次及200次读取 | 0 | 0 | 固定状态在已有源中 | 0 |
| 百万核心模型/有界Linux文本 | 0 | 0 | 固定栈缓冲另计 | 0 |
| 真实完整采样器（含磁盘/进程） | 12800 | 36748 | 262144 / 327680 | 0 |

完整采样器费用是所有权模型，本机峰值符合预留；磁盘在任意主机上的内部工作仍未完整证明。macOS 进程工作票据减少了31.9375 MiB，保留它的依据是512个PID、旧/新计数向量、固定原生记录和有界名字的静态上限，不依赖当时只有少量进程。

原生汇总状态在本机为固定 64 字节；首次及后续 200 次实际读数均不申请 Rust 堆。百万核心的合成汇总行不会生成核心表；无限尾部输入、64 KiB 完整及溢出输入也不会扩容。固定缓冲放在已有后台线程栈，不能称为零内存。

单独运行的 Mach 拥有权测试连续 1000 次汇总读取及 32 次真实进程刷新，前后 send right 引用数相同。该测试默认 ignored 以免其他并发采样干扰，但本轮用 exact/ignored 命令实际执行通过；不把专项未执行项目当成已验收。
