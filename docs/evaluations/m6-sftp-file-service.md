# 统一SFTP文件任务层候选

状态：目录、上传和下载已通过同一个Service/Pool执行，完成真实回环SSH传输、取消/源变化/目标保留及最大DTO计量。仍仅编译进测试，没有工作区上传/下载入口、目标确认界面或默认发布配置；完整M6不勾选。没有增加Cargo包、线程、任务槽或16MiB子池额度。M4–M8、三平台和长测继续按原目标推进。

## 请求、拥有者和结果

[Service](../../src/sftp/service.rs) 从目录专用请求/返回值扩为Action/Output。传输请求只捕获有额度的本地/远端路径、Profiles/Identity快照、Source会话/代次、超时、覆盖策略及Progress，不含File、连接或原生句柄。界面构造请求不访问文件/SSH；Backend、文件与实际传输仍在已有两个工作器内创建。排队不消耗认证期限。TransferTask交付完整Ticket、认证邮箱和独立Status，后者跨关闭/普通Completion丢弃保存发布事实及部分位置。

传输API要求绝对路径，保留原名字节及转义显示；远端文件名不为空、不是尾部点项/斜线，长度受1024字节文件名/16KiB整路径限制。上传还为同目录48字节随机临时名保留路径空间。LocalPath内的RemotePath直接共享给Status，避免再复制本地原文和显示文本。临时远端文件由工作器生成128位系统随机后缀、排他创建并请求0600；不自动复用或删除。0600请求不证明任意远端ACL/文件系统的额外权限配置。

满队列在复制路径/身份之前先拒绝；Pool::submit仍在真正提交时重新核对。这个快速拒绝避免最大字段构造耗尽临时额度，把已满队列误报为Budget。额度不足仍可独立拒绝请求，现有任务不被覆盖。目录界面读取Output::Directory，意外的传输输出按协议错误处理，不作为目录或终端输入。

结果元数据先于执行资源准入。普通传输完成返回固定Snapshot和有限Failure；清理失败仍让执行器关闭并保留Failed/Unknown，不能靠普通Completion保证可见性，调用者必须继续持有Status。文件/连接显式finish，创建或关闭失败的清理标记不会因Drop重试变成Confirmed。

## 上传与下载提交顺序

上传在工作器只读打开普通本地源，核对声明长度，逐块传输到同目录随机临时名。远端大小/可选fsync、CLOSE ACK之后再次检查本地设备/inode/长度及mtime/ctime，最后取消检查之后才RENAME。首write尝试、成功ACK、明确失败码和不确定结果沿用[固定报告](m6-sftp-transfer-report.md)语义。源文件显式关闭，再结束独立SSH/helper/端点；后续取消或清理错误不抹去已确认发布。

下载接收选择时的Version（大小及秒级mtime）。LSTAT先检查普通文件类型和版本；实际打开句柄在读取前后做FSTAT，结束后再核对路径版本。缺失属性、符号链接或不匹配都会拒绝。SFTP v3没有inode或纳秒版本；相同大小/同秒变化、检查之后的变化和远端命名空间竞争仍可能不可见，这不是不可变快照或完整路径NOFOLLOW保证。

本地输出使用已有私有同目录暂存拥有者。下载完成/远端关闭ACK、版本核对及本地sync之后，先显式结束SSH/helper/端点；只有传输结果和该清理都确认，才执行本地commit。取消或失败保留暂存位置，不提前发布目标。默认不覆盖；Replace::ExplicitlyApproved只是一项底层参数，当前还没有用户覆盖确认UI，不能将测试赋值当作用户授权。发布后分别记录目录同步和暂存清理状态，最后显式关闭本地拥有者。

真实取消发现：底层捕获流可能先返回IO错误/零字节，取消标记此时已经设置，原先会被当成协议失败。[Channel](../../src/sftp/client.rs)现在在read/write/flush的失败边界检查同一个取消标记，返回Cancelled；没有恢复执行器的事后统一覆盖，已解析的成功ACK仍优先，未确认的提交仍是不确定。新增1项测试覆盖5种IO形态回归，旧12类RENAME边界及实际执行器竞争回归继续通过。

## 真实回环验收

[工具](../../tools/check_auth_parent.py)新增`--transfer`：临时加密密钥、独立known_hosts/config、回环sshd和实际helper，只用生成的32MiB固定块文件，不访问用户SSH数据。文件大于16MiB子池，没有全文件缓冲。固定答案由夹具前端提供，不是GUI认证或真实SSH终端窗格验收。运行中的取消/修改在观察到前半段进度后注入，不声称冻结了所有网络调度。

| 场景 | 验证结果 |
| --- | --- |
| 上传、下载 | 32MiB逐块核对；上传成功ACK，下载本地发布且目录同步/暂存清理确认 |
| 两方向默认目标已存在 | 原内容保留，失败报告和部分文件位置仍可读 |
| 两方向底层显式替换 | 替换目标内容核对通过；不代表已实现用户确认界面 |
| 两方向传输中取消 | 未尝试发布，部分文件保留，明确Cancelled，清理确认 |
| 本地同大小变化、远端mtime变化 | Changed，目标未发布，保留部分数据 |
| 过期远端选择、错误认证 | 不发布目标；过期选择在创建本地暂存前拒绝 |
| 传输中关闭 | 不依赖普通Completion，实际join后Status保留取消结果 |
| 同时上传和下载 | 同一池两个方向各32MiB核对，最终清理和预算归零 |

14类均通过，原始状态/进度/发布/停止原因、进程采样及日志见[传输报告](m6-sftp-file-service-transfer.json)。单任务最大受管峰值5377439 B，双方向峰值5751504 B，均低于子池上限；这是预留账本，不是进程RSS/文件缓存硬上限。Pool/认证/结果释放后独立Status继续持有父票据，最后Status释放归零。夹具在核对部分文件仍存在后清理自己生成的目录，Service本身不递归删除用户数据。

8类原目录Service认证/取消/等待场景及12类工作区目录/认证/导航/关闭场景也通过，源码快照保持一致。[目录回归](m6-sftp-file-service-service.json)、[工作区回归](m6-sftp-file-service-workspace.json)。工作区夹具仍是携带SSH配置引用的本地测试PTY和软件画布，未接工作区文件传输/真实系统焦点/IME。

首轮成功夹具用了0xFF文件名，本机RENAME返回失败4，报告正确保持Rejected而非成功。[初始失败](m6-sftp-file-service-real-initial.json)、[状态诊断](m6-sftp-file-service-real-diagnostic.json)。无沙箱原生对照证明ASCII/UTF-8名可以创建，0xFF名返回Illegal byte sequence(92)，见[本机名称探针](m6-sftp-file-service-name-native.json)；普通沙箱探针的EPERM不用于推断文件系统能力。成功夹具改用带空格、Unicode和`; $()`的允许名称，没有转码或放宽协议原名字节规则。是否接受某些名字由目标文件系统决定，不是模型保留字节就能保证。

## 最大DTO与父额度

[全线程计量工具](../../tools/check_sftp_executor.py)`--allocation --file-service`临时复制源码并注入epoch分配器，计入跨线程分配/释放及保守realloc重叠。固定计量头、allocator/C/OS内部、实际栈/RSS不在范围；根Budget/输入/通知/Profiles快照和应用级首次线程全局初始化预先准备，新池/三线程/TLS、DTO及报告计量。替身工作器只创建有额度的系统随机临时路径候选，不执行文件/认证/网络IO。

每请求把身份显示的id/name/host/user四项分别拉满64/128/255/64字节，并用4096字节helper/config路径、各16384字节原始本地/远端路径（显示四倍转义）；原文路径由Status共享。Profiles快照预先准备并在请求间共享，探针不是全部配置组合或完整配置解析分配验证。两个活动任务另保留工作器生成的完整临时路径，后续交替上传/下载直至2活动+64等待。两工具链均准入66项，第67项Full，拒绝阶段的live/分配次数/扩容次数与准入后完全相同。
