# 受保护粘贴的归属与额度交接

状态：三平台读取入口、受保护请求/结果、认证编辑器的请求与消费接口、普通终端的安全丢弃路径已实现。认证编辑器和 SFTP 仍只编译进测试；工作区还没有打开认证面板或发出认证粘贴的真实操作入口。不能把这份记录当作完整可见认证 UI、原生剪贴板真机或 IME 归属验收。

## 行为与所有权

`PasteRequest` 区分普通和受保护读取。普通请求保留既有 Paste/PasteFailed 事件；受保护请求无论成功还是失败都返回 ProtectedPaste，不能回落成普通 Paste。macOS/Windows 同步读取和 X11 在途请求均移动同一个拥有者，不在结果到达时重新绑定当前焦点。

Editor.request_paste 在同步挑战状态后捕获 session、generation、connection、challenge serial 和唯一 view 的完整起始身份，选择 1023 字节及严格 Unicode 策略。同一编辑器只允许一个在途请求；重复请求返回 Busy，既不替换原请求，也不分配新结果槽。Editor.paste 先同步并检查 token/完整起始身份，借用拥有者的文字更新固定 Secret，不转成普通 Text 或再复制一个 String。失配结果不清除当前视图自己的在途标记。确认型提示拒绝粘贴，失效挑战先清理本地秘密。

每个受保护请求在平台读取前，直接从原 Editor 的现有共享账本申请独立 Lease，覆盖最大输出 String、元数据 Box、固定拥有者与余量。没有另建脱离应用的 Budget。该 Lease 随请求/结果移动；原编辑器关闭或重建后仍保留，直到文字和元数据实际释放。结构的 data 字段（包含 Box 和清理文字）先于 Lease 析构。

受保护结果没有 Clone/Debug/Display。成功、读取失败、无效文字、迟到、取消和无接收器丢弃路径都释放自有副本；String 的已初始化字节在释放前 volatile 清零。原生策略先限量，结果入口另检查 capacity，防止错误适配器保留超容量缓冲；这项二次拒绝不证明绕过原生准入、已创建的任意大 String 受过额度覆盖。

普通 Congminal 和 Workspace 已显式丢弃受保护结果，后者也结束在途标记；测试在真实 cat 会话和搜索栏用可见屏障验证该结果没有被写入。该默认行为是未接认证控制器时的安全兜底，后续认证控制器须先接管对应结果。

## 成本与分配证据

无新增 Cargo 包、线程、进程或定时器。普通路径只有原有解码 String，没有新 Box；探针的五字节普通请求/结果共一次五字节分配、无扩容。受保护路径每次多一个 80 B 元数据 Box，最大输出为 1023 B，两者合计最多 1103 B Rust 请求；当前每请求保守 Lease 是 1263 B。请求到结果移动同一个 Box；消费时只借用文字，除了平台解码的一个 String 不再分配输出副本。

[工具](../../tools/check_input_allocation.py) 在临时源码副本注入同线程 GlobalAlloc 计量，保留源码/夹具/清单哈希和 rustc 版本。最大输入源、共享 Budget 上下文、通知和取消对象在计量前准备，实际 Backend、Prompt、Editor、请求、结果在计量内创建。关键采样如下，当前与 Rust 1.88 一致：

| 状态 | 请求存活 | 请求峰值 | 账本存活 | 账本峰值 |
| --- | ---: | ---: | ---: | ---: |
| 编辑器创建 | 2614 B | 2614 B | 4485 B | 4485 B |
| 请求元数据创建 | 2694 B | 2694 B | 5748 B | 5748 B |
| 最大文字已读取 | 3717 B | 3717 B | 5748 B | 5748 B |
| 原编辑器已关闭、结果在途 | 1671 B | 3717 B | 1951 B | 5748 B |
| 迟到结果被新视图拒绝 | 2614 B | 3717 B | 4485 B | 5748 B |
| 完整释放 | 0 | 3717 B | 0 | 5748 B |

全部九个采样点的存活/峰值有额度覆盖，包括成功、无效 NUL 和取消路径。在 allocator **释放前**检查旧视图、成功、无效、取消共四个已初始化事件区域，4 次检查、0 次失败；不读取释放后的内存。本机 Event 为 40 B、PasteRequest 为 32 B，记录实际布局，不把 Rust 内部布局当作跨平台 ABI。

[当前工具链](m6-sftp-auth-clipboard-allocation.json)、[Rust 1.88](m6-sftp-auth-clipboard-allocation-msrv.json)。初始探针在满答案后追加 NUL，先命中容量限制，预期错误已改为选区替换以实际覆盖无效字符路径；未放宽产品输入规则，失败记录保留。

这些是 Rust 请求字节，不包括 allocator、C/ObjC/OS、RSS、线程栈或输入源的内部副本；不代表完整全局资源账本、实际剪贴板读取延迟或原生输入到呈现 P95/P99。没有重复用网络吞吐基准给本次纯平台/编辑接口改动背书。
