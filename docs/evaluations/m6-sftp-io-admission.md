# SFTP输入额度与IO余量

状态：请求元数据已独立限额，仍共用原16MiB总池、2工作器和64等待槽。最大数据请求在输入限额处拒绝，不能继续挤占工作空间；真实双方向IO压力场景已通过。仍是测试候选，工作区传输入口、完整性能对照和M4–M8余项未完成，没有新增依赖或线程。

## 同一账本的两项准入

[预算](../../src/resources/budget.rs)新增SftpInput分项及上限。总used和输入分项在同一Mutex内核对，输入票据的分类保存在原有Kind字段，离开提交线程后仍生效。增长、缩小、释放和显式额度转移都更新同一份计数；新增try_transfer_to可在目标分项不够时完整拒绝，不先归还再抢额度。降低分项上限不能低于已有票据，也不能再次提高。

Service提交期间使用只绑定目标池的SftpInputScope，将路径、身份、发布槽、报告和Job票据归为输入；文件、协议包、连接和临时路径由工作器按普通Sftp分项申请。捕获上下文使用8个固定Arc槽，没有Vec或每请求线程；不同池嵌套、非LIFO释放和异常退出都不会覆盖或遗留外层标记，超出8槽明确拒绝。Guard不能跨线程移动，票据本身可以。未匹配的预算及FontMap不受捕获分类影响。

[执行器](../../src/sftp/executor.rs)在创建任何线程之前配置分项，配置失败即释放父票据，不返回无法继续观察的后台启动。普通通用Pool保留原策略；[Service](../../src/sftp/service.rs)统一通过带IO策略的构造器启动，测试替身也使用同一个构造器，不能绕过限额。

本机固定运行时预留R=4937760 B，包含工作器/回收器模型栈、创建与固定槽。按每工作器3MiB扫描、1MiB最大包、256KiB管道和256KiB协议/身份/文件余量，保护H=9437184 B（9MiB）IO空间。输入上限Q=T−R−H=2402272 B，T仍为16777216 B。新输入同时满足总额度与Q，IO可使用未用的输入空间，没有预先为每任务分配9MiB缓冲。

这保护的是IO总份额，并非任意时刻仍有9MiB空闲，也不是每个工作器单独的硬配额。已经保留的目录结果、认证输入或其他IO拥有者也占总额度，后续IO仍可明确返回Budget。完成记录中的输入路径继续计入Q，界面须提供有界保留/释放记录，不能无限积累；释放记录不会删除磁盘部分文件。

## 压力与所有权证据

新增3项预算测试覆盖并发申请、作用域外的resize/转移、IO压力下缩小/释放、嵌套/8槽拒绝/异常恢复；新增执行器启动前失败测试，以及Service的元数据饱和后完整9MiB IO申请、IO已满份额时小请求仍能准入的测试。它不会因当前IO已使用而再次扣除整个9MiB，把本来可用的小请求错误拒绝。

真实SSH夹具新增pressure场景：先暂停两个连接的认证，在放行前捕获最大路径请求直至输入拒绝（14份压力输入，输入2331308 B，小于Q），再完成上传/下载各32MiB。第一项完成后取消压力任务，但继续保留其Status/路径，另一方向仍完成。普通Completion/数据结果、取消与独立报告的显式清理/join及最后父额度释放都有断言。它不等于固定所有网络调度，也不是GUI测试。

15类真实传输、8类目录任务和12类工作区认证/目录/关闭场景分别记录在[传输](m6-sftp-io-transfer.json)、[目录](m6-sftp-io-service.json)、[工作区](m6-sftp-io-workspace.json)。只使用生成的密钥、回环sshd和私有端点，不读取用户SSH文件。工作区仍为本地测试PTY携带SSH配置引用及软件画布，没有工作区上传/下载或真实系统焦点/IME。

## 全线程请求计量

[工具](../../tools/check_sftp_executor.py)的文件任务探针继续使用各16KiB原始本地/远端路径、4KiB helper/config及最大id/name/host/user字段。Profiles快照预先准备，不是全部配置解析分配测试。两个替身工作器保留有额度的随机临时路径；计量覆盖新池/三个线程/TLS、请求/报告、拒绝、实际IO字节缓冲、join和迟到拥有者。它没有文件/认证/网络IO。

两工具链均在13项（2活动+11等待）处触发输入Budget，保持64槽容量；小字段的2活动+64等待常规回归继续通过。该变化修正了此前只靠16MiB总上限、最大DTO可塞66项却没有IO空间的问题。不能将64槽说成任意大小输入都应塞满。

输入用量2290184 B，两个已存在的临时路径占用了164096 B动态工作额度；随后真的申请并填充剩余9273088 B字节缓冲，使动态IO份额达到9MiB。总受管预留16665128 B，低于16777216 B。当前/1.88的全线程Rust请求峰值分别11730529/11730938 B，父预留峰值16778407 B（含预先准备的807 B配置票据）覆盖。最后只保留一份Status时请求246568 B、父票据16777600 B；最后释放均归零。[当前计量](m6-sftp-io-allocation.json)、[MSRV计量](m6-sftp-io-allocation-msrv.json)。

Budget拒绝会有3次有界临时分配：第一条路径成功构造，下一次准入拒绝后释放；最终live和used与拒绝前一致。这不是Full快速拒绝，也不宣称所有拒绝都零分配。8个分配回归包括两工具链的目录、通用执行器和工作区/迟到输入，均检查请求有父预留覆盖和最终归零。计量排除epoch头、allocator/C/OS内部、实际栈/RSS，且预热已有应用级首次线程全局初始化；新线程/TLS仍计入。根预算对象、冷进程锁等M4全局元数据缺口没有据此关闭。
