# LatestTask 线程运行时与外部回收拥有者

2026-10-26。本阶段将生产 LatestTask 接入固定记录的共享回收器：创建前预留工作线程运行时/请求栈，工作器函数返回后仍由回收记录持票，原生 join 返回后才归还。不是完整 M4、所有后台线程、完整 RSS 上限或三平台运行验收。既有安装包未更新，未提交或推送。

## 创建、持票与关闭

- 生产进程只有一个共享回收器，固定 **64 个记录槽**，不动态增长。每预算池也最多保留 64 个受管工作器槽；先准入费用和槽位，再构造名字、调用 std 线程创建。字节额度可能先拒绝，数量上限不保证所有槽都可填满。
- 每工作器请求 **2 MiB 栈**，另预留 **64 KiB 运行时余量 + 两份闭包内联大小 + 256 B**；完整包装闭包限 16 KiB、名字限 128 B 且拒绝 NUL。动态捕获缓冲和工作输入/结果仍由相应子系统负责，不能因内联大小已计费就宣称所有内容已受管。
- 回收器请求 **256 KiB 栈 + 64 KiB 运行时余量**；固定状态/Arc/同步对象另预留 **5272 B**。当前 64 位 Budget/Stats 为 **368/320 B**，根账本自身公式随类型增大为 **496 B**，没有提高配置的总上限。
- 普通存活工作器发布后没有可回收内容，不叫醒回收器；退出先于句柄发布时才补唤醒，其余由退出标记通知。回收器无定时轮询。共享核心仍有独立的每池 32 槽边界，不能把“核心已销毁”当作线程已退出。
- 回收器先将句柄移出状态锁，再 join；阻塞的 TLS 析构可以阻塞回收者，但不会持有状态锁或让界面执行工作器 join。其余完成记录最多占满固定槽位，不通过新建额外回收线程绕过限制。
- 线程 panic 后 join 返回 Err 仍确认原生线程退出，记录错误并释放费用；join 操作自身异常则保留费用/槽位，关闭接收并报告 unconfirmed。失败状态不自动创建替代回收器。

主入口在创建窗口前初始化回收器并完成首次 Mutex/Condvar 引导。根拥有者不可跨线程移动；成功创建后各返回路径都会请求关闭。窗口/工作区销毁后才等待回收器，等待检查预算为 250ms；这不是严格的全程序最坏关闭上界，原生 join 尾部/调度及其他未接入线程仍须验收。超出等待预算保留费用并打印未确认信息，不将其解释为已回收。

回收器线程确认退出后归还其栈/运行时票据，固定状态本身在生产全局拥有者中继续保留 **5272 B**，属于可解释的进程生命周期元数据；私有测试实例销毁时该费用也归零。调用者的普通输入/结果析构仍可能在界面执行，不据此宣称所有关闭/交互延迟已经有界。

目录 Browser 的核心、线程和请求现在固定使用创建 Browser 时的预算池；更换当前资源上下文也不会把它们转付给另一个池。小预算测试相应增加线程预留，生产总额度没有增加。

## 实际请求：不借用栈额度掩盖堆漏计

[当前工具链](m4-task-runtime-allocation.json)和 [Rust 1.88](m4-task-runtime-allocation-msrv.json)使用同一 epoch 全线程 Rust 请求计量器。每个检查点从可覆盖堆的费用中扣除显式工作器/回收器栈预留，再检查存活与峰值；64 KiB 余量是本机探针验证的保守运行时模型，不是实际栈、C/OS、分配器或 RSS 测量。平台可能按其规则处理请求栈大小，不能将请求值当作物理驻留或所有平台精确地址空间上限。

私有新回收器从冷路径计量，父预算/上下文和测试控制标志在区间外初始化。测试 TLS 只用原子标志和 yield，属于诊断设施，不能拿它做空闲 CPU 测量。

| 阶段 | 当前工具链实际存活请求 | 可用于堆的预留 | 存活工作器槽 |
|---|---:|---:|---:|
| 新回收器及首次同步 | 4951 B | 70808 B | 0 |
| 原生 TLS 析构阻塞 | 5009 B | 136616 B | 1 |
| 满额度拒绝另一个工作器 | 5009 B，无新增请求 | 136616 B | 1 |
| 再持有正好 16 KiB 内联闭包 | 21524 B，峰值 21535 B | 235176 B | 2 |
| 所有工作器与回收器已 join | 4504 B | 5272 B | 0 |
| 私有回收器最后拥有者退出 | 0 B | 0 B | 0 |

16 KiB 边界同时保留前一个阻塞 TLS 的工作器；超限闭包另由普通回归拒绝。人工额度填充只用于测试拒绝，未当作堆覆盖峰值的证据。首次标准线程初始化/新线程 TLS 及名字等 Rust 请求在相应运行时余量内；本机 MSRV 独立报告也通过，具体分配时序以原始报告为准。

账本结构增加后，另以[当前工具链根冷探针](m4-task-runtime-root-self.json)和 [MSRV 根冷探针](m4-task-runtime-root-self-msrv.json)复核自身费用：首次根/Arc/Mutex实际 **448 B**，先扣 **496 B**；子池持有根、最后释放及拒绝零请求继续成立，未沿用旧类型大小冒充当前计量。

真实 LatestTask 区间先在区间外初始化共享回收器，线程本身仍在区间内创建。共享核心与任务对象销毁后、原生 TLS 仍阻塞时，**核心槽及 Tasks 费用已为零，但保留 2163024 B 工作器费用**，其中 2 MiB 为请求栈，扣栈后 65872 B 可覆盖堆。当前工具链本轮实际存活 445 B、峰值 905 B。TLS 释放并真正 join 后，本轮实际请求及原池费用均归零。

无确认的 join 使用独立测试进程注入，保留 **2162688 B**、1 个槽和 unconfirmed 状态，关闭接收；只确认回收器自身已 join，绝不伪造工作器退出。这个故障用例故意由与生产静态拥有者相同的存活记录持票至进程退出，不拿它作“全部归零”证据。

## 同负载成本与取舍

[成本对照](m4-task-runtime-cost.json)用同一 System 分配器夹具，两次预热后五组交替。先共同初始化标准线程全局状态和进程预算，再测当前共享回收器引导（基线为空适配器的计时底噪）；因此引导报告采用新增绝对时间，不用百分比描述空操作。

工作器阻塞时测 100×1000 次最新待办替换、100×10000 次取消轮询、100×1000 次原 Default 取消令牌生命周期；另测 100 次创建/提交/读结果/关闭。每轮等待费用回落在计时外，旧实现没有新实现的原生 join 确认，不是等价清理承诺的对照。最后一个任务必须返回 100000，语义指纹 **204200**。

| API 场景 | 五组配对耗时中位变化 | 范围 | 每次操作的分组中位（前→后） |
|---|---:|---:|---:|
| 待办替换 | -3.60% | -15.50%～+11.36% | 173.89→177.66 ns |
| 取消轮询 | +3.49% | -8.74%～+11.67% | 0.69→0.71 ns |
| Default 令牌生命周期 | -4.50% | -9.15%～+3.03% | 124.60→114.76 ns |
| 一次性任务生命周期 API | +16.08% | -1.49%～+32.68% | 15.82→18.36 µs |

配对百分比中位与分别对两组求中位的比值是不同统计量，表内不将它们混作同一计算。短 API 离散明显，不声称普遍提速。首次工作器构造每轮只有一次，五组配对中位 **+36.17%**（+19.33%～+71.88%），分组中位 **24.33→34.54µs**，样本很少且受调度影响；新增共享引导配对中位约 **45.12µs**（42.50～51.96µs）。这是有成本的准入/回收保障，不是免费改动，也不是整个应用/窗口启动时间。

初版无条件在发布工作器时唤醒回收器，成本与实现保留为 `*-before-wake-coalescing.json` 和[旧实现](baselines/m4-task-runtime-before-wake.rs)。当前只在已退出的发布竞争中补唤醒。前后两次对照各自使用同一冻结基线，没有直接配对初版与最终版，不能据两份报告把某个耗时变化归因为该优化。

500ms 独立空闲区间用 libproc 每 5ms 采样：基线测试进程 **3 个线程**，当前 **4 个线程**，所有测量组 CPU 增量均为 **0ns（采样可见值）**。它包含测试框架和一个阻塞工作器，支持“此区间没有观察到额外空闲 CPU”，不是长测/完整应用空闲保证。整成本进程 RSS 配对中位 **+176 KiB**（+112～+192 KiB），CPU 中位按 0.01s 分辨率约零（-0.01～约0s）。

## UI、SFTP 与完整回归

[文件额度](m4-task-runtime-file-quota.json)继续保留 **16 MiB SFTP 子池、9 MiB I/O 余量**，2 个运行/11 个等待后因额度拒绝，最后本轮请求/父/子额度归零。[Workspace](m4-task-runtime-workspace.json)本轮请求峰值 **1958381 B**，模态绘制区间零新增，SFTP 父/子和本轮请求最后归零；最终**根快照仍有 1146880 B**，未据此宣称缓存或完整回收。旧阶段两次全线程绘制分配来源仍未知，本次通过不能当作已修复。

[真实回环预览入口](m4-task-runtime-preview-entry.json)继续通过私有 helper/OpenSSH 认证、目录、上传/下载及服务回收，受管峰值 **8395077 B**、3 个实际请求；仅为本机回环和软件画布，不是原生窗口/输入法/外部主机验收。
