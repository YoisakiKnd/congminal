# M1 适配与性能评估

日期：2026-10-20。功能：会话拆分、主题、快捷键、字体缩放与有限后台任务。

## 方案与依赖决定

采用标准库适配：复用现有平台事件、软件渲染和字体后端；任务执行器使用 `std::thread`、`Mutex`、`Condvar` 和原子量。本轮 Cargo 直接/传递第三方依赖均为 0，没有新增外部运行程序。已有 shell、系统字体/窗口库依赖保持原有模型。

没有为已有渲染能力引入 UI 框架，也没有为一个串行字体任务引入异步运行时。本轮能力不需要新的协议后端，直接实现约 1 个线程、3 个任务槽的适配。该决定仅覆盖 M1，不等于已经比较或否定某个第三方包的性能。

| 后续模块 | 待对照的候选类别 | 开始评估时间/预算 |
|---|---|---|
| 搜索 | 有界纯文本扫描；正则需求明确后再比较匹配库 | M2，约 2 ms 分片、最多 1024 个会话结果 |
| 布局/侧栏 | 当前软件渲染组件、轻量 UI 组件库 | M4，受全局账本约束，隐藏面板停止绘制 |
| SSH | 系统 OpenSSH 与成熟 SSH 库 | M5，测连接/认证、每连接内存、取消和子进程合计开销 |
| SFTP | 成熟库与 OpenSSH 子系统的有界适配 | M6，流式传输、最多 2 个活动任务与 16 MiB 共享缓冲初始目标 |
| Git | Git CLI 与成熟 Git 库 | M7，大仓库/工作树、NUL 输出、取消、diff 截断 |
| 监控/通知 | 系统接口适配与跨平台库 | M3/M7，按需订阅、采样去重、隐藏/断线降频 |

具体包/程序的版本、特性、许可证和传递依赖在原型接入时锁定；当前未验证，未进入默认后端。接入门槛见 [依赖策略](../dependency-policy.md)。

## 成本与边界

- 默认输入路径增加一次无分配哈希查找和焦点判断；查询到发送文本动作时复制最多 8 KiB 的动作文本。
- 主题切换复制固定调色板并使屏幕失效，下次绘制整屏一次；不加载字体，不增加线程。
- 字体请求 40 ms 合并，至多一个运行任务、一个待办和一个结果；后台结果与当前字体短期共存。用户会看到延迟生效的字号，而输入线程继续工作。
- 字体线程按需创建，第一次使用后保留一个空闲工作线程；无忙等或定时空转。配置监视器维持原有每秒一次元数据检查，但取消可直接唤醒。
- 文件 I/O 取消合作执行，无法保证中断正在等待的系统调用；关闭主界面不 join 该调用，返回后清理并丢弃结果。
- 资源快照按需收集，不把映射大小伪装成 RSS，也不声明已完成全局预算准入。

## Release 对照

基线：M1 开始前的完整工作树快照（已含上一批底层加固）。平台：Darwin arm64，Rust 1.99.0；release 默认配置，Maple Mono NF CN 30px，3616×2416 像素/200×60 格。先分别构建，之后按“基线→M1”交替五轮，单线程执行同名基准。

原始数据：[m1-bench.json](m1-bench.json)。输入基准为真实 PTY 会话的 1000 个按键，混合字符、方向键及复制，每轮分别统计分位数，再比较五轮分位数中位数。基线使用对应旧字段的同负载无窗口构造器；不包含 OS 事件传递、PTY echo 和屏幕呈现时间。

| 指标（五轮中位数） | 基线 | M1 |
|---|---:|---:|
| VT 解析 | 127.7 MiB/s | 129.0 MiB/s |
| 整屏重绘 | 3.205 ms | 3.182 ms |
| 单行更新 | 0.331 ms | 0.322 ms |
| 按键处理到入队 P95 | 84 ns | 208 ns |
| 按键处理到入队 P99 | 1333 ns | 2542 ns |
| release 可执行文件（含 debug=1） | 1,359,240 B | 1,436,104 B |

吞吐/绘制差异接近噪声，没有稳定超过 5% 的中位数回退；单次整帧样本范围基线 3.057–3.307 ms、M1 3.071–3.331 ms，因此不据此声称普遍提速。按键 P95 增量约 0.000124 ms，低于 1 ms 接入门槛；这不能替代端到端呈现延迟测量。二进制增加 76,864 B（约 75 KiB）。无网络下载和新增第三方编译步骤；未单独控制编译器缓存来量化编译时间。

## 原生窗口开销

原始数据：[m1-runtime.json](m1-runtime.json)。使用 macOS `proc_pidinfo` 读取本次测试进程；五轮“基线→M1”交替，启动计时为创建进程至 shell 写入就绪标记，不含首帧呈现。每次预热 300 ms 后采集 3 秒空闲 CPU，shell 随后自然退出。测试 shell `exec sleep 4`，每次核对恰好一个子进程，并单独统计其开销。

| 五轮中位数 | 基线 | M1 |
|---|---:|---:|
| 启动到 shell 就绪 | 127.37 ms | 129.31 ms |
| congminal RSS | 109.94 MiB | 109.88 MiB |
| congminal 线程数 | 14 | 14 |
| 空闲 CPU（单核百分比） | 0.00276% | 0.00264% |
| shell 子进程 RSS | 1.016 MiB | 1.016 MiB |
| 子进程空闲 CPU | 采样期间无计数增量 | 采样期间无计数增量 |

启动中位数约增加 1.5%，未超过 5% 门槛；本场景无额外线程或可分辨的空闲 CPU 增量。RSS 含原生窗口、运行库与已驻留字体页，不能用它推算受管负载预算。系统首次初始化、缓存和调度会影响启动，数据只适用于本场景。

另一次原生窗口测试持续约 32 秒：20 次 15/17px 字体提交、21 次配置重载，同时切换三套主题，最终恢复 15px/dark 并自然退出。20 个快照 RSS 范围 110.11–110.30 MiB，首/末约 110.23/110.16 MiB；线程数 11–15（包括原生系统工作线程），未呈持续增长。该短测不替代 30 分钟压力验收，也不测持续外部命令的 CPU 开销。

独立单线程真实 PTY 回归中，12 轮字体加载/复位前后，活跃字体文件所有者均为 41,082,052 B；结束时任务运行/待办/结果槽均为空，输入/输出队列均为 0。该测量配合所有权释放测试，验证重复切换不会累积旧字体映射。

## 正确性与运行验证

```sh
cargo fmt --all -- --check
cargo test --offline
cargo clippy --offline --all-targets -- -D warnings
cargo clippy --offline --all-targets --target x86_64-unknown-linux-gnu -- -D warnings
cargo clippy --offline --all-targets --target x86_64-pc-windows-gnu -- -D warnings
cargo build --offline --release
cargo test --offline --release bench_ -- --ignored --nocapture --test-threads=1
```

正常测试 **150 项通过，3 项手动基准忽略**。三平台 Clippy 检查通过，release 构建通过。现有 `ci/smoke.sh` 在 macOS 上通过启动/运行/退出检查；本机截图命令未获得显示图像，截图/人工视觉验收未完成。测试覆盖旧终端/字体/图像回归及 M1 的配置、规范化按键冲突、取消版本校验、真实 PTY/IME 提交/焦点、300 次主题循环、快速字号到上限后复位、12 轮真实字号加载/复位，以及 2 MiB 输出退出排空和满队列关闭。

未验证：Windows/Linux 真机 UI，完整输入法候选交互、动态 DPI、冷文件缓存启动、端到端输入到屏幕 P95/P99、30 分钟压力、多会话（尚未实现）。这些不以单元测试或本机结果代替。后续功能增加线程/并发、改变预算或引入第三方依赖后重新测量。
