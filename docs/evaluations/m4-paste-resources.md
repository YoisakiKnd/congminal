# M4 普通粘贴读取、在途拥有者与发送转换

2026-10-25。普通剪贴板读取和发送前转换接入既有 `clipboard-reserved`。无新增包、线程或运行时子进程。本页验收 Rust 缓冲、平台适配中的准入调用和本机模拟/PTY 流程；外部剪贴板协议、平台原生送达、系统内部内存及完整输入到显示时延仍待。

## 平台读取与在途结果

Congminal 从当前会话取出普通读取请求时绑定源 Terminal 的预算，初始票据为零字节，不提前占用最大 8 MiB。macOS/X11 在 UTF-8 验证后、Windows 在计算 UTF-16 解码长度后，先取得输出容量额度再申请 String。普通 Windows 解码仍用替代字符处理孤立代理，受保护读取保持严格拒绝；两个模式都在写入时检查已核定长度，不让第二遍数据变化自动触发扩容。

结果使用 `ManagedPaste`，拥有文本和票据，最后释放文本后归还额度。一个普通读取请求至多解码一次，不能拿同一张票据同时返回两份缓冲。`finish` 检查实际 capacity 同时受读取上限和已付额度覆盖，拒绝不携带未付文本。未绑定请求的生产 finish 路径拒绝创建普通文本事件；旧 `Event::Paste(String)` 只保留给未归属输入的隔离/兼容测试，不由生产剪贴板适配构造。

工作区继续把结果送回发起读取的窗格。切换焦点不改目标；源窗格关闭后，已解码结果仍持有额度，回复到达后丢弃，不能落到新活动终端。认证打开/关闭的屏障消费迟到普通回复；认证控制器及 macOS 输入桥显式擦除这些未归属输入，受保护回复继续保留原身份和秘密清理。正常终端文本按普通 String 释放，不逐字节擦除全部历史粘贴内容。

X11 在调用 `XGetWindowProperty` 前额外预留请求字节：`ceil(limit/4)×4+1`，覆盖协议取整与终止零请求；准入失败先删除待收取属性再报告失败。属性复制期间这张票据与 Rust 解码票据并存，`XFree` 后才退出该作用域。不支持的类型、超限或剩余数据继续拒绝。该预留不是分配器头部、X server 内存或整个 Xlib 的计费模型；macOS NSPasteboard/NSString 的内部副本和 Windows 由系统拥有的源块也未在这里当作 Rust 请求收费。

读取失败显示“剪贴板无文本、超限、额度不足或读取失败”，不能把普通窗口的额度拒绝静默忽略。提示自身的完整界面/元数据分配不由核心缓冲的零分配拒绝证明代替。

## 一次转换与整笔入队

发送前保留原有 **8388596 B（8 MiB − 12 B）** 输入上限。`paste_bytes` 先为单个 Vec 申请最多 `input.len()+12`，再将 CRLF→CR、LF→CR，bracketed 模式去掉伪造的 `ESC[201~` 并加上开始/结束标记。普通模式保留结束标记字节，嵌入 NUL/Unicode 字节语义保留。

连续普通文本按固定 8 字节安全扫描跳过，找到 CR/LF/ESC 后再处理；使用有界切片读取和字节存在检测，没有越界指针/SIMD平台依赖。所有扩展都在原预留容量内，不在逐字节路径访问共享预算。上限/准入失败时不向 PTY 发布任何字节。转换成功后仍调用已有的整笔 ByteQueue 写入：队列额度继续覆盖其拥有的独立副本，输入满或关闭时整笔拒绝，不发送半个 bracket frame。

原来多次 replace、format 的临时 String 已取消。搜索模式仍走自身受控写入，通知/认证焦点继续阻止文字进入终端。同步读取和转换仍可能占用当前线程，本页不以微基准证明原生事件硬时限。

## 实际分配和释放

[当前工具链](m4-paste-resources-allocation.json)和 [Rust 1.88](m4-paste-resources-allocation-msrv.json)使用同 epoch 全线程 Rust 请求计量，保守计入 realloc 旧、新重叠。输入/UTF-16 数组、池、Scope 与锁在测量前建立，计量器附加头、分配器/C/OS 和实际栈不计入 Rust 数字。X11 外部票据只模拟有界请求预留，没有调用 Xlib。

| 阶段 | 实际存活请求 | 本池额度 |
|---|---:|---:|
| 最大 X11 请求预留 | 0 B | 8388597 B |
| UTF-8 解码，外部票据同时持有 | 8388596 B | 16777193 B |
| 外部释放，结果在途 | 8388596 B | 8388596 B |
| 原结果与完整转换结果并存 | 16777204 B | 16777204 B |
| 原回复释放，仅保留转换结果 | 8388608 B | 8388608 B |
| 转换结果释放 | 0 B | 0 B |
| 独立 UTF-16 最大 ASCII 解码/在途 | 8388596 B | 8388596 B |
| UTF-16 结果释放 | 0 B | 0 B |

UTF-8 与转换共有 **2 次分配、0 次扩容**，实际峰值 **16777204 B**，由当时额度完整覆盖；UTF-16 独立区间 1 次分配、0 次扩容。满池时 UTF-8 读取、外部请求预留、转换以及非法严格 UTF-16 拒绝均零新增请求，最后归零。64 MiB 预算峰值包含人为占满的压力票据，不能当作真实堆峰值。队列副本由既有 Queue 预留承担，不包含在此核心区间中；也不把释放后的账本值等同 RSS 立即下降。

## 行为验证与成本排查

新增常规回归覆盖准入前拒绝、源池/不同当前 Scope、单次解码、结果移交/销毁、UTF-16 替代/严格模式、未付 capacity 拒绝、X11 请求额度、关闭源窗格后的清理，以及转换后整笔队列拒绝。转换逐项对照原 replace/format：10 种片段三重组合×两模式共 **2000** 组，另有长度 0～511 的随机 ASCII×两模式 **1024** 组，覆盖 8 字节扫描边界、CR/LF/结束标记、Unicode 与 NUL。已有认证屏障测试现经过真实计费解码接口生成普通迟到回复。

第一版逐字节 push 造成 ASCII 约三倍总耗时，原始记录保留为 `*-before-batched-scan.json`。批量扫描消除了该回退。UTF-16 首版重复计算输出长度，后复用已准入长度，保留写入边界检查。中间结果见 `*-before-utf16-count-reuse.json`。

释放计时发现复用秘密容器令普通最大文本逐字节擦除，约额外 **2.1 ms**；已改为正常普通文本释放，只在认证隔离路径显式擦除。原始结果见 `*-before-ordinary-release.json`，不把仅构造函数变快当作整个生命周期变快。认证屏障擦除大未归属输入的线性成本和原生输入时限仍须后续验收。

## 同负载测量

[最终对照](m4-paste-resources-cost.json)在前一阶段冻结源码和当前临时副本注入同一夹具主体及显式薄适配器。前版执行原有 replace/replace/replace/format 和 ClipboardRead 解码，当前执行实际带额度的 request/finish 与转换 API；适配器源码与哈希都保留。生产 System 分配器，各两次预热后五组交替，UTF-8 输出累积指纹相同。

每轮 1000 次短混合输入、各 8 次约 1 MiB ASCII 普通/bracketed、Unicode 混合及控制符密集转换；另各 5000 次 600 B UTF-8/UTF-16 读取、5000 次单独小结果释放和 8 次最大结果释放。构造/转换计时排除哈希及最后释放，释放单独计时；进程 CPU/RSS 包含全部构造、哈希和释放。

转换明显降低本夹具成本，带额度读取/归还增加常数开销；不能把短纳秒结果、百分比中位或共同 UTF-16 逻辑推广成平台原生响应。每轮最大普通释放只有 8 个样本，百分比波动很大；批次折算中位恢复到亚微秒量级，不代表每次系统释放均有相同时限，也不将它描述为稳定提速。
