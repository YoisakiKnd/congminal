# M4 UI 分片重排评估

日期：2026-10-21。当前工作区未提交、未发布。基线是本轮开始时的本地快照 `/tmp/congminal-tick-baseline-01a158a4`，包含上一轮流式消费内核和网格准入，并非远端 alpha.5。没有新增 Cargo 包、生产常驻线程或采样任务。实现和边界见 [执行说明](../execution-m4-reflow.md)，最终指纹见 [构建记录](m4-tick-build.json)。

## 实现与验证

超过 256 KiB 的主屏宽度重排使用只读源步进，不在事件中扫描全部历史，也不取走旧源；搜索、选区及绘制仍可读取旧文本。新历史、主/备用网格分片准备后交换；新旧网格分别持有预留，旧状态分片销毁后才归还旧票据与临时额度。文本与历史额度版本改变时取消旧结果，取消输出分片回收后重新准入一个最新目标。

Session 的推进是约 500 µs 合作式预算，每段 4096 cells；工作区一次只推进一个窗格的准备/退休作业，槽主完成或取消清理后轮换，焦点变化不会打断其进度。输出解析在准备阶段暂停，沿用 1 MiB 队列背压；键盘仍可写入有界输入队列，回显可能等到提交。排队尺寸不保留重复预留，也不代表已通过最终准入。

Debug/release 各 **253 项通过，13 项手动基准忽略**；macOS 本机、Linux x86_64 GNU、Windows x86_64 GNU 的 all-targets Clippy `-D warnings` 通过。2100 组重排参考差分增加只读步进对照；585 组宽度变化的完整终端对照覆盖高度、光标、历史和备用网格。另有逐阶段取消、配额变化、宽字符修复、退休票据、尺寸边界、连续目标合并、真实 PTY 输入/尺寸、满输出队列关闭、单输出所有者、焦点轮换及关闭槽主等测试。补充了旧网格绘制/IME 框的画布裁剪，并修正单窗格缩放被拒绝时误触发退出的问题。作业票据声明在所有行/索引之后，确保正常完成与关闭析构均先释放缓冲再归还额度。

## 四窗格 UI/PTY 对照

三个交替先后顺序的对照，每次八轮实际列数变化。四个真实 PTY，初始历史一半软行、一半硬行；每次发起布局后立即通过 Event::Text 发送回显标记，持续调用 tick 和到期 draw，直到目标提交、旧状态退休且终端文本中收到回显，期间反复创建/关闭第五个会话。基线只注入同一测试工作负载，其 pending 查询恒为 false；生产逻辑不变。原始注入代码、逐轮值、直方图、日志和约 50 Hz libproc RSS 样本见 [完整数据](m4-tick-ui.json)。

下表为三个运行汇总的中位数。request 是发起布局调用，complete 从发起前计时，包含重排、退休和回显到达；不是操作系统事件到屏幕呈现的测量。基线的主要阻塞发生在 request 中，不能用其很短的 tick 来声称比当前更响应。

| 指标 | 同步基线 | UI 分片 |
|---|---:|---:|
| request 每轮中位数 ms | 6.655 | 0.144 |
| 每次运行 request 最大值的中位数 ms | 10.167 | 1.102 |
| tick P95 的桶上界 ms | 0.050 | 0.550 |
| 每次运行 tick 最大值的中位数 ms | 0.007 | 2.023 |
| 输入处理最大值的中位数 µs | 6.500 | 5.625 |
| complete 每轮中位数 ms | 7.151 | 10.832 |
| 每次运行 complete 最大值的中位数 ms | 11.282 | 14.748 |
| RSS 采样峰值 MiB | 120.64 | 207.31 |
| 混合账本峰值 MiB | 248.23 | 248.23 |

布局调用大部分耗时移到多个 tick，当前每次运行有 177–186 次带待处理作业的 UI turn；测得最慢单次 tick 为 2.178 ms，最慢 request 为 1.175 ms，最慢 paint 为 1.234 ms。50 µs 桶只提供分位上界，单次最大值单独计时。队列实际峰值为 17 字节，另一个满队列/关闭测试验证 1 MiB 背压边界；轻量回显负载不能代表持续满速刷屏。

**存在明确的内存与总完成成本回退**：本组 complete 中位数约增加 51.5%，RSS 采样峰值约增加 71.8%。旧文本必须保持可读，UI 路径构造独立输出，不能复用仍归旧源所有的 cell；复制、分批调度、分配器保留和碎片都可能影响成本，RSS 分解尚未完成。不能把较短的 request 解释为全部性能已通过。

最初允许四个窗格同时准备输出时，RSS 采样峰值中位数约 212.16 MiB，tick P95 桶上界为 2.05 ms，见 [并发版本原始记录](m4-tick-ui-parallel.json)。单输出所有者版本最终组 RSS 中位数约 207.31 MiB，tick P95 为 0.55 ms。此前单槽组曾为 191.47 MiB，见 [中间组记录](m4-tick-ui-pre-drop-order.json)；进程/分配器状态波动明显，不能据某组声称 RSS 稳定改善。所有权测试确认同时至多一个作业持有输出，但 RSS 高水位仍待跟踪。未删除并发或中间组的记录。

同一 release（debug=1）生产二进制为 1,871,704 → 1,912,520 字节，增加 40,816 字节，约 2.18%。这不证明启动成本通过，原生 GUI 启动仍待重测。

## 常规性能回归

相同 release 配置的五个交替对照，双方均跳过新增 UI 工作负载和单内核片段基准；测量之间不并行运行其他测试。完整轮次和源码校验见 [全套记录](m4-tick-bench.json)。数值只在本组环境内比较，不与上一轮不同时间的绝对耗时拼接。

| 场景/轮次中位数 | 基线 | 当前 |
|---|---:|---:|
| VT MiB/s | 129.7 | 130.5 |
| 3616×2416 整帧 ms | 3.033 | 3.085 |
| 单行更新 ms | 0.318 | 0.320 |
| 事件入口 P95 / P99 ns | 250 / 2542 | 250 / 2291 |
| 工作区入口 P95 / P99 ns | 292 / 1917 | 291 / 2000 |
| 四窗格整帧 / 单行 µs | 603 / 25 | 607 / 25 |
| 搜索 / 复制片段 P95 µs | 153 / 106 | 151 / 105 |
| 同步硬行重排 P50 / P95 µs | 293 / 419 | 285 / 407 |

整帧约 +1.7%，VT 约 +0.6%，入口 P95 增量小于 1 ms。同步硬行 P50/P95 分别约 -2.7%/-2.9%，20 次总耗时中位数均为 6 ms，样本较小且形态有限。此前组的复制 P95 为 104 → 110 µs、硬行 P50 为 286 → 303 µs，见 [保留的中间组](m4-tick-bench-pre-drop-order.json)；不能把轮次波动直接解释为普遍改善或回退。这些同步内核数值不代表 UI 路径的总完成成本。

## 分配与准入

测试副本注入线程局部 GlobalAlloc/System 请求字节计数，realloc 保守计算旧新缓冲重叠；按原始输入和目标形态比较九个场景，生产源码不变。额度可能还覆盖原先未接共享账本的旧历史，不能与“额外峰值”差额当作利用率，也不是 RSS。

| 场景 | UI 路径额外峰值 MiB | 已准入额外额度 MiB |
|---|---:|---:|
| 64 MiB 硬行缩窄 | 67.78 | 202.38 |
| 64 MiB 硬行扩宽 | 67.80 | 202.27 |
| 64 MiB 长软行 | 71.06 | 209.05 |
| 窄历史扩到 4096 列 | 64.57 | 132.77 |
| 2048 行先扩到 4096 列、最终缩到 1 行（低于阈值，同步） | 160.07 | 321.14 |
| 4096 列宽字符缩到 1 列 | 0.78 | 29.08 |

九个场景均在准入模型内，网格最终实际容量不超过预留，临时票据及终端销毁后的所有额度归零。完整数据与注入代码见 [分配探针](m4-tick-allocation-probe.json)。只读准备阶段不能享有同步硬行捷径的低额度，可能拒绝小账本中同步路径原本可完成的缩放；当前实现选择保留旧状态和拒绝原子性，并未降低历史上限来掩盖峰值。

对照上一轮同步消费探针，64 MiB 长软行额外峰值为 8.88 MiB，当前只读 UI 路径为 71.06 MiB；同步硬行为约 1.26/1.27 MiB。两种所有权策略不同，这些增加必须保留在评估中。工作区串行推进把同时存活的新增历史限制在一个作业内；这不等于 RSS 必然同比下降，也没有消除单会话新旧历史共存。

## 可复现检查

```sh
cargo test --offline --release bench_ui_resize -- --ignored --nocapture --test-threads=1
CONGMINAL_UI_ROUNDS=1000 cargo test --offline --release bench_ui_resize -- --ignored --nocapture --test-threads=1
python3 tools/check_grid_pressure.py --ui-rounds 1000 --output /tmp/congminal-ui-reflow.json
```

macOS 工具的 UI 模式运行原始用例、不修改 Rust 测试，以约 50 Hz 采样。旧 `--seconds` 模式仍通过测试副本改变列数跨度，但现在会推进 UI tick 直到完成再验证列数；其布局计时包含测试等待，不能用作 UI 单次阻塞指标。30 分钟稳定性与三平台原生窗口交互仍未验收。

## 1000 轮与工具检查

最终源码的原始 UI 用例完成 1000 轮、22,155 次待处理 UI turn，动作阶段约 12.42 秒，回显全部到达，输出实际峰值 17 字节。tick 最大 2.776 ms，输入处理最大 14.166 µs，布局请求最大 3.620 ms，单轮提交/退休/回显总完成时间最大 25.854 ms。RSS 采样峰值 187.31 MiB，后半段约 185.02–187.31 MiB，仍有增长；结束后全部额度与映射数量归零。见 [1000 轮原始记录](m4-tick-ui-pressure.json)。这是短时反复回收验证，不能替代 30 分钟稳定性或真实窗口延迟。

旧压力适配器另经 [六秒完整运行](m4-tick-pressure-tool-smoke.json) 检查；仅用于工具/资源回收验证，包含测试轮询等待的布局耗时不当作 UI 阻塞时间。修正析构顺序及画布/拒绝处理之前的测量保留在带 pre-drop-order 或 parallel 后缀的文件中，最终结果对应构建记录中的同一套源码指纹。

## 后续边界

小网格、仅改高度、备用屏幕、画布重新分配及关闭 Session 的析构仍有同步工作；单行扫描/分配器和固定上限元数据也不可抢占。当前测试驱动的是 App/Workspace 和真实 PTY，未测真实窗口的事件分发、输入法及显示呈现，不代表所有 UI 停顿消除。

持久历史及全部索引/元数据仍未完整接入共享账本，512 MiB 是已接项目的混合准入额度，不能当作全部堆或 RSS 上限。下一步先接持久历史所有权计费与非活动历史回收，继续减少只读输出的峰值和完成成本，再补其余同步路径、启动与三平台真机/长测。
