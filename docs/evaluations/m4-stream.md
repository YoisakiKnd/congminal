# M4 流式重排评估

日期：2026-10-21。当前工作区未提交、未发布。基线是本轮开始前的本地快照 `/tmp/congminal-stream-baseline-01a158a4`，已包含前一轮网格/缩放准入，并非远端 alpha.5。没有新增 Cargo 依赖、常驻线程或周期任务。最终源码与二进制指纹见 [构建记录](m4-stream-build.json)。

## 实现与正确性

软行重排逐段消费旧行，不再拼接完整逻辑行；长行最多缓存两个可复用旧行缓冲。连续窄 cell 批量复制，宽字符与占位格单独映射。输出保持有界 VecDeque，历史直接接管索引，硬行整体转移捷径保留。具体所有权、容量模型和步进边界见 [执行说明](../execution-m4-reflow.md)。

准入仍在取走历史之前，拒绝时保留旧文本、选区及 PTY 尺寸。流式临时额度从四份输入余量收紧为一份输入、受限输出及固定缓冲/索引余量。新增 32 MiB 账本测试可在持有 8 MiB 软行历史及 2 MiB 其他额度时完成缩放，结束后临时票据归零。

重排 2100 组案例同时对照参考算法、普通/预检调用及 1/17/4096 cell 步进；覆盖宽字符、软行、光标、屏幕顶端及被裁剪的空白尾行。另有 1000 组历史接管/逐行 push 的配额与淘汰对照，以及缓冲复用、两个备用缓冲上限和跳过光标后长行等验证。Debug/release 各 **238 项通过，12 项手动基准忽略**；本机、Linux x86_64 GNU、Windows x86_64 GNU 的 all-targets Clippy `-D warnings` 通过。交叉检查不代表三平台原生运行。

复用容量按实际容量计费，同一历史字节额度下可保留的行数可能变化；没有扩大历史配额，也不承诺与旧分配策略保留完全相同的历史行数。

## 分配峰值

独立源码副本注入测试用 GlobalAlloc/System 包装，线程局部记录 Rust 请求的存活字节；realloc 保守计算旧新缓冲重叠。数据是相对缩放前的额外峰值，并非 RSS；额度可能临时覆盖原先未接共享账本的历史输入，不能当作分配利用率。

| 场景 | 额外峰值 MiB | 已准入额外额度 MiB |
|---|---:|---:|
| 64 MiB 硬行缩窄 | 1.26 | 71.76 |
| 64 MiB 硬行扩宽 | 1.27 | 72.55 |
| 64 MiB 长软行 | 8.88 | 209.05 |
| 窄历史扩到 4096 列 | 63.39 | 68.37 |
| 2048 行先扩到 4096 列、最终缩到 1 行 | 160.07 | 321.14 |
| 仅变矮并增长历史索引 | 2.00 | 6.02 |

长软行额外峰值从上一轮 103.30 MiB 降到 8.88 MiB，约减少 91.4%；已准入额外额度从 401.15 降到 209.05 MiB，约减少 47.9%。九个场景均在额度内，最终网格实际容量不超过预留，临时票据归零，终端销毁后全部额度归还。原始数据、注入代码和源码指纹见 [分配探针](m4-stream-allocation-probe.json)，旧值见 [上一轮探针](m4-grid-allocation-probe.json)。这不包含系统分配器块大小、系统库或未来新增分配路径。

## 常规性能

相同 release 配置交替先后顺序，测量之间不并行运行其他测试；保留全部慢样本，按轮次中位数汇总。全套两侧都跳过新增步进基准，确保工作负载一致。事件入口只测处理/入队，不代表端到端输入延迟。

| 场景 | 基线 | 当前 |
|---|---:|---:|
| VT，五对 MiB/s | 63.7 | 63.5 |
| 3616×2416 整帧，全套 ms | 6.476 | 7.014 |
| 单行更新，全套 ms | 0.661 | 0.675 |
| 事件入口 P95 / P99 ns | 208 / 2417 | 209 / 2417 |
| 工作区入口 P95 / P99 ns | 250 / 2541 | 250 / 4042 |
| 四窗格整帧 / 单行 µs | 1273 / 51 | 1194 / 50 |
| 64 MiB 硬行重排 P50 / P95 µs | 949 / 1122 | 751 / 1037 |

VT 约 -0.3%，单行约 +2.1%，全套整帧约 +8.3%；首个当前版本样本为 9.195 ms，随后样本也有波动。追加独立绘制结果在下方记录，不能删除首组后只报告较快一组。全套硬行基准每轮仅 20 次，P95 结果只能代表该样本规模及形态。搜索片段 P95 为 303 → 318 µs、复制为 212 → 218 µs，状态容量相同；全套样本见 [原始记录](m4-stream-bench.json)。

追加独立 16 对绘制中位数：整帧 8.552 → 8.117 ms（约 -5.1%），单行 0.776 → 0.789 ms（约 +1.7%）。整帧样本范围分别为 7.239–15.235 与 7.198–13.450 ms，环境波动明显；本组未复现全套的稳定回退，不能据此保证所有环境下无回退。全部样本见 [独立绘制记录](m4-stream-render-isolated.json)。同一 release（debug=1）二进制为 1,870,968 → 1,871,608 字节，增加 640 字节，约 0.034%。

## 内核步进成本

新增手动基准使用 20,000 行、每行 120 cells 的同一软逻辑长行，含宽字符对；缩到 79 列，光标在末尾，每次 step 预算 8192 cells。五次 release 运行均推进 1160 段，按轮中位数计：片段 P50 为 10.667 µs，P95 为 13.625 µs，最大片段中位数 53.791 µs，推进总耗时 10.577 ms，结束后的 finish 约 6 µs。五次中最大片段为 89.458 µs。

[完整片段数据](m4-stream-slices.json) 记录全部样本与源码指纹，可用 `cargo test --offline --release bench_stream_soft_slices -- --ignored --nocapture --test-threads=1` 复现。计时从 Stream 构造后开始，结束后 finish 不包含结果最终销毁，也不包含终端预检、网格提交、历史接管或事件循环调度，不能当作完整 resize 成本或 UI 响应保证。

## 真实 PTY 压力

三个交替顺序的 20 秒对照，每次创建四个真实 PTY、反复创建/关闭第五个，初始填充历史。源码副本把缩放跨度扩大到四个字符宽度并断言列数变化，增加 50 µs 分桶的布局耗时直方图；生产源码不变。libproc 约 1 Hz 采样主进程 RSS，未合计 Shell 子进程 RSS。

| 三轮中位数 | 基线 | 当前 |
|---|---:|---:|
| RSS 峰值 MiB | 217.97 | 148.08 |
| 混合账本峰值 MiB | 440.43 | 248.23 |
| 整组布局 P50 上界 ms | 23.95 | 18.05 |
| 整组布局 P95 上界 ms | 37.05 | 28.40 |

RSS 峰值约减少 32.1%，账本峰值约减少 43.6%；布局 P50/P95 约减少 24.6%/23.3%。分位值是 50 µs 桶的上界，非精确单次耗时。各组实际重排次数不同，不能当作固定重排次数吞吐测试。所有组准入拒绝数为 0，结束后全部额度和映射数量归零。

**长尾停顿仍未验收**：当前版本三个 20 秒样本最大单次布局分别为 225.215、92.287、70.928 ms；旧版为 95.379、50.823、130.093 ms。中位分位数改善不能证明最大停顿改善，也不能将这些离群值未经证据归咎于系统调度。

追加当前版本 60 秒运行完成 4264 次实际重排：RSS 峰值 144.17 MiB，账本峰值 248.23 MiB，布局 P50/P95 上界为 2.45/21.25 ms，最大 211.842 ms。后 40 秒 RSS 约 143.14–144.17 MiB，仍有小幅增长；操作后重排票据均归零，网格实际容量约 167 KiB。活动阶段为 14 线程。该组文本/换行分布随运行改变，不能与 20 秒基线直接比较分位数；60 秒也不能替代 30 分钟稳定性或无泄漏证明。

[完整压力记录](m4-stream-pressure.json) 含全部日志、直方图、RSS、账本快照和测试副本指纹。单次复现工具为 [check_grid_pressure.py](../../tools/check_grid_pressure.py)：`python3 tools/check_grid_pressure.py --seconds 60 --output /tmp/congminal-stream-pressure.json`。工具仅修改临时副本中的测试，原始基线须使用记录的快照；可用 `--seconds 1800` 执行长测，本轮未执行。

## 尚未验收

UI 仍同步调用 finish；step 的工作量预算不提供硬实时保证，单行扫描、分配或销毁可超过预算。后续必须把预检、推进、提交及取消清理一起纳入 UI 调度，处理连续缩放合并、状态版本和有界 PTY 背压。当前存在步进接口不等于缩放期间能响应输入。

持久历史/全部索引、字体解析临时缓冲和其他元数据尚未完整接入共享账本；512 MiB 仍是已接项目的混合准入额度，不能称为全部堆或 RSS 上限。启动成本沿用上一轮未验收状态，本轮没有重新测 GUI 启动，不能据依赖数不变推断启动性能通过。Windows/Linux 真机、三平台输入法/窗口交互及 30 分钟长测仍待完成。
