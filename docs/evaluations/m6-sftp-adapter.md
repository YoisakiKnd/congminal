# OpenSSH 有界管道适配开销

本轮结论：macOS 上可继续接入该适配，没有观察到正常工作负载超过 5% 的吞吐退化，也没有增加传输工作线程；仍不满足完整发布门槛。GUI 延迟、认证 helper、弱网、多任务、三平台与 30 分钟长测继续待验。SFTP 模块仍仅编译进测试。

## 范围与方法

候选是系统 OpenSSH 加自有非阻塞管道；对照是同一个 OpenSSH、参数、配置、生成密钥、服务端、SFTP v3 客户端和目录/传输函数，只把底层替换为直接阻塞 std 管道。阻塞对照只适用于正常网络测量，没有产品取消保证，不作为备用产品后端。比较的是新增有界适配成本，不重新比较另一套库/协议实现。

本机 Apple M4、16 GiB，macOS 27.0.1 arm64；release/default-dependency，Rust 1.99.0，客户端/服务端均 OpenSSH 10.3p1、LibreSSL 3.3.6。禁用压缩和连接复用；读取 501 个可见目录项，32 MiB 模式数据上传及逐字节核对下载，64 KiB 块、顺序 ACK、临时上传/大小检查/fsync/关闭/重命名均相同。每次各留 600 ms 传输前后空闲窗。先预热两个实例，再五组交替顺序，共十个测量实例；没有刷新系统缓存或声称机器冷启动。

[原始数据与版本](m6-sftp-adapter-bench.json)，工具为 tools/check_sftp_adapter.py。5 ms libproc 采样记录测试进程及派生 SSH，最多 64 项，可能遗漏瞬时峰值；服务端和采样器不计入客户端树。时间来自同一 Rust workload 的 Instant。没有把测试进程当成完整 GUI 或全部堆准入证明。

## 同负载结果

以下均为五次中位数，括号为范围。

| 项目 | 阻塞对照 | 有界适配 |
|---|---:|---:|
| 连接到 VERSION | 48.347 ms（46.576–51.894） | 48.164 ms（44.974–55.459） |
| 目录读取 | 133.680 ms（131.154–134.707） | 132.916 ms（121.268–135.559） |
| 上传 | 238.93 MiB/s（236.81–242.11） | 245.55 MiB/s（242.20–249.12） |
| 下载 | 244.72 MiB/s（241.69–245.14） | 242.82 MiB/s（241.32–245.36） |
| 清理 | 2.564 ms（2.348–3.754） | 1.126 ms（0.906–1.447） |
| 受管峰值 | 3169340 B | 3431484 B |

适配明确增加 262144 B 工作预留；这不是实测新增堆字节。上传观察值高约 2.8%、下载低约 0.8%，不据这五组差值宣称加速或零开销。清理的语义也不同：基线关闭 stdin 后等正常退出，适配明确结束受控进程组；均只在所有传输 ACK 后执行，不把两种清理解释成等价的退出码验证。

客户端树每次观测峰值的中位：对照 13467648 B、适配 13303808 B；最大分别 13500416/13516800 B。此差异不支持“适配减少内存”的结论。传输后空闲 RSS 中位分别为本进程 8781824/8814592 B、SSH 子进程 4685824/4472832 B，需看合计与样本波动。

传输前空闲 CPU 的中位均为 0，传输后分别 0 和约 0.0033 个单核百分点。两个方案均为测试程序 2 线程、SSH 1 线程、合计 2 进程，没有为适配新增线程或轮询任务。这里的 600 ms 窗不能代替长测；没有断言全部模式空闲开销为零。所有实例结束受管额度归零，采样未见客户端派生进程残留。

## 创建锁与剩余门槛

独立于吞吐/RSS 试验，另做 100 次真实 ssh -V 启动：后台实际取得 process_launch 锁后发出一次通知，观察线程争用新窗格 fork 会使用的同一锁。等待时间中位 232 µs、P95 342 µs、P99 533 µs、最大 690 µs；最近秩百分位。通知到观察线程取得锁的上界中位 239 µs、P95 351 µs、P99 544 µs、最大 701 µs，包含观察线程调度，不能当精确持锁时间。

这是热缓存、无网络的同步锁采样，没有运行 GUI 输入/绘制，也不涵盖 PTY fork 后的工作；不能把它记成 GUI P95。测试观察钩子仅在 Unix test 构建存在，普通应用没有该 TLS/通知路径。冷环境、并行负载及此前 SSH 时序问题仍需保留调查。

新增包数为零；使用中的外部依赖仍为系统 OpenSSH。Windows 的异步写槽、系统 bcrypt 调用与读等待轮询没有在此处测量，不能外推。后续 [认证方案](../design-sftp-auth.md) 会新增受限 helper，必须重新计入其启动、等待、RSS 和进程成本，再接默认界面。共享 16 MiB、2 活动/64 等待和完整生命周期验收不因本轮正常单任务对照而视为完成。

首版吞吐数据保留在 [早期记录](m6-sftp-adapter-bench-throughput-initial.json)。本轮完整回归见 [构建记录](m6-sftp-adapter-build.json)；测量后仅将夹具配置路径绑定到局部变量以兼容 Rust 1.88，不改变工作负载/协议/实际适配。原始测量散列保留；[初次 MSRV 错误](m6-sftp-adapter-build-msrv-initial.json) 单独记录，没有提高最低 Rust 版本。
