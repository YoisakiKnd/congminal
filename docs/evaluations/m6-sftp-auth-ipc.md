# 后台认证端点与资源验证

`ssh/auth_ipc.rs` 已在测试后端接通 Unix 私有端点和认证状态。`Pump` 由原后台工作器主动调用 `tick`，自身不创建线程、计时器或常驻进程；尚未加入 `capture::Stream` 的等待回调或可见界面。因此本轮不等于应用已经支持 SFTP 交互认证，也不勾选完整 M6。

每个端点固定两个连接槽，单次 tick 最多接受四个连接，每槽最多四次 1024 字节 IO。多余连接直接关闭，整个阶段最多接受 32 次连接尝试；已验证挑战仍受原状态的 16 次、120 秒上限限制。解析先检查能力/长度，再给包体额度，观察写端 EOF 后才发布提示，避免忽略完整帧后的额外数据。接收和发送各有绝对 5 秒期限，输入等待使用原认证阶段期限，不按每个分片续时。调用者必须持续推进 tick；这不是独立调度器或同步文件系统的硬中断保证。

一个普通输入可以与一个通知共存。通知保留有界可见提示并回复空成功；普通答案从 Front 一次移动到发送槽，没有克隆或新增答案队列。错误帧、重复普通输入、超限、取消、认证过期和 IO 失败都会关闭该认证状态并释放全部槽；未实现将坏请求无限忽略后继续服务。接收暂存逐段及 Drop 清零，发送直接借用 Secret；显式 `finish` 清理自身票据/socket 并报告错误。SSH/helper 进程仍须由流监督者另外回收，不能把端点清理当作完整进程清理。

创建时校验 Backend 和 Pump 使用同一 Budget，固定结构及暂存预留为 `size_of::<Pump>() + 4096`；端点路径、请求包体、显示文本及 Secret 独立计费。没有提高应用总预算，也没有新增依赖。固定槽和有限 IO 次数限制每次工作的数量，不证明 fork 创建锁争用或 GUI 响应时间已经达标。

## 验证

三项测试覆盖最大 UTF-8 答案、半关闭前不发布提示、控制字符转义、通知与输入并存、错误能力、额外数据、部分帧超时、任务取消、答案已排队时取消、阶段过期、第三个连接拒绝、32 次尝试上限、预算身份和最终零额度。全部在私有临时目录内运行，无真实 SSH 凭据。

稳定源码完整回归：默认 debug/release 各 381 通过、25 忽略，原生各 390 通过、27 忽略；默认三目标和本机原生 all-target Clippy、Rust 1.88 原生 release 测试编译均通过。[构建记录](m6-sftp-auth-ipc-build.json)。这些交叉检查不证明 Linux/Windows 真机行为。

临时源码副本注入的分配探针覆盖 16 KiB 部分请求、两份同时存在的 64 KiB 转义显示、1023 字节排队/发送/解码答案与清理。256 KiB 是本次隔离测试池，未变更应用 SFTP 总额度。当前工具链测得 Rust 请求峰值 165887 B，账本峰值 172119 B，各采样点存活均有覆盖，最终实际请求存活和账本均零；10000 次等待 tick 没有分配或 realloc。计时约 4 ms 仅是热缓存微诊断，不是空闲 CPU、GUI 延迟或真实网络吞吐结论。[完整测量](m6-sftp-auth-ipc-allocation.json)。

初始测量夹具先同步写完整 16 KiB，再推进同线程接收，遇到本机 socket 背压而挂起；已终止自己的测试进程、清理其临时目录并保留 [初始记录](m6-sftp-auth-ipc-allocation-initial.json)。夹具现以非阻塞部分写与接收交替推进，工具也增加独立进程组和超时整组清理。该调整属于夹具，没有放宽产品缓冲或协议上限。

同一探针在已安装的 Rust 1.88 上运行，峰值、各点存活、零分配等待及最终归零均一致；等待微诊断约 4.8 ms，同样不解释为系统空闲开销。[最低版本测量](m6-sftp-auth-ipc-allocation-msrv.json)。

这些数据仅覆盖当前线程 Rust GlobalAlloc 的请求字节及保守 realloc 重叠，排除分配器自身、C/OS 内部、线程栈、RSS 与预初始化的共享预算/创建锁上下文。全局预算上下文及其懒初始化继续属于 M4 待办。

下一步把端点推进接入独立流的等待循环，区分用户认证等待与网络 IO 超时，在 SFTP VERSION 后关闭认证阶段；随后补真实 Rust 父端/helper/OpenSSH 组合互操作、取消/退出确认及可见 UI。Windows DACL/私有管道、采用前五轮公平成本、真实密码/多因素与三平台/长测仍保留。
