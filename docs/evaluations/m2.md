# M2 搜索、链接与桌面打开评估

日期：2026-10-20。基线为本轮开始前的 M1 工作树快照。平台 Darwin arm64，Rust 1.99.0，release 默认优化；未推送或提交工作区改动。

## 适配选择与成本

没有新增 Rust 第三方包、异步运行时或 UI 框架；直接/传递 Cargo 依赖仍为 0。搜索首版为精确纯文本，使用自写流式 KMP 和有限坐标窗口；新增 UI 复用现有字体和脏行渲染。正则和完整字素编辑没有作为未验证依赖接入。

- 搜索关闭时不扫描历史；链接只在鼠标进入新格子或显式动作时有界命中，不建全历史索引。无新增定时器或采样线程。
- 搜索输入会替换旧状态；结果窗口至多 1024，查询/预编辑各 1 KiB。结果与状态占内存，不把缓存计数伪装成完整匹配总数。
- OSC 8 的目标池受 1 MiB URL 正文与 1024 条双限。属性 ID 放进 Flags 的剩余位，三平台检查下单元格仍为 20 B；旧 ID 不复用，淘汰目标不会将旧文字重定向到新 URI。
- 目标池的保守保留水位在链接段结束、光标属性恢复或软复位时更新；重排后使用新文档水位。避免在每个普通字符上查表，仍由预算和历史淘汰约束。
- 桌面打开是自写参数/生命周期适配：macOS `/usr/bin/open`、Linux `gio open`、Windows ShellExecuteW。Unix helper 至多一个在途请求，空输入与输出重定向，不保留日志缓冲，5 秒取消/超时回收。Linux 不把直接 exec 浏览器的 `xdg-open` 作为超时杀死的对象。
- Windows 的 shell32 首次点击才从系统目录加载一份并持有到进程退出，默认启动不增加该 DLL 的显式加载。Windows 系统调用本身合作式取消；不等待不可中断的调用，也不为新点击增加线程。
- 打开线程第一次实际使用才创建，后续保留一个等待线程；有运行/待办/结果时忽略重复点击。启动浏览器会增加外部进程、CPU 和内存，不能声称零影响。浏览器属于用户桌面应用，不并入终端受管堆统计；现阶段未量化各桌面处理程序的实际启动成本。

Linux `gio` 版本/安装状态、Windows 系统分发与实际浏览器启动尚未真机测量，标为待验证，不声明已通过依赖发布门槛。链接复制和识别不依赖这些打开程序，程序缺失/失败会反馈错误。没有安装或下载额外工具；第三方搜索/GUI 库没有未测就接入默认路径。进一步引入包或更换打开后端时按 [依赖策略](../dependency-policy.md) 单独比较。

## 五轮交替对照

原始样本：[m2-bench.json](m2-bench.json)。两边分别构建后，按“基线→M2”交替五轮；同一 Maple Mono NF CN 30px、3616×2416 像素/200×60 格，按基准单线程运行。

| 指标（五轮中位数） | M1 基线 | M2 |
|---|---:|---:|
| VT 解析 | 132.3 MiB/s | 132.5 MiB/s |
| 整屏重绘 | 3.029 ms | 2.999 ms |
| 单行更新 | 0.313 ms | 0.315 ms |
| 按键处理到入队 P95 | 250 ns | 250 ns |
| 按键处理到入队 P99 | 1917 ns | 2583 ns |

解析/绘制没有稳定超过 5% 的中位数回退。单行约增加 0.7%，P99 增加约 0.000666 ms；差异较小且包含调度噪声，不作全场景提速或零成本保证。每轮输入基准为真实 PTY 会话的 1000 个字符/方向/复制按键，仅计处理到入队，不包括 OS 事件传递、echo、屏幕呈现。首轮单行基线还有 0.603 ms 异常值，全部样本保留，没有只筛选快样本。

初始版本逐字符做链接记账，同负载中位数 129.9→127.0 MiB/s（[初始数据](m2-bench-initial.json)）；随后移至属性状态转换。两组各自成对比较，不拿不同轮次的绝对吞吐宣称优化幅度。

最终 release 可执行文件（含 debug=1）为 1,564,712 B，M1 快照为 1,436,136 B，增加约 125.6 KiB；体积也包含构建路径和符号信息。

## 大历史搜索

五轮均填充到 67,108,608 B 历史行负载，查询不存在的 `missing needle`，完整扫描而非达到结果上限早停：

| 指标 | 结果 |
|---|---:|
| 时间片数 | 每轮 202 |
| 单片 P95 中位数 | 150 µs |
| 单片最大值的中位数 | 174 µs |
| 五轮观测到的单片最大值 | 191 µs |
| 完整扫描中位数 | 25 ms |
| 搜索状态 | 33,422 B |

同一进程内分片执行，原生事件每轮先处理；2 ms 是合作式上限目标，可能受调度或单步执行影响，不是严格实时保证。测量不含实际窗口绘制/输入法延迟；完整逻辑行不被复制，历史大小不会使搜索状态等比例增长。

## 原生启动与空闲

原始样本：[m2-runtime.json](m2-runtime.json)。macOS 原生窗口五轮交替，启动计时到 shell 就绪标记；预热 300 ms 后使用 `proc_pidinfo` 采集 3 秒空闲开销。每次核对恰好一个 `exec sleep 4` 的 shell 子进程，并自然退出。

| 五轮中位数 | M1 基线 | M2 |
|---|---:|---:|
| 启动到 shell 就绪 | 147.96 ms | 144.50 ms |
| congminal RSS | 109.97 MiB | 109.89 MiB |
| 线程数 | 14 | 14 |
| 空闲 CPU（单核百分比） | 0.00285% | 0.00281% |
| 子进程 RSS | 1.016 MiB | 1.016 MiB |
| 子进程 CPU | 采样无计数增量 | 采样无计数增量 |

原始数据保留首次系统初始化造成的 1036/487 ms 样本。中位数无超过 5% 的启动回退，未见关闭搜索/未点击链接时额外线程或可分辨空闲 CPU 增量。这不能推断开启浏览器后的资源占用。

## 重复搜索、取消与链接淘汰压力

原始时间序列及日志：[m2-stress.json](m2-stress.json)。90 秒无窗口真实 PTY 场景，保持约 64 MiB 历史，反复打开/更换查询、执行分片、处理按键、绘制高亮、关闭搜索并注册新链接；不启动浏览器。

- 完成 99,304 轮；历史行负载维持 67,107,840 B，未超过 64 MiB。
- 链接池从约 99 KiB 达到约 100 KiB 后稳定；关闭搜索后查询状态为 1/14 B，结果与扫描窗口释放。
- RSS 开始约 80.58 MiB，预热后约 89 MiB；10–30 秒为 89.03–89.05 MiB，30–90 秒稳定在约 89.02 MiB。包含字体与渲染缓存高水位，不等于所有分配立即返还操作系统。
- 线程数始终为 5，没有随轮次增加。
- 该压力场景观测最大分片 3249 µs，超过约 2 ms 目标；未单独剖析这次超额的原因，保留原始值。检查间隔与系统调度均不提供严格实时保证，不能用单独无窗口的 191 µs 最大值代替压力峰值。

这是短期压力验证，不替代 30 分钟验收。原生窗口、系统输入法、实际浏览器和多会话同时工作仍需后续测试。

## 验证命令与限制

```sh
cargo fmt --all -- --check
cargo test --offline
cargo clippy --offline --all-targets -- -D warnings
cargo clippy --offline --all-targets --target x86_64-unknown-linux-gnu -- -D warnings
cargo clippy --offline --all-targets --target x86_64-pc-windows-gnu -- -D warnings
cargo build --offline --release
cargo test --offline --release bench_ -- --ignored --nocapture --test-threads=1
CONGMINAL_STRESS_SECS=90 cargo test --offline --release integration_tests::stress_search_and_links -- --ignored --exact --nocapture --test-threads=1
bash ci/smoke.sh target/release/congminal /tmp/congminal-m2-smoke/smoke.png
```

正常测试 164 项通过，5 项手动基准/压力测试忽略；三平台 Clippy 检查通过。最终 release 的现有 macOS 冒烟脚本通过启动、运行和自然退出检查；系统截图命令无法取得显示图像。另已检查 [无窗口帧缓冲预览](../previews/m2-search.png)，不把它当作系统截图。包含旧终端/字体/图像回归与 M2 关键路径，模拟覆盖层像素会与从头绘制结果比较。浏览器不会被自动测试启动；正常/取消/错误/缺失后端行为在结构化适配与模拟 helper 中验证，不把模拟结果当作真实桌面性能。

未完成：Windows/Linux 运行、实际桌面浏览器成本与能力检测、完整原生输入法候选交互、原生窗口截图验收、端到端输入到呈现分位数、30 分钟压力。多会话和进程级准入账本尚未实现，仍依赖后续 M4。
