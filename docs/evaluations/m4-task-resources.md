# LatestTask 共享核心、取消令牌与提交一致性

本阶段只验收 LatestTask 的共享核心和显式计费取消令牌，不完成整个后台线程资源账本。无新增包、子进程或线程；默认发布依赖及现有安装包未改变，未提交或推送。

## 实现边界

每个 Budget 最多保留 **32 个 LatestTask 共享核心**。创建时先取得名额、预留 Shared/Arc 和 Mutex/Condvar 首次懒分配余量，再创建共享状态和原有工作线程。名额跟随共享状态的最后拥有者；关闭界面后，不可中断的工作仍占用名额和额度，不能立即用新任务替代这部分存活资源。该上限不是全进程所有线程上限，也不是 OS 线程已退出的证明。

每次生产提交使用 `try_submit`，先为取消令牌预留费用；失败会失效旧请求，向目录/SSH/字体/打开链接/通知调用者报告错误。任务创建的额度不足用固定 `OutOfMemory` 值返回，避免为预算错误另建装箱消息。请求版本使用 checked_add，耗尽后关闭核心，不回绕、不重放。旧结果失效与新输入发布在同一次持锁期间完成，旧输入/结果的用户析构和取消都移到锁外，避免析构重入任务状态时死锁。

工作器通知回调异常退出时关闭核心、清除待办和结果，后续提交明确拒绝。普通工作异常仍沿用错误结果路径。受管取消令牌可被结果/工作克隆保留，最后一份释放才归还其额度；Shared 和 Cancellation 的 Arc 强引用统一经 `into_inner` 退役，先释放 Arc 控制块，再归还成员票据。

**仍待**：线程 Builder/name/Notify/工作闭包及运行时、JoinHandle、TLS、实际线程栈、完整退出确认；泛型输入/结果内部动态缓冲及异常字符串不因 Shared 计费而自动受管。其他模块的 `Cancellation::default()` 仍未计费；为了让同一个取消原语支持票据，其 Arc 状态增加了一个可选 Lease，必须计入相邻回归及成本，不能宣称所有取消对象都已接入。

## 实际请求与生命周期

[当前编译器](m4-task-resources-allocation.json)和 [Rust 1.88](m4-task-resources-allocation-msrv.json)在临时源码副本中使用相同 epoch 全线程请求计量器。根 Budget/上下文先初始化，独立区间不创建线程，实际运行首次 Mutex/Condvar 零时等待、提交/替换/取消和最后拥有者释放。它检验共享核心和受管令牌，未用整个线程运行时分配冒充本轮覆盖。

| 阶段 | 实际存活请求 | 预留额度 | 核心名额 |
|---|---:|---:|---:|
| 一个核心及首次锁/条件变量 | 272 B | 304 B | 1 |
| 提交并首次等待取消令牌 | 416–464 B | 528 B | 1 |
| 替换请求、保留旧令牌 | 544 B | 752 B | 1 |
| 失效新请求、保留旧令牌 | 464 B | 528 B | 1 |
| 销毁核心、保留旧令牌 | 192 B | 224 B | 0 |
| 旧令牌销毁 | 0 B | 0 B | 0 |
| 32 个未使用锁的核心 | 5120 B | 9728 B | 32 |
| 全部释放 | 0 B | 0 B | 0 |

懒初始化时机导致首次提交请求数有差异，两份报告均覆盖实际值。替换/失效的实际请求峰值 **656 B**、预算峰值 **752 B**。全部步骤无扩容；零额度创建/令牌拒绝以及第 33 个核心拒绝零新增请求。32 核心使用栈数组，没有把测试容器容量计入核心费用。

新增七项常规任务回归验证 32 槽拒绝、共享/取消准入、无合作任务继续持票、返回令牌跨核心销毁持票、版本耗尽、待办析构重入、拒绝提交清除旧结果及通知回调异常。目录测试同步改为隐藏后仅保留 Tasks 费用、销毁拥有者后归零，未通过忽略仍存活核心费用来恢复旧断言。

## 同负载成本

[同负载对照](m4-task-resources-cost.json)将同一 System 分配器夹具注入冻结基线及当前副本：工作线程被通道阻塞时 100×1000 次待办替换，100×10000 次取消轮询，100×1000 次旧 Default 令牌创建/取消/零时等待/销毁。最终返回值必须是最后一次提交的 100000，语义指纹为 200000；两次预热、五组交替配对。

| 场景 | 配对耗时中位变化 | 范围 | 每次操作折算中位（前→后） |
|---|---:|---:|---:|
| 替换待办 | +17.08% | +10.09%～+20.77% | 79.69→92.95 ns |
| 取消轮询 | -35.18% | -39.84%～-33.20% | 0.72→0.47 ns |
| 旧 Default 令牌生命周期 | +7.81% | +3.72%～+26.95% | 75.65→88.44 ns |

整进程 RSS 配对中位 **+96 KiB**（+80～+112 KiB），CPU **+0.01s**（0～+0.01s，时间分辨率 0.01s）。夹具 API 区间排除验证、核心创建/销毁；整进程统计包含测试框架和一个工作线程，不能据此逐字节归因或声称系统进程/整程序成本已完整验收。默认令牌路径也有回退，不能概括成任务全面提速。新增准入及持票带来的提交增加约 13ns，保留边界以避免用漏计换取速度。
