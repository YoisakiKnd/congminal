# 可见认证面板控制器与阻塞描述符

状态：单连接 Controller 已协调实际 Front、Panel、Editor、受保护输入和剪贴板请求；真实 Cocoa 视图回调到 Controller/Backend 的串联已验证。认证/SFTP仍为测试模块，Workspace尚未拥有该控制器，没有用户操作入口；完整配置档/主机标题、鼠标控件、通知、退出确认和共享传输控制器仍待接入。本文件不代表完整M6或系统输入法验收。

## 输入占用与交接

[Controller](../../src/ssh/auth_controller.rs) 只为已选择的挑战创建，要求Owner与Front一致，一个面板、一个待交付粘贴请求，不创建线程/进程或读取文件。控制器对象按size_of加128字节预留，Panel/Editor/索引/文字分别沿用原账本；没有新建独立池或新增Cargo依赖。宿主仍需决定哪条活动连接可以打开覆盖层，后台连接不能凭该组件自行抢焦点。

InputContext新增明确的阻塞状态：保留完整原身份和账本Arc，但禁止生成文字/命令负载或构建Cocoa context。身份比较不因状态改变，因而阻塞再启用不能绕过退役校验。macOS管理器在收到阻塞描述符时先退役原client并返回nil，继续吞掉普通输入；只有宿主显式移除整个覆盖层才恢复普通context。

失焦清理Panel中的固定秘密/组合、提示索引、几何和未发出的粘贴请求，保留阻塞描述符；恢复时创建新Editor/view。已交给平台的旧粘贴仍独立拥有额度，返回后按旧身份拒绝，不能清掉新视图的在途请求。提交后同样释放面板并阻塞，等待服务器下一挑战再创建新view；关闭/过期继续阻塞，直至宿主明确移除覆盖层。新面板构建先释放旧面板，预算失败取消当前连接且不回落终端；后台快照刚失效时只等待重新同步，不取消可能刚发布的新挑战。

每次原生输入、显式决定、粘贴和绘制前同步Front，输入动作处理后也同步，包括失败路径。Submit经过Panel当前提示实际绘制的审阅门禁，组合未结束时拒绝。Confirm也获得有归属的命令context，文字不能成为答案；Enter默认回答no，只有带原控件token的明确同意才能回答yes。Panel在审阅或修改状态前先同步并核对token，旧控件不能给新提示留下审阅状态。取消无载荷额度，满额也能完成。

无归属Text/Preedit/Paste先清理已初始化字节，再做可能失败的同步；普通按键、复制/粘贴请求和鼠标事件均不透传给终端。当前鼠标事件只被阻挡，宿主尚未接同意/拒绝按钮的命中测试，不能称为完整可操作界面。结构事件仍返回给宿主；CloseRequested先取消并清理该连接，但不证明后台SSH/helper已经退出。

## 额度和组件耗时

[分配工具 --controller](../../tools/check_auth_allocation.py) 在临时副本注入当前线程Rust请求字节计量，运行实际控制器；生产allocator保持不变。生命周期负载是16KiB控制字节展开成64KiB完整提示、旧/新换行索引重叠、最大1023字节在途粘贴跨失焦/重建、旧粘贴拒绝、最大提交和答案移动。源数据在栈上，渲染器/字体/画布与共享预算/线程/时钟先预热；测量区只新增控制模型与应用文字。

两工具链十个采样点结果一致，所有请求存活/峰值都有相应账本覆盖：

| 阶段 | Rust请求存活 | 请求峰值 | 账本存活 | 账本峰值 |
| --- | ---: | ---: | ---: | ---: |
| 创建控制器/提示/首个索引 | 330174 B | 330174 B | 336109 B | 336109 B |
| 旧/新索引重叠 | 592326 B | 592326 B | 598517 B | 598517 B |
| 最大粘贴在途 | 331277 B | 592326 B | 337372 B | 598517 B |
| 失焦后仍持有旧粘贴 | 67079 B | 592326 B | 68183 B | 598517 B |
| 新view创建、旧粘贴仍在途 | 331277 B | 592326 B | 337372 B | 598517 B |
| 答案已提交、后端已取走并释放 | 336 B | 592326 B | 1256 B | 598517 B |
| 控制器/后端/快照全部释放 | 0 | 592326 B | 0 | 598517 B |

旧粘贴、共同输入String、提交答案三次均在allocator释放前检查初始化字节已清零，3通过/0失败，不读释放后内存。[当前](m6-sftp-auth-controller-allocation.json)、[Rust1.88](m6-sftp-auth-controller-allocation-msrv.json)。控制器对象主要内联在调用方，账本仍按完整对象收费；Rust堆请求与账本预留不要求相等。失焦时Front仍保留当前挑战提示，故不要求此时全部归零。

另做200次暖“有归属输入→控制器→软件绘制”：100次单字节提交各解码一个String，100次删除命令无载荷分配，总计100分配、0扩容、净存活0，模型/渲染账本存活不增加。当前/Rust1.88的P50/P95/P99/最大为58/59/61/62 µs、64/68/69/71 µs；其中解码/控制器段为166/209/292/542 ns、167/250/292/375 ns。原始200点排序样本保留，使用nearest-rank。短提示、单字符和暖缓存负载与此前长提示绘制探针不同，不能据此宣称优化幅度；没有输入法、NSEvent调度、窗口呈现、冷缓存或完整UI尾延迟结论。

原生对象和直接回调到Editor亦在两个工具链复验，峰值分别5459/3981 B、账本12535/15869 B，最终均0，4/5次释放前清零无失败。见[对象当前](m6-sftp-auth-controller-native-lifetime.json)、[对象Rust1.88](m6-sftp-auth-controller-native-lifetime-msrv.json)、[Editor当前](m6-sftp-auth-controller-native-editor.json)、[EditorRust1.88](m6-sftp-auth-controller-native-editor-msrv.json)。这两类原生探针与控制器大提示负载分别计量，不能简单相加为全应用硬峰值。

所有请求字节均不含allocator自身、C/ObjC/OS内部副本、RSS和栈；缓存预热不等于冷启动零成本。没有新增包、后台线程、进程或轮询器，普通App仍返回None；新增描述符状态检查的全窗口成本仍待完整GUI测量。
