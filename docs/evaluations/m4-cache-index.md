# M4 缓存桶、FIFO 及组合缓存

零新增依赖、线程、子进程或 unsafe。缓存 Key 限定 Copy；字符串归属于受管值，组合缓存也用指纹定位、原文及格数校验，命中不再创建临时 String。临时字形和字符串先准入，缓存申请负载模型差额及桶空间后原子接管已有额度。

新增 `cache-index-model` 分项，保守覆盖 std HashMap 桶/控制字节和 VecDeque 实际容量。扩容前覆盖旧、新块重叠，失败归还未提交的负载差额并尝试淘汰；可复用已有桶时不扩容。清理缓存现释放桶和 FIFO，之后才归还额度；先前 clear 保留这些分配。每个缓存新增一个汇总票据，不给持久条目增加票据，命中不更新账本。

**这是有探针验证的标准库布局模型，不是稳定 ABI 或精确 RSS。** HashMap 公共 API 不提供底层分配大小；以容量推导保守桶数并预留控制分组/对齐空间，保留原有负载固定估计，存在保守重复计费。更新 Rust 工具链须运行 [缓存探针](../../tools/check_cache_pressure.py)：

```sh
python3 tools/check_cache_pressure.py --output /tmp/cache-probe.json
```

工具只在临时副本注入分配器；正常测试/应用不安装该分配器，不用探针计时。提前初始化测试线程及 Mutex 的一次性元数据，四种实际布局各插入 4096 项，零负载费用、零动态值内存，每次插入都断言实际 Rust 请求 live/peak 被指数额度覆盖，含 realloc 旧、新块重叠。56 个边界样本均通过，clear 后请求字节及额度都为零。

| 4096 项布局 | 实际保留 / 准入模型 B | 实际扩容峰值 / 准入峰值 B |
| --- | ---: | ---: |
| 普通字形键/值 | 630,792 / 630,856 | 929,808 / 929,936 |
| 编号字形键/值 | 614,408 / 614,472 | 913,424 / 913,552 |
| 连字原文/结果头部 | 565,256 / 565,320 | 831,504 / 831,632 |
| 组合原文/字形头部 | 892,936 / 893,000 | 1,323,024 / 1,323,152 |

前后相同头部布局的桶容量及请求峰值不变，模型没有通过扩大全局 512 MiB 限额消除拒绝。小额度测试显式加入新计费的索引大小：覆盖只够负载时分配前拒绝、扩容重叠被拒后淘汰并复用旧桶、跨账本、满池转移、清理回收及碰撞原文校验。组合缓存原本 String 键，改后较大的值头部有真实成本，不把此表解释成该缓存所有布局均不变。

五组交替前后计时，输入和输出校验值一致，探针与计时分开构建：

| 操作 | 前→后 |
| --- | ---: |
| 七词冷连字批次 | 78.494→78.836 µs |
| 同组热连字批次 | 1.341→1.341 µs |
| 冷 emoji 组合生成/缓存/销毁 | 32.937→33.351 µs |
| 热 emoji 组合查询及小摘要 | 36→13 ns |

冷连字请求峰值 2,462→3,054 B，因为新 clear 真正释放桶，每批须重新申请；旧基线清理后保留的桶在探针开始前已存在。冷 emoji 峰值 14,840→14,822 B，热查询临时分配 18→0 B。缓存中位冷成本约增 0.4%/1.3%，不是免费。纳秒微基准不代表真实 UI 输入到呈现。

完整五组基准：整帧 3.021→3.028 ms，四窗格 604→609 µs，局部 25→25 µs。十组独立预热整帧 3.025→3.019 ms、单行 0.313→0.312 ms。工作区输入 P95 292→292 ns。VT 原始中位 120.7→129.8 MiB/s，源码未变且前组波动更大，保留样本，不将其当缓存收益。

Debug/release 各 297 通过、13 显式忽略，显式 Maple Mono 编程连字通过；三平台 all-target Clippy `-D warnings`、格式及 release 构建通过。6 秒本机真实 PTY 压力冒烟没有额度拒绝，记录准入峰值 248.7 MiB，销毁后 used/mappings 均归零；样本 RSS 约 191.4→198.5 MiB，线程 14。负载尚在增量建历史，不能从六秒推断 RSS 稳定或长期无泄漏；不是 30 分钟验收。
