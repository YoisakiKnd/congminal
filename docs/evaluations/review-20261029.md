## 需要优先修复

### 1. P1：远程 Git 的路径可以成为远端 shell 命令

位置：`src/git/mod.rs:1188–1224`。

代码把远程目录、路径及 Git 参数分别传给 `ssh`，并认为它们不会经过 shell。然而 OpenSSH 会用空格把远程命令参数连接后发送；本机 `/usr/share/man/man1/ssh.1:99–104` 也明确描述这个行为。目录包含空格会拆词，分号、替换表达式等可以改变命令。工作目录来自远程会话，打开只读 Git 面板也会经过这条路径。

临时探针使用按 OpenSSH 语义连接参数并执行 shell 的假传输程序，传入 `/missing; printf REVIEW_INJECTED #`，真实 `run` 返回了标记。现有 `fake_ssh` 用 `exec "$@"` 保留参数边界，未模拟远端 shell，无法覆盖此问题。本轮没有使用真实远端主机验证。

修复：明确远程 shell 协议，逐参数正确引用原始路径，或通过固定远程入口传递结构化数据；把工作目录、diff 路径和所有动态参数都纳入边界。远端 Git 的相关环境变量也必须在远端设置，本地给 ssh 的环境并不保证转发。增加空格、引号、换行、分号及无效 UTF-8 路径的验证。

### 2. P1：Git 的 `--` 不能保证文件名按字面匹配

位置：`src/git/mod.rs:1470` 附近各个按文件操作的 `run` 调用，以及 diff 路径构造。

暂存、取消暂存、撤销修改、冲突解决等把原始文件名放在 `--` 后，仍会被 Git 当作 pathspec。探针创建实际名为 `:(glob)*.txt` 的文件及未选中的 `victim.txt`，只暂存前者，后者也进入了索引。撤销修改存在同类扩大操作范围的风险。

修复：在所需命令范围启用 literal pathspec，并控制继承的 pathspec 环境；保留原始名字节。覆盖 `:(glob)`、通配符、方括号、前导短横线、重命名两端，以及暂存/撤销/冲突等各条入口。

### 3. P1：本地目录上传在 UI 线程无界收集目录

位置：`src/workspace/remote_upload.rs:94–101`、`src/sftp/local_plan.rs:114–123`。

预览直接同步调用 `local_plan::walk`，传入一个没有外部取消拥有者的新令牌。遍历器先把一个目录的全部 `DirEntry` 和名字收进 `names` 并排序，之后才执行文件数及估算内存检查。2,000 文件/512 KiB 仅限制输出，不限制之前的工作集或扫描数量。文件达到上限后仍继续遍历剩余目录；一个巨大目录或慢文件系统足以卡住整个窗口。目录内循环也没有取消检查。

修复：移动到受准入的后台任务，绑定会话/连接/预览代次；读取和收集前限制累计扫描量、队列、目录数、路径容量及排序工作集，循环内检查取消。保留有界结果并明确截断，拒绝或取消后释放全部工作所有权。不能仅将原遍历器放入线程便宣称内存问题已解决。本项由调用链静态确认，未运行慢磁盘压力实验。

### 4. P1：Git 超时会提前退还仍存活读取器的缓冲额度

位置：`src/git/mod.rs:1144–1169`、`1185–1187`、`1256–1263`。

stdout/stderr 读取器持有裸 `Vec`，其输出票据只留在 `run` 栈上。取消/超时杀死并等待直接子进程后，函数立即返回；后代进程若继承管道，读取器还在阻塞和持有已读缓冲，票据却已经析构。运行时的线程票据并不代替 Git 输出缓冲票据。

探针先输出 65,536 字节，再由短时后代持有管道：`run` 超时后，`git-reserved=0`，仍有 2 个受管读取线程存活。探针随后等待后代自然结束及资源归零，没有遗留长驻子进程。

修复：输出缓冲的票据随读取器移动、随结果交接，错误路径也由实际最后拥有者释放；处理子进程树及继承管道，清理无法确认时保留相应费用和状态。缓冲扩容还需覆盖旧/新分配重叠。

### 5. P1：Git 结果先分配，之后才申请结果额度

位置：`src/git/mod.rs:773`、`995–1048`、`797–814`。

`parse_status` 无预算参数，直接分配条目数组、原始路径、转义临时字符串和展示文本。`finish_snapshot` 收到这些已分配值后才申请额度；输入 stdout 的票据不足以同时覆盖原输入和多份展开后的结果，`WORK_BYTES` 也在末尾才申请。低额度时可先超出准入模型再报 Budget。

修复：为解析工作集预先准入，增长前覆盖重叠，并将结果票据移交到 Snapshot。需要同一分配 epoch 的低额度拒绝、转义放大、最大条目数及最后释放证据。本项为静态确认，尚未测量完整放大倍数。

### 6. P1：监控额度没有跟随真正的数据拥有者

位置：`src/workspace/monitor_panel.rs:174–184`、`313–340`，`src/monitor/mod.rs:370–384`。

历史先创建再申请额度；后续改变历史点数会重建环形队列，但已有票据没有同步调整。采样器由工作闭包持有，256 KiB 预留却由 Panel 持有，关栏会在工作器确认退出前释放预留。进程列表仅最终显示 5 行，`sysinfo` 内部仍刷新和持有全部系统进程；16 个句柄上限没有限制内部进程表内存。固定预留源自单台 Linux 机器的 RSS 差值，不能作为跨平台和任意进程数的准入上限。

修复：区分历史、采样器、回包和显示内容，票据分别由真实拥有者持有，直到实际释放。历史变更使用事务式准入；第三方内部容器需要可证明的限制、受控适配或隔离策略，不能通过提高固定预留替代边界。补进程数量变化、暂停/关闭在途采样、低额度和配置变化测试。

### 7. P1：远程监控读取阶段绕过取消和超时

位置：`src/monitor/remote.rs:142–159`。

先等子进程退出再读 stdout，有管道填满导致等待超时的风险；子进程退出后又进入阻塞 `read_to_end`，此阶段不再检查取消或期限。后代持有管道时能一直阻塞。

复现用短时后代保持管道打开，直接子进程通过 `exec true` 退出；1 秒后取消，`run` 仍在 3.381 秒后返回成功。原探针在 150ms 取消时未稳定进入读取阶段，断言失败；已保留首轮日志。第二版延后取消用于明确观察读取阶段，四个最终探针全部确认预期缺陷。

修复：并行、有界地排空 stdout，读取和等待共用取消/期限，保留子进程及管道清理状态，回包前再次核对取消。沿用受管运行时及正确的缓冲票据，不增加无界读取线程。
