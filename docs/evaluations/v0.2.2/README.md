# v0.2.2 启动目录与窗口标题

Windows 本地终端此前继承启动器目录。Scoop 快捷方式或直接打开安装目录中的 EXE 时，该目录通常是安装目录。新默认在配置模型中明确设置为用户主目录，使实际 shell、文件侧栏和 Git 的目录回退保持一致；不更改 congminal 进程自身的工作目录，显式配置与相对路径仍按原启动环境解析。

主目录通过有界 `GetEnvironmentVariableW` 查询 `%USERPROFILE%`，最多 4096 个 UTF-16 单元，并限制为本地绝对路径。变量缺失或格式不合法时保留继承行为。默认目录仅在构建配置时确定，不增加目录扫描、启动探测子进程、线程或后台刷新。本地连接配置档未指定目录时采用同样默认；明确配置的路径优先，全局 `shell.working-directory = "."` 可继承启动目录。

原生窗口初始标题保持 `congminal`；应用的 OSC 标题仍更新窗格/标签页。删除了专供窗口标题的待发送字符串及切换窗格时的复制，避免为固定标题反复分配和调用原生窗口 API。认证面板等独立窗口保留自身标题。

验证包括 macOS 本机 901 项主程序、21 项 helper 回归通过，macOS/Windows 目标 Clippy 通过。三平台 CI 保留真实 `ratatui-image` 自动探测、完整图片传输、认证传输、应用冒烟及最低 Rust 版本检查。

新增 `ci/check-windows-startup.ps1` 在 Windows 原生 GUI 中从程序目录启动独立配置，检查默认主目录、带空格和中文的显式目录、`.` 继承目录。子 shell 主动将标题改为模拟 Scoop 的 `pwsh.exe` 路径，检查实际进程窗口标题持续为 `congminal`；每例正常退出并清理临时夹具，不更改用户配置。
