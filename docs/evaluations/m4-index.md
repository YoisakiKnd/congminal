# M4 重排行索引交接评估

日期：2026-10-21。工作区未提交、未发布。基线是本轮开始的本地快照 `/tmp/congminal-index-baseline-01a158a4`，已含历史共享计费与压力回收，源码与上一轮最终历史构建指纹一致；并非远端 alpha.5。没有新增依赖、生产线程或周期任务。最终源码及检查见 [构建记录](m4-index-build.json)，机制见 [重排说明](../execution-m4-reflow.md)。

## 改动与所有权

UI 作业原先逐行从输出索引取行，再逐行插入另一份历史索引。现在在原 VecDeque 中按工作预算轮转校验，拒绝单行超额项；校验结束后分片淘汰最旧前缀，直接转交行索引及其已准入额度。交接阶段不另建完整索引、不重新扫描全部历史，旧终端在提交前保持可读。

输出索引的末次增长按保留行数上限截断，避免翻倍到永远用不到的槽数。若淘汰后容量超过保留行数两倍且超过 32 槽，则分片迁移保留后缀来收紧索引，避免少量文本长期持有大空表。取消先销毁输出及空索引，再归还历史借用的聚合额度。新旧索引重叠继续由原保守模型预留，没有减少文本配额、放宽账本或改变 cell 所有权策略。

Debug/release 各 **267 项通过、13 项手动基准忽略**；macOS 本机、Linux x86_64 GNU、Windows x86_64 GNU 的 all-targets Clippy `-D warnings` 通过。新增测试验证满账本中交接不增加准入拒绝、原索引容量被转交、173 组不同宽度及紧配额与整表接管相同、校验/淘汰/索引收紧中途取消保持旧源并归还额度、输出索引容量不突破保留上限。原有 2100 组参考重排差分及 585 组完整终端对照继续通过。

紧配额测试保留每行原始 cell 容量后，与已有整表接管对照；消费重排可能复用更宽的旧缓冲，而只读路径使用新缓冲，两者在相同容量额度下保留行数本就可以不同，不能混用这一差异来判断索引校验是否正确。三平台交叉检查不等于原生窗口运行验收。

## 分配峰值

前后分别在测试副本注入同一线程局部 GlobalAlloc/System 探针，记录缩放前基线之上的额外存活请求字节；realloc 保守计旧新重叠，不是分配器 usable-size 或 RSS。九个场景均通过峰值不超过准入余量、最终网格受票据覆盖、临时票据释放及终端销毁后额度归零的断言。代码和全部样本见 [基线](m4-index-allocation-before.json)、[当前](m4-index-allocation-after.json)。

| 场景 | 基线额外峰值 MiB | 当前额外峰值 MiB | 变化 |
|---|---:|---:|---:|
| 64 MiB 硬行缩窄 | 67.782 | 64.091 | -5.45% |
| 64 MiB 硬行扩宽 | 67.797 | 64.077 | -5.49% |
| 64 MiB 长软行 | 71.056 | 64.045 | -9.87% |
| 窄历史扩到 4096 列 | 64.567 | 64.561 | -0.01% |
| 4096 列宽字符缩到 1 列 | 0.778 | 0.578 | -25.63% |
| 2048 行先扩宽再缩为 1 行，同步路径 | 160.086 | 160.086 | 0% |

降低的是索引容量与交接重叠，**不是消除了文本副本**。64 MiB 长软行仍额外需要约 64.05 MiB；同步消费路径此前约 8.88 MiB，内存策略差异仍然显著。工作集准入模型未收紧，不能把分配下降描述为共享账本峰值也下降。

五组交替先后顺序，四个真实 PTY、软/硬混合历史、每次八轮实际列数变化；双方运行相同原始 App/Workspace 用例。布局请求后立即发送回显，推进 tick 和到期 draw，直到提交、退休完成且回显可见。request 是布局调用，complete 包含作业与回显，不是原生事件到显示呈现。libproc 约 50 Hz RSS 样本、直方图和日志见 [UI 完整记录](m4-index-ui.json)。下表为各次运行汇总的中位数。

## 重复运行与剩余边界

最终源码的 [1000 轮缩放](m4-index-ui-pressure.json) 完成 21,594 次待处理 UI turn，动作阶段约 12.55 秒，全部回显到达，输出实际峰值 17 字节；tick 最大 1.925 ms，输入处理最大 9.583 µs，request 最大 1.128 ms，complete 最大 25.923 ms。RSS 峰值 210.38 MiB，后半段约 209.50–210.38 MiB；销毁后全部额度与映射归零。另有 [六秒压力工具检查](m4-index-pressure-tool-smoke.json)。长循环的 RSS 仍高且有增长，不能将短对照组的范围当作长期保证，也不能代替 30 分钟验收。

增加紧配额索引收紧之前的首组数据保留在带 `pre-compact` 后缀的文件中，例如 [UI](m4-index-ui-pre-compact.json)、[分配](m4-index-allocation-after-pre-compact.json) 和 [常规基准](m4-index-bench-pre-compact.json)；当前表格与构建记录只使用最终源码数据。

本轮完成索引峰值收紧。下一步仍需评估减少只读 cell 副本的表示与所有权方案，覆盖字体解析/光栅化/解码、缓存桶及任务元数据，以及同步高度/备用屏/画布/关闭路径的延迟。512 MiB 是混合额度，完整堆/RSS、真实窗口输入到呈现、启动、三平台真机及 30 分钟稳定性均未宣称完成。详见 [计划](../roadmap.md)。
