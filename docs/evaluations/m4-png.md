# M4 PNG 内存准入与副本优化评估

日期：2026-10-21。工作区未提交、未发布。基线为本轮开始的本地快照 `/tmp/congminal-png-baseline-01a158a4`，已含上一轮重排行索引优化；不是远端 alpha.5。没有新增包、生产线程或周期任务。最终源码及检查见 [构建记录](m4-png-build.json)，额度公式与边界见 [资源说明](../execution-m4-memory.md)。

## 本轮范围

只读重排剩余约 64 MiB 的额外存活请求主要是新文本本身，继续减少需要调整存储/读取接口。本轮转向计划中另一项独立缺口：PNG 解码工作集及返回 RGBA 的共享准入，没有修改文本所有权策略。

先借用输入验证结构、CRC 与头部，再申请 `joined + expected + rgba + 4096` 字节；`expected` 是全部扫描行精确大小，包含 Adam7 每遍的过滤字节。PNG 使用精确预留一次的解压输出，写出仍逐块检查上限并验证最终长度；单 IDAT 借用原始压缩数据，多个 IDAT 准入后精确拼接。不为块列表分配随文件内容增长的索引。

解过滤直接修改解压缓冲，保留过滤字节及上一行跨度，每个隔行 pass 独立开始；不再创建整幅解过滤副本。临时缓冲销毁后，票据缩到返回 RGBA 的报告容量，随 Image 保留到像素销毁。RGBA 字段不再允许其他模块直接扩容。输入本身由调用者/字体映射持有，不重复收费；4 KiB 仅覆盖当前有固定上限的哈夫曼与码长堆缓冲，不是完整堆/RSS 模型。

## 正确性与拒绝

Debug/release 各 **274 项通过、13 项手动基准忽略**；macOS 本机、Linux x86_64 GNU、Windows x86_64 GNU 的 all-targets Clippy `-D warnings` 通过。新增七项测试覆盖：

- 返回图片离开创建资源上下文后仍持有原拥有者额度，销毁才归零；输出能容纳但工作集不能容纳时，分配大缓冲之前拒绝。
- 准入后无效过滤、解压数据过短/过长均归还工作集，其他仍存活图片的额度不变。
- 单 IDAT 和 1/2/7/128 字节分段 IDAT 像素相同且不修改输入；五类过滤、低位打包及 16 位通道保留邻行关系。
- 小尺寸 Adam7 空 pass 和每遍首行 Up 预测的重置；精确解压覆盖 stored/fixed/dynamic 并拒绝长度两侧的不匹配。

既有 ImageMagick 像素夹具、CRC、逐字节截断、压缩炸弹及彩色字体测试继续通过；16 位夹具沿用既有允许 1 级差异的换算验证。没有改变 4 Mi 像素、32 MiB 输入、尺寸及精确解压上限。三平台编译检查不等于原生窗口验收。

## 分配与 PNG 性能

七个固定输入：三个既有小图片夹具，Python zlib 生成的最大 2048×2048 RGBA16、1024×1024 随机 RGBA8 的单/多 IDAT，以及 1024×1024 RGBA16 Adam7。输入文件哈希、大小、测试注入、分配探针与全部轮次见 [完整数据](m4-png-decode.json)。

分配使用测试副本中的线程局部 GlobalAlloc/System 探针，计 Rust 请求字节和 realloc 旧新重叠，**不计调用者已有的输入文件字节，不是 usable-size 或 RSS**。所有场景的 RGBA 长度与校验值和基线一致；当前峰值不超过已准入余量，返回时额度等于 RGBA 容量，销毁后归零。基线没有 PNG 共享计费，不能把基线 ledger=0 解释为没有分配。

| 场景 | 基线请求峰值 MiB | 当前请求峰值 MiB | 变化 |
|---|---:|---:|---:|
| RGBA16 2048×2048 | 80.053 | 48.002 | -40.04% |
| 随机 RGBA8 1024×1024，单 IDAT | 16.003 | 8.001 | -50.00% |
| 同图，多 IDAT | 20.001 | 12.003 | -39.99% |
| RGBA16 1024×1024，Adam7 | 16.015 | 12.002 | -25.06% |
| 37×23 RGBA8 | 0.01204 | 0.00658 | -45.39% |

最大场景准入约 48.006 MiB，返回图片继续持有 16 MiB。初版仅原地解过滤、仍逐步扩容时的完整峰值为 64.003 MiB；最后一次解压扩容仍同时存活两份约 32 MiB 缓冲。该中间组保留在 [扩容版本记录](m4-png-decode-pre-exact.json)，不能把它的约 48 MiB 主要缓冲合计当成实际峰值。最终精确预留版本才达到约 48.002 MiB 的完整请求峰值。

性能使用另外两份不带分配探针的测试副本，五组交替对照，包含解码及销毁。每次小图 100 次，大图 3 次；下表是各次运行均值的中位数，样本较少的大图不报告 P95。

## 剩余边界

这一步只覆盖 PNG 解码及返回 RGBA。缩放权重、浮点行/输出，字体轮廓解析、光栅化、COLR 图层及缓存桶/任务元数据仍待接入，最终字形沿用已有缓存计费模型。PNG 准入错误可能触发字体原有单色/缺字或组合降级及缓存路径，额度恢复后的自动重试尚未统一，必要时需清缓存/重新加载字体。

只读文本重排副本、同步路径/关闭延迟、启动、三平台真机及 30 分钟稳定性继续列在 [计划](../roadmap.md)。没有把 PNG 峰值下降解释为完整堆/RSS 已受控，也未新增系统 OOM 必可恢复的承诺。
