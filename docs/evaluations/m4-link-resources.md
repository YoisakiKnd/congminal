# M4 链接目标池、命中检测与 URL 拥有者

2026-10-25。新增 `links-reserved`，OSC 8 目标记录及每份 URL 文本在分配前准入；可见 URL 检测不再为每个格子建立 String、片段队列和坐标索引。无新增包、线程或运行时子进程。本页只验收链接缓冲及其转交；桌面打开工具内部 Command、平台转换/错误、通用任务和完整应用元数据仍待。

## 目标池与所有权

HashMap 加 ID 队列改为按单调 ID 排列的 VecDeque，每条含真实 ID、最后行号和唯一拥有的 URL。原有 **1024 条、1 MiB 文本、每 URL 2048 UTF-8 B** 限制保留，不给新链接复用旧 ID。普通连续 ID 先用与首项的差值定位并检查实际 ID；稀疏淘汰后校验失败才二分查找，不能把当前位置当作 ID 直接返回。到 Flags 上限后拒绝新增，不回绕。

记录从 4 槽按需倍增，扩容前同时保留旧、新块；完成后按真实 capacity 收紧。字节或条目上限要求先淘汰一个旧目标时，不为本可复用的槽位无谓扩容。新 URL 和记录容量准备成功后才淘汰旧目标；准入失败保留旧 URL 和 ID，不损坏原关联。prune 保留活跃属性并按最后行号淘汰，坐标重排仍更新保守水位。

每个 Url 持有自己的 String 和票据，不提供生产 Clone/From 隐式分配接口。OSC 解析先在 2048 B 栈块拼接分号片段，验证 UTF-8/HTTP(S) 和上限后再分配。目标池和每条文本捕获创建池，跨 Scope 操作不转记到别的预算。prune 归还已释放文本，但保留的记录容量继续收费直到池销毁。

命中结果的新 URL 先准入后复制。菜单复制直接把命中 Url 的 String/票据移动给 CopyText，打开任务同样直接接收 Url，原终端销毁后仍持票；转交本身不复制文本、不重新申请额度。为仍需保留悬停文本的 Shift 点击复制，独立剪贴板副本继续按其拥有者收费。转交的原 URL 仍记 `links-reserved`，不能再按 clipboard 分项重复加算。

## 无堆临时词扫描

可见文本检测借用格子的基础字符、附加符号和按原规则补入的 VS16，不为每格构造 String。向左右确认同一有界词后，在固定 **2048 B 栈块**拼出文本；记录目标偏移，再遍历格子恢复 URL 起止坐标，不建立片段/偏移 Vec。最终确认目标、点击位置及范围后只分配一份已付 URL。非法词、非 URL、超长逻辑词和隐藏字符不产生临时堆请求。栈空间有明确上限，但不计入本页堆分配数字。

保留软换行连接、宽字符坐标、组合符/emoji、括号平衡和标点裁剪、HTTP(S) 大小写规则、隐藏链接拒绝。打开前仍重新检测并比较当前悬停目标，外部进程只由显式用户动作触发。共享额度不足时不产生新命中/不打开旧目标，拒绝由全局额度诊断计数；本页没有加入按 OSC 输出逐次弹出的警告。

Url 构造器检查长度和额度，目标合法性由池插入/命中确认及 launcher 打开前各自验证。仅测试构建提供 From<&str>，支持既有合成 UI 夹具与 launcher 拒绝非法目标的回归；测试便捷构造不属于生产准入接口。

## 实际分配

[当前工具链](m4-link-resources-allocation.json)和 [Rust 1.88](m4-link-resources-allocation-msrv.json)采用同 epoch 全线程 Rust 请求计量，保守包括 realloc 旧、新重叠。池/Scope/锁、源终端及夹具字符串在测量前建立；计量器附加头、分配器/C/OS、实际栈和全部根预算元数据不在本页请求数字内。

1024 条各 74 B URL 的最终记录块为 **65536 B**（Entry **64 B**），加文本合计 **141312 B**，实际存活请求与账本相同。累计 1033 次请求，其中 8 次扩容；遍历全部 ID 的 get/touch 零新增分配。

逐次核对 4→1024 槽的九个增长点，实际请求峰值均等于当时预算峰值，未借最后满额高水位掩盖早期重叠。例如第 513 项增长到 1024 槽时，存活 **103498 B**，扩容重叠峰值 **136266 B**；随后装满才到 **141312 B**。

| 阶段 | 实际存活请求 = 链接池额度 |
|---|---:|
| 1024 条记录/文本 | 141312 B |
| 全 ID 查询/触碰 | 141312 B，无新增请求 |
| prune 只留一个目标，记录容量保留 | 65610 B |
| 建立命中输出，再无复制转交 CopyText | 65684 B |
| 源池销毁，仅保留输出 | 74 B |
| 输出销毁 | 0 B |

满池拒绝额外 URL/独立目标池不产生新分配，最后归零。4 MiB 人工压力票据只用于拒绝场景，不当作真实堆峰值。

真实 Terminal 的独立命中区间：非 URL 零新增分配，可见 URL 与 OSC URL 共 **2 次分配、0 次扩容、49 B** 最终文本；额度覆盖，移交 CopyText 保持原指针，源终端先销毁后结果仍持票，最后整个源池及本轮请求归零。桌面打开任务的内部线程/Command 未包含在这个区间内，不能以 URL 拥有者测试代替整个任务/OS 成本验收。

## 行为与性能取舍

新增三项常规回归覆盖创建池归属、记录增长拒绝保留旧 ID、稀疏/环绕队列与 ID 耗尽、活跃项保留，以及基础字符/附加符号的独立旧规则对照和 URL 转交生命周期。原有逐字节 OSC 分段、SGR/重排、软换行/宽字符/括号、超限/控制符/隐藏目标等五项继续通过。

初版只用二分查找，使全部 ID 的 get/touch 微基准约慢八倍；结果保留为 `*-before-dense-index.json`。最终连续 ID 直接定位后核对真实 ID，稀疏时保留二分回退，没有减小目标上限、忽略旧 ID 或取消额度以换取计时。旧 HashMap 的不透明桶布局也不再用未经证明的逐项估计收费。

[最终同负载对照](m4-link-resources-cost.json)把同一 System 分配器夹具主体注入前一阶段冻结源码及当前副本，两次预热后五组交替。插入适配器明确记录原来的 String 参数构造和当前借用参数/实际 Url 准入；全部适配器源码及哈希保留。每轮：200 批各 1024 次 get/touch、1000 次满池轮换插入、各 1000 次可见/OSC/非链接检测，以及 200 批各 1000 次实际 OSC 解析/输出/prune。比较 ID、目标、命中坐标及最后可见格子的真实 URL 关联指纹；不只比较数量。

该协议负载显式每帧调用 prune，代表给定工作序列，不是通用 VT、真实窗口帧率或所有终端输出的吞吐结论。计时排除哈希和最终拥有者销毁，插入计时包含原参数字符串或新版实际准备；进程 CPU/RSS 包含构造、历史、验证和全部析构。
