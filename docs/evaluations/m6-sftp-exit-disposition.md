# SFTP 退出处置与传输结局核对

2026-10-24。退出界面已接入工作区候选，仍仅在 Unix 测试入口编译，未进入 Alpha.6；不表示完整 M6、原生窗口或三平台验收完成。没有新增包、线程或扩大原 16 MiB SFTP 子池。

## 行为

关闭先取消准备、目录、文件任务和认证，等待原工作器及回收线程结束。`Shutdown::Complete` 还须核对执行器的 `joined` 事实；若回收器异常而工作器结束无法确认，保持窗口，不提供确认退出，不把未知状态当成功。该状态重复观察不持续请求绘制。

确认线程结束后，回收失败/未知会显示退出警告。即使通道回收正常，只要文件提交不确定、目标持久化/暂存清理有警告、传输中断或结局缺失，也要核对。普通已确认且没有上述异常的关闭继续自动完成。

警告保留发布、警告、取消、失败、不确定、中断及未开始计数；不因取消或用户确认退出更改原发布事实。窄窗口按字符宽度换行、分页，只有连续实际绘制全部警告且确认按钮完整可见时，点击才能退出。Enter、Esc、重复窗口关闭都不确认；焦点、渲染/几何变化和翻页使旧点击失效。单终端模式使用现有画布，无须为退出再创建工作区或画布。

用户可先进入任务列表查看原主机、路径和部分文件候选的只读报告，再返回警告。退出检查期间取消、清除和重试入口关闭，并在事件处理处再次拒绝旧的修改点击；不会删除文件、自动重试或重放认证输入。查看详情时继续有界排版，静止检查界面不因退出 dirty 标记持续重绘。

## 内存与性能边界

退出视图只保留固定摘要与点击/分页状态，存入原 State，其尺寸由原 State 准入票据覆盖。本机 State 计费比重试阶段增加 280 B；正文与换行索引使用固定栈数组，不持有路径副本，不创建新后台工作。异常摘要只在 join 后冻结一次，随后不重复扫描所有文件进度。

探针退出视图存活 Rust 请求 1,138,931 B，子账本 5,065,489 B（包含栈预留等计费），输入分类 40,128 B；包含表单、属性查询、重试、66 条记录及认证编辑的全过程请求峰值 1,954,698 B。最终请求、子额度和父预留均归零，其他应用分项仍有 1,146,880 B。

计量预热了既有字体/画布/PTY等，排除分配器内部、C/OS、实际栈/RSS；合成退出视图只测绘制组件，真实失败/明确退出由独立回环证明。不能把这些数字称为全进程内存上限或原生事件到呈现延迟，也没有新增公平吞吐或长测结论。
