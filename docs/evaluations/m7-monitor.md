# 本地状态监控：依赖成本与采样开销（M7 F10）

右栏“监控”页的本地 CPU / 内存 / 磁盘读数由 `sysinfo` 提供，采样在后台任务线程里执行。本文记录依赖选择、实测成本，以及新增的线程、子进程、缓存与数据持有关系，供资源与性能审查。

## 依赖选择

| 候选 | 结论 |
| --- | --- |
| `sysinfo` 0.38.4（采用） | 固定版本 `=0.38.4`，`default-features = false`，只开 `system`、`disk`；`rust-version = 1.88` 与项目 MSRV 一致；Linux/macOS/Windows 一套代码，不需要自己写 `/proc` 解析 |
| 手写 `/proc`、`sysctl`、`GetSystemTimes` | 平台代码量最大，Windows 侧要自己拼 PDH/NT API，且没有现成测试；收益只是省一个依赖 |
| `procfs` | 只覆盖 Linux，与“三平台一套适配”目标冲突 |
| `heim` | 长期无维护，依赖树比 `sysinfo` 更大 |

`sysinfo` 只出现在 `src/monitor/mod.rs` 的 `system` 子模块里，上层拿到的是 `Raw`/`Sample` 这些纯数据类型；换成别的实现只需改这一个文件。

特性裁剪的收益：默认特性会额外拉 `network`、`user`、`component` 三块（Linux 上还有 `linux-netdevs` 相关代码），本项目只用 `System` 与 `Disks`，因此关掉默认特性只开 `system` + `disk`。依赖树因此只有 `libc`、`memchr`、`sysinfo` 三个 crate，`Cargo.lock` 无其他新增。

## 原型阶段测量（集成前，`/tmp/monproto`）

一次性的独立原型，用于确认“1 Hz 采样能不能放在任务线程里、磁盘要不要单独降频”：

| 项目 | 第 1 次 | 第 2 次 |
| --- | --- | --- |
| 冷启动（新建 `System` + `Disks` + 首轮全量刷新） | 161.6 µs | 172.7 µs |
| `refresh_cpu_usage` 中位 / 最大 | 0.3 / 50.7 µs | 0.2 / 58.5 µs |
| `refresh_memory` 中位 / 最大 | 27.7 / 81.2 µs | 24.5 / 68.6 µs |
| `Disks::refresh` 中位 / 最大 | 534.4 / 765.6 µs | 538.0 / 1027.1 µs |
| RSS（空进程 → 加 `System` → 加 `Disks`） | 2100 → 2288 → 2340 KiB | 同量级 |

结论：CPU+内存一轮几十微秒，1 Hz 完全放得下；磁盘一轮半毫秒，比前两者贵一个数量级，因此单独用 `disk-seconds`（默认 10 s）降频。RSS 增量约 240 KiB，据此把面板的固定预留定为 `RESERVED = 256 KiB`。

## 集成后实测（本机 Linux x86_64）

复现命令（`#[ignore]` 的真实采样成本测试，会读 `/proc`，不进常规测试）：

```
cargo test monitor_sample_cost -- --ignored --nocapture
```

本机结果（`mem_total` 8.33 GB，4 核）：

| 场景 | n | 中位 | p95 | 最大 |
| --- | --- | --- | --- | --- |
| 冷启动（新采样器 + 含磁盘的首轮） | 5 | 865.8 µs | 870.3 µs | 954.4 µs |
| 常规一轮（CPU + 内存，不刷磁盘） | 180 | 56.4 µs | 68.2 µs | 77.7 µs |
| 含磁盘的一轮 | 20 | 847.4 µs | 854.7 µs | 873.1 µs |

折算到占用：常规一轮 56 µs/s ≈ 单核 0.006%；磁盘 847 µs / 10 s ≈ 0.008%。冷启动 866 µs 只在打开面板或从暂停恢复时付一次（采样器在任务线程内惰性创建并长期复用，见下）。这些数字比原型高（冷启动 161 → 866 µs），差异来自集成版同时取内存/磁盘/挂载点标签，以及本机当时负载不同；量级结论不变。

## 线程、子进程、缓存与数据持有

| 项目 | 数量与生命周期 |
| --- | --- |
| 操作系统线程 | 每个打开的面板一个 `LatestTask` 工作线程（命名 `monitor`），由现有任务池准入（`LatestSlot` + 全局 64 线程上限）。采样器在该线程内惰性创建，随线程一起回收；暂停、切页、关栏或退出应用即释放。`sysinfo` 自身不建线程。 |
| 子进程 | 无。本地读数全部走系统调用。 |
| 缓存 | 只有一个定长历史环形队列（`VecDeque`，容量在创建时确定，运行期不扩容）：容量 = `history-seconds / interval`，上限 `MAX_SAMPLES = 900`。默认 300 点 × 64 B ≈ 19 KiB，最坏 900 点 ≈ 58 KiB。没有磁盘缓存，也不跨会话共享。 |
| 额度 | 打开面板时按 `Kind::Monitor` 申请 `RESERVED + 历史字节`（默认约 275 KiB），关闭时归还；额度不足即显示“监控额度不足，已停止采样”，不启动线程。 |
| 数据持有 | `Panel` 持有额度票据、历史、任务句柄与最近错误；`Workspace` 持有 `Panel`；线程内持有采样器（`Box<dyn Sampling>`）。回包只带 `Sample`（`Copy`）与挂载点字符串，跨线程不共享可变状态。 |

采样器在任务线程里只创建一次（`Option<Box<dyn Sampling>>` 存在闭包里），所以每次采样不会重复付冷启动成本；面板关闭后线程结束，采样器随之释放，不会留下后台轮询。

## 未测量的部分

- macOS / Windows 的采样成本未测（本机只有 Linux）；`sysinfo` 在这两个平台的依赖（`windows`、`objc2` 系列）编译时间也未计入。
- 磁盘读数只取“非只读、最外层挂载中总量最大”的一个卷，多卷场景的显示与切换成本未测。
- 网络文件系统、容器内 `/proc` 受限环境下的行为未测。
