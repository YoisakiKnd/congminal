# Git 请求元数据与本地网络读取边界（2026-10-29）

本轮继续用户已授权的内存边界与性能工作。基于上一批七项修复后的未提交源码，不新增运行依赖，不提交、推送或发布。

## 实现与所有权

- `Limits` 的 git/ssh 程序路径、host/user/identity/jump 在复制前统一计量，每个动态字段最多 16 KiB；每个请求分别持有 `Tracked<Limits>`，不依赖目录票据的析构顺序。缓存版本最多 128 字节并独立持票，提交 hash 独立持票。版本探测也按 UTF-8 边界执行字节上限。
- GUI 将路径、分支、提交信息作为借用的 `WriteSource` 传入，额度获批后才复制为任务拥有的负载。历史、分支查询也借用已有目录与 hash。写请求限制单次 48 条路径、路径负载 64 KiB、单路径 16 KiB、提交信息 4096 字节、分支名 255 字节；当前界面单条操作不受这些批量上限影响。根目录先校验再复制。网络超时直接设置在已计费配置中，去掉执行时的第二份配置复制；已有远程只读、二次确认、literal pathspec 和 shell 引用规则保持有效。
- 错误分类在原始 stderr 字节上匹配，不先构造整段 lossy String。摘要先在栈上解码，按 200 **字节** 截断且保持 UTF-8 完整，控制字符转为空格，非法字节显示替代字符。固定大小的共享错误块先准入再分配，Clone 只增加引用计数；费用跟随最后副本。所有强引用都通过 `Arc::into_inner` 析构，使最后一个拥有者先释放 Arc 内存块、再归还移出的票据，避免块仍存在时提前归还费用。未暴露 Weak 引用。
- 写操作的临时参数向量、解码与摘要重叠另有 32 KiB 工作预留。已有请求/回复预留仍覆盖其有界摘要；**GUI 提示、视图文本和面板常驻配置的完整准入仍待后续接入**，不能由这里推导完整界面堆上界。
- Linux `/proc/net/dev` 改为固定 64 KiB 栈缓冲加一个溢出检测字节；短读/Interrupted 重试，超长、读失败或非 UTF-8 返回未知，不显示被截断输入的部分总量。无需缓冲扩容或新增线程。测试在 macOS 上直接覆盖相同读取函数；Linux 真机调用仍待验收。64 KiB 栈占用属于已有工作线程栈预留，不等于零内存成本。

## 性能

同一台 macOS arm64、冻结修改前源码与当前源码，System 分配器；每项两轮预热、五组交替配对。不用分配计量器计时。

最终构造微基准（五种请求合计）1.229 → 1.349 微秒，配对中位数 **+9.60%**，绝对增加约 **0.120 微秒**；有界网络解析 6.034 → 6.274 微秒，配对中位数 **+4.46%**，绝对增加约 **0.240 微秒**。这是明确的边界检查/准入成本，本轮接受；不宣称所有路径都更快。ASCII 错误构造及一次副本 0.201 → 0.166 微秒，配对中位数 **−17.0%**。

总体 Git 查询 57.966 → 58.516 毫秒，配对中位数 **+0.948%**；五组分别 −0.763%、−2.074%、+5.465%、+2.651%、+0.948%，不据此宣称严格零回退或 UI 尾延迟达标。监控 cold −0.227%、无磁盘采样 0%、带磁盘采样 −0.758%；动态进程样本 −4.302%，进程集合随时间变化，不能当成同一 PID 集合的提速。Git 整个测试命令的 RSS 差中位数 −49152 字节，CPU 差中位数 0 秒（计时分辨率 0.01 秒）；均非应用稳态或 RSS 上界证据。

总体 Git 基准比较同样 500 个修改文件并核对结果指纹；查询计时从请求构造后开始，因此另有构造/复制/释放专用微基准覆盖五种请求、同样 ASCII 错误及一次副本、同样完整 64 KiB 网络输入。微基准不模拟 UI 绘制或实际网络/磁盘等待。非法 UTF-8 错误改按字节限制，语义由单测覆盖，不拿不同输出长度宣称同负载性能提升。
