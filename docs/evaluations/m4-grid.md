# M4 网格与缩放准入评估

日期：2026-10-21。代码位于当前工作区，未提交、未发布；基线是本轮开始时已经包含共享账本首批的本地快照 `/tmp/congminal-grid-baseline-01a158a4`，不是远端 alpha.5。没有增加 Cargo 依赖、常驻线程或周期采样。最终源码/二进制指纹和验收状态见 [构建记录](m4-grid-build.json)。

## 实现与正确性

主/备用网格使用容量预留，缩放另持有完整目标预留和临时工作集票据。先完成准入和画布准备，才移动历史、改变光标/选区并发送 PTY 尺寸。工作区先预检所有可见窗格；取消或拒绝时所有临时票据自动归还。已准入的增长直接合并票据后收缩，避免提交中途被其他线程抢占。RIS 复用两套网格。具体计费公式和未覆盖范围见 [执行说明](../execution-m4-memory.md)。

原先缩放可保留过大的行索引，从历史拉回行也会先 insert 后 pop 而触发扩容；现在收缩行索引/过宽 cell，先移除屏幕尾行再插入。历史记录 cell 容量的保守下界，只有在确实需要增长时才逐行汇总容量，避免把额外归约计算叠在每次硬行检查上。下界允许因淘汰而偏低，不能偏高；接收行时更新，清空/取走时重建。

Debug 和 release 各 **233 项通过、11 项手动基准忽略**；本机、Linux x86_64 GNU、Windows x86_64 GNU 的 all-targets Clippy `-D warnings`、格式及差异空白检查通过。交叉检查不代表 Windows/Linux 真机运行。

新增验证覆盖初始网格准入/销毁、旧新网格峰值、临时工作集拒绝与取消、额度被其他任务占满后的提交、滚动/备用屏/RIS、容量下界更新、多个窗格预检失败，以及 128 MiB 账本内 64 MiB 硬行历史与另 20 MiB 预留同时存在的反复缩放。1800 组重排案例同时对照普通调用、携带预检结果的调用和参考算法。真实 PTY 测试确认网格拒绝前不会执行新 Shell；缩放被拒绝后原选区仍在，`stty size` 仍为 `24 80`，释放额度重试后为 `12 40`。

## 分配峰值探针

在独立源码副本中注入仅供测试的 `GlobalAlloc/System` 包装；生产源码不变。线程局部记录 Rust 请求的存活字节，realloc 保守计旧/新缓冲重叠。下表是相对缩放前的额外峰值，预留还可能临时覆盖原先未计入的历史输入，因此不能把预留与该差额直接视作利用率，也不能与 RSS 等同。

| 场景 | 实测额外峰值 MiB | 已准入额外额度 MiB |
|---|---:|---:|
| 64 MiB 硬行缩窄 | 1.26 | 71.76 |
| 64 MiB 硬行扩宽 | 1.27 | 72.55 |
| 64 MiB 长软行 | 103.30 | 401.15 |
| 窄历史扩到 4096 列 | 63.62 | 68.37 |
| 2048 行先扩到 4096 列、最终缩到 1 行 | 160.07 | 321.14 |
| 仅变矮且触发历史索引增长 | 2.00 | 6.02 |

九个场景均未超过准入模型，结束后网格实际容量不超过持有的预留，临时票据归零；另含宽字符缩到 1 列、仅改高度和备用屏。完整样本、注入代码及生产源码校验值见 [原始记录](m4-grid-allocation-probe.json)。这些案例不是对所有未来分配路径的形式证明；分配器块大小、系统库和 RSS 不在该探针内。

## 性能对照

所有对照使用相同 release 配置，交替先后顺序且不与其他测试同时测量。记录每轮值后取轮次中位数；不删除冷启动或慢样本。事件入口只测处理/入队，不能当作端到端输入延迟。

| 场景/组别 | 基线 | 当前 |
|---|---:|---:|
| VT，五对全套基准 MiB/s | 66.3 | 64.9 |
| 3616×2416 整帧，全套 ms | 6.412 | 6.655 |
| 仅改一行，全套 ms | 0.645 | 0.680 |
| 同尺寸整帧，独立十六对 ms | 6.697 | 6.851 |
| 仅改一行，独立十六对 ms | 0.669 | 0.670 |
| 四窗格 1600×900 整帧 µs | 1224 | 1222 |
| 四窗格仅改一行 µs | 50 | 50 |
| 事件入口 P95 / P99 ns | 208 / 3083 | 250 / 2500 |
| 工作区入口 P95 / P99 ns | 292 / 2750 | 250 / 2916 |

VT 约 -2.1%，整帧全套约 +3.8%；全套单行约 +5.5%，追加独立十六对后整帧约 +2.3%、单行约 +0.2%，没有据第一组直接断言稳定回退。五对原始值及二进制体积见 [全套数据](m4-grid-bench.json)，追加绘制数据见 [独立绘制](m4-grid-render-isolated.json)。同一 release 配置（debug=1）下二进制为 1,849,160 → 1,870,808 字节，增加 21,648 字节，约 1.17%。

最初逐历史行串联容量求和时，扩大样本后的硬行重排 P95 为 1.105 → 1.195 ms，约 +8.1%，见 [优化前每轮 200 次数据](m4-grid-reflow-200-pre-floor.json)。引入容量下界后，最新五对、每轮 200 次的 P50 为 0.891 → 0.870 ms、P95 为 1.152 → 1.118 ms、200 次总耗时为 181 → 177 ms，见 [优化后数据](m4-grid-reflow-200.json)。测试副本只调整原有基准的迭代次数和分位索引，生产源码不变。全套中每轮仅 20 次的 P95 仍为 1.145 → 1.265 ms；不同组波动明显，不能据某一组推断所有重排形态均无回退。长软行的低延迟仍需流式/分片实现。

## 本机 GUI 与压力

六对 GUI 自然退出均为 0；启动定义为启动进程到 Shell 写标记，不是首帧。最终组启动中位数为 223.287 → 262.574 ms，约 +17.6%；此前同轮实现的组为 236.098 → 242.999 ms，约 +2.9%。**启动成本尚未通过 5% 验收**，需固定环境并增加分阶段计时，不能用前后两组不同的基线挑选结论。原始数据见 [最终 GUI 记录](m4-grid-runtime.json) 和 [此前记录](m4-grid-runtime-pre-floor.json)。

最终组 RSS 中位数为 115,621,888 → 115,777,536 字节，约 +0.148 MiB；线程中位数均为 14（基线有一个 15 线程样本）。空闲单核 CPU 为 0.01157% → 0.01130%，这一量级不解释为可靠改善。每次仅有一个测试 sleep 子进程，子进程 CPU 中位数为 0；没有增加采样线程。

最终 60 秒压力在源码副本中扩大尺寸跨度到四个字符宽度，每次断言字符列数变化；原先 1190↔1200 像素变化可能没有跨越字符边界，不能单凭像素变化证明重排覆盖。最终完成 250,319 次循环、3,737 次实际重排，期间维持四个真实 PTY，并反复创建/关闭第五个会话。

- 账本峰值 461,821,824 字节（约 440.43 MiB），未超过默认 512 MiB；拒绝数为 0。
- 五秒间隔的操作后快照中，网格预留约 342.7–353.3 KiB、实际容量约 166.9–167.0 KiB，重排临时预留均为 0；销毁后所有额度及映射数量归零。
- RSS 峰值 264,519,680 字节（约 252.27 MiB）；20 秒以后仍由约 242.91 增至 252.27 MiB，**不能称为已达到稳定平台或无泄漏证明**。输入历史/网格容量受限且票据已归还，分配器保留/碎片等因素仍需更长采样或分配跟踪区分。
- 最长一次布局/重排为 **45.773 ms**，不满足低延迟交互预期。入口处理/PTY poll 的短计时不包含这段 UI 阻塞，不能用它们宣称缩放时无卡顿；流式/分片重排调整为后续首项。
- 活动阶段采样为 14 线程；初始化/退出采样包含 1 线程。只测测试主进程 RSS，没有同步采样四个 Shell/外部程序的 RSS。

[完整压力数据](m4-grid-stress.json) 包含生产源码校验、测试副本校验、原始日志、1 Hz RSS 和五秒账本快照。可复现工具为 [tools/check_grid_pressure.py](../../tools/check_grid_pressure.py)：`python3 tools/check_grid_pressure.py --seconds 60 --output /tmp/congminal-grid-pressure.json`。工具只修改临时副本中的压力用例；生成用例与上述 60 秒测试完全一致，不在产品中引入采样线程；新增工具另经 [6 秒完整运行检查](m4-grid-pressure-tool-smoke.json) 通过。30 分钟可用 `--seconds 1800`，本轮未执行。

## 未验收项

持久历史仍沿用工作区 64 MiB 分项池，未成为完整共享账本成员；字体解析/解码、缓存桶、其他元数据和平台临时缓冲仍待接入。保守软行预留可能拒绝本可用流式算法完成的缩放。分配器 OOM 的可恢复性、三平台原生输入法/窗口交互、Windows/Linux 真机、启动成本、30 分钟长测与重排期间的端到端交互延迟仍未验收。当前额度不能称作完整受管堆或进程 RSS 上限。
