# 后台上传源准备与版本绑定

状态：测试候选已接“本地源只读元数据任务 → 原票据/配置匹配 → 带源版本的不可变审阅 → 开始时再核对”。macOS隔离回环已通过同大小替换源文件的拒绝场景。一般用户的源选择/目标输入控件仍未接入，默认SFTP入口关闭，完整M6不勾选。没有新增Cargo包、线程或检查辅助进程。

## 元数据与实际传输

[Service](../../src/sftp/service.rs)新增InspectLocal/LocalSource任务结果，复用原2工作器/64等待/16MiB池。UI方法只校验和捕获受管路径/身份；请求在开始工作前不访问文件。这个Action不创建Front/私有端点/helper/SSH，也不读取SSH配置文件；取消仍使用同一Ticket。检查不占用额外队列、结果容器或线程。

[本地源](../../src/sftp/local_transfer.rs)的inspect只调用不跟随最终符号链接的symlink_metadata，要求普通文件，返回设备/节点、长度及纳秒mtime/ctime组成的固定Stamp。先预留32KiB工作空间覆盖路径转换/系统接口的Rust临时请求；不打开数据文件、不读取内容，也不占用进程创建互斥锁。可读权限直到实际传输打开源时才确定，不把元数据成功当作数据可读保证。

UploadChecked把所选Stamp带过队列和审阅；上传开始打开源后，在生成远端临时名称/写数据之前核对完整版本，变化返回Changed。已有传输期间/RENAME前的源核对、长度检查、原子提交和独立清理确认继续保留。它是可观察文件身份/元数据的核对，不是内容哈希、文件系统锁或不可变内容快照；后续变化及不可靠的文件系统时间语义不能据此作绝对保证。底层旧Upload原语仍保留，新的用户源准备路径使用UploadChecked。

## 一个准备槽与认证优先

[Workspace桥接](../../src/workspace/transfer_prepare.rs)只保留一份准备：原Ticket、会话/代次、Profiles快照/索引、原名本地/远端路径、固定结果/错误状态。满记录表或满队列先拒绝，已有准备未结束时不再接第二份。结果只有匹配原Ticket/绑定/选中会话才能生成审阅；取消、切换配置或窗格后的迟到结果丢弃，不给后来目标套用旧版本。

等待界面只读，普通文字/预编辑不会进入终端。Enter/Esc取消等待，窗口关闭仍走共享结束门禁。失败或审阅准入不足保持固定错误状态，等待明确取消/重新选择，不在每tick重试；准备自身没有定时轮询，完成由既有执行器唤醒。

准备排队时允许已有任务认证取得前台，等待界面让出绘制和事件；否则两个工作器都等待认证时，后面的检查无法运行。认证仍只接有来源的输入，未归属的Esc不能绕过原保护；认证的取消不顺带取消准备槽。已有认证未关闭时，准备结果保留，稍后再打开审阅。

文件系统调用本身可能阻塞工作器；取消在调用前/后检查，不能把网络超时当作元数据查询的硬截止。仍须等工作器/回收器真正结束才确认退出，未完成不提前退父额度。失败退出处置及完整文件系统/平台长测仍待完成。
