# M4 Shell 记录、工作目录与 UI 批量复制

2026-10-25。命令历史、完成事件和 OSC 7 工作目录接入 `shell-reserved`；新增分类而不提高总额度。无新增包、线程或运行时子进程。本页只覆盖这些缓冲及相邻 UI 回归，输出复制/剪贴板、解析器自身、侧栏/平台文字和完整元数据仍待。

## 准入和行为

Shell 捕获创建池，两张零字节票据分别持有命令和事件队列。首次各取 4 槽，之后按二次幂增长到原有 1024/64 上限；扩容前预留旧、新容量重叠，完成后收紧到实际容量。满额后先轮换再写入，不逐事件更新预算。失效位置、历史淘汰和事件消费保留容量继续收费，供后续复用；最后拥有者销毁后归还。

命令历史和事件各自准入：历史增长拒绝时，已有事件槽仍可交付完成状态。分别统计未保留命令与丢弃事件，状态栏和资源诊断可见。ID 在执行开始时单调消费，拒绝、重复 D 标记和恢复额度都不重放旧完成事件，不从缺失元数据猜测成功。原有未知退出码、重排/备用屏幕/回写失效规则保留。

OSC 7 仍最多 3072 UTF-8 B。取消 `Vec<&str>`、join 和解码 Vec，使用两个有界 3072 B 栈块拼接/验证；栈不包含在本页堆请求数字内。保留分号、远程 host、一次百分号解码、控制字符/非法 UTF-8 拒绝等语义。验证后先准入 host/path，再分配两段精确容量，字段只提供借用访问。替换时旧目录仍持票；额度不足清除旧目录，明确显示“工作目录额度不足”，不继续显示过期路径。畸形输入也清除目录，但不冒称额度拒绝。

## 实际分配

[当前工具链](m4-shell-resources-allocation.json)和 [Rust 1.88](m4-shell-resources-allocation-msrv.json)采用相同全线程 epoch Rust 请求探针，保守包含 realloc 旧、新请求重叠。池、Scope/锁及输入 URI 在区间外建立；不包含计量器附加头、分配器/C/OS、实际栈和整个应用初始元数据。

| 阶段 | 存活请求 = Shell 记录/目录额度 |
|---|---:|
| 首次命令完成，各 4 槽 | 480 B |
| 命令 1024 槽、事件 64 槽 | 92160 B |
| 再 10000 次完成/消费 | 92160 B，零新增请求/扩容 |
| 最大 URI 的目录 | 95225 B |
| 替换目录、独立 Shell 拒绝 | 95225 B，拒绝零新增 |
| 独立 Shell 恢复并接收新 ID | 95705 B |
| 清除位置/目录，保留记录容量 | 92640 B |
| 所有 Shell 销毁 | 0 B |

本机构造中 Command/Completion 为 88/32 B。记录增长的请求峰值 **137216 B**，与当时预算峰值相同；所有 2～1024 个命令的二次幂检查点均被覆盖。满额前累计 14 次请求，其中 12 次扩容（扩容也计入请求数）。最大目录增加 3065 B；替换旧新目录同时存活也在额度内。后面的 1 MiB 预算峰值包括人为填满的压力票据，不能解释成实际堆峰值。最后请求与额度归零不承诺分配器 RSS 立即回落。

## 成本与 UI 回退处理

[同负载对照](m4-shell-resources-cost.json)对前后冻结源码注入同一生产 System 分配器夹具，两次预热后五组交替。每轮 5000 次首次 ABCD 生命周期（Default/drop 在计时外）、200 批各 1000 次热完成/事件消费、200 批各 1000 次真实 OSC 133 解析/输出/淘汰/消费，以及 5000 次交替目录更新。指纹比较 ID、状态、位置、目录及事件丢弃，排除非确定的 elapsed，前后一致。

| 场景 | 五组配对耗时中位变化 | 范围 |
|---|---:|---:|
| 首次 ABCD 生命周期 | +28.37% | +25.73% ～ +30.71% |
| 已有容量的完成/消费 | +0.24% | -0.48% ～ +1.19% |
| 真实 OSC 133 解析及输出 | -4.16% | -5.34% ～ -3.29% |
| OSC 7 目录更新 | +8.34% | +4.94% ～ +13.23% |

批次折算中位首次约 **62→80 ns**，热完成约 **42 ns**，目录约 **190→205 ns**，含计时/夹具成本。前置计费增加首次及目录更新成本，首次和最后保留容量与旧实现相同；目录更新不是逐字节热路径，不把约十五纳秒增量隐藏为零成本。整进程 RSS 配对中位 **+128 KiB**（+112～+160 KiB），CPU 中位 −0.01s（五组均为 −0.01s，分辨率 0.01s）；这些包含构造、验证和析构，不能逐字节归因于 Shell。

初次 UI 对照发现所有模式更新约回退 27%。单独禁止批量入口或整个更新函数内联未解决，原始结果保留。最终让 Search 借用实际 VecDeque 的两个切片，UI 按可信长度一次准入、分段复制；通用不可信迭代器保护保留在测试供给入口。没有减少匹配数量、跳过装饰或取消额度检查。新增常规回归覆盖队列环绕的逻辑顺序、当前/链接装饰、重复更新清除特殊尾项、空结果保留已计费容量，以及拒绝清除旧状态。

[最终 UI 成本](m4-shell-resources-ui-cost.json)：相同真实 PTY/app 的五模式负载，5000 次更新和 500 次强制完整软件绘制；五组更新配对中位 **+0.40%**（−0.43～+1.21%），更新加完整绘制 **+1.20%**（+0.89～+1.51%），像素指纹 **6821514814623131185** 一致。整进程 RSS 中位 +32 KiB（−144～+80 KiB），CPU 中位接近 0s（范围约 0～+0.01s，分辨率 0.01s）。不是原生输入到显示或平台长测结论。
