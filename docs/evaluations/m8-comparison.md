# 同负载横向对照（M8：吞吐、输入响应、重绘耗时、RSS、后台开销）

路线图 M8 要求「记录终端吞吐、输入响应、重绘耗时、RSS 和后台开销的同负载对照」。本文件把这几项放在**同一台机器、同一构建配置、同一组固定负载**下并列，方便横向比较；每行都写了复现命令，数值分两类标注：

- **本机复测**：本文档编写时在这台机器上重新跑过（`rustc 1.99.0`、`--release`、4 核 / 7.7 GiB、Linux 6.8）。
- **引用记录**：需要隔离环境或长时间运行的项，直接引用已有记录并注明文件。

## 1. 固定负载定义

| 编号 | 负载 | 定义 |

| L6 | 后台采样 | 监控页一轮采样（不含磁盘 / 含磁盘 / 含进程表），1 Hz 节奏 |

## 3. 怎么读这张表

- **输入派发（纳秒级）远低于一帧预算（16.7 ms）**：瓶颈不在事件派发，而在绘制与 PTY 往返。L2 只计到「写入 PTY 队列」，不含内核回显与原生窗口呈现。
- **分片重绘是 52 µs，全量是 1 670 µs**：日常输入走分片路径，只有布局变化（开关侧栏、切页签、改窗口）才付全量代价。四窗格的画布合计 11.3 MB，这是 `render` 侧的主要内存项。
- **搜索与重排都是「单片几百微秒、总数毫秒级」**：两者都按片让出，不阻塞一帧；64 MiB 历史的搜索总耗时 54 ms 由 202 片构成，单片 p95 283 µs。
- **后台采样的三个档位差一个数量级**：无磁盘 62 µs、含磁盘 394 µs、含进程表 13.3 ms。进程表最贵，因此按 5 s 而不是 1 s 刷新（`[monitor] processes` 可关）。
- **长时运行的增量主要是终端回滚**，不是泄漏：见 [M8 长测](m8-soak.md) 的解释段。

## 4. 缺口（未覆盖的横向对照）

- **没有原生窗口的输入到呈现延迟**：L2 与 L5 都在软件绘制层，不含 X11/Win32/Cocoa 的合成与垂直同步。真实窗口延迟需要真机与抓帧工具。
- **没有与其它终端的横向对比**（alacritty/kitty/wezterm 同负载）：本文件只做「本项目不同负载之间」的对照。
- **没有 SFTP / SSH 吞吐的同负载对照**：`docs/evaluations/m6-sftp*.json` 有各自成本，但没汇总成表；且需要隔离 sshd。
- **Windows / macOS 没有对应数值**：只有 Linux 真机与两个交叉编译目标。
- **L7 不在 CI**：`ci/soak-x11.sh` 是手动/按需运行的脚本。
