# M4：PTY、配置监视与布局线程的统一准入和回收

2026-10-26，本机 macOS arm64。此阶段把其余常驻应用工作线程接入已交付的固定运行时；完整 M4–M8、终端兼容和三平台/长测目标仍执行中。没有新增 Rust 包、应用子进程或回收线程，没有提高生产预算、64 个工作记录或 8 窗格上限。SFTP 仍使用自己的固定 2 工作器、1 回收线程和原 16 MiB 池，输入额度继续保护 9 MiB IO 余量。

## 实现与边界

PTY 的 reader/writer/waiter 在创建文件描述符、fork/ConPTY 和 shell 前预留三个记录、工作槽及资源费；早期配额失败不执行新 shell。闭包确定后缩减预留，原生启动失败自动回滚。工作器统一进入创建者的 Budget 上下文，配置 watcher 和布局 Store 也使用该机制。布局在读取文件之前准入；watcher 启动失败进入可见配置警告，提前取消不读取配置元数据。布局动态数据、普通取消对象和配置内容的完整分配账本仍待完成。

每个工作器的请求栈 2 MiB 与堆余量分票。回收器在原生 join 完成后才归还栈和工作槽；函数返回或 Drop 不代表 TLS 已结束。写线程控制对象只保留 Thread/取消 IO 所需的元数据费用，因此线程结束后 UI 仍持有控制对象时，堆票据继续保留，栈费已可归还。最后控制引用释放后才退还堆票据。

Windows 在发布记录前 DuplicateHandle，控制对象持有独立 OwnedHandle，避免原 JoinHandle 被回收后的失效/复用句柄。复制失败时仍先把实际线程交给回收器，再关闭写队列使它退出；真实启动后控制发布失败的注入回归已覆盖。Windows 启动顺序为 reader、waiter、writer，关闭时保留输出排空路径。本机只做 Windows 静态检查，尚未证明 ConPTY 原生取消和关闭时延。

所有这些工作器与 LatestTask 共用同一个全局 64 记录运行时；每 Budget 的工作槽也最多 64。两者都可能提前拒绝，不保证每个预算都可同时占满。LatestTask 的独立 32 核心上限不变。回收确认失败仍持票并关闭接收；不启动替代回收器。原生系统调用/文件系统卡住时只保留明确所有权，不能据此宣称可中断或有硬关闭期限。根退出的 250 ms 仍为软检查预算。

## 请求分配与测试隔离

当前 Budget/Stats 大小分别为 368/320 B，根对象自留公式仍为 496 B；此处类型探针不重复宣称根对象的冷分配实测。运行时固定注册表费用从 5272 增至 5784 B；工作器堆模型为 64 KiB + 两份闭包大小 + 256 B，闭包最多 16 KiB。该模型不覆盖捕获指针后任意大小的泛型负载，也不是实际栈、malloc、系统内存或 RSS 上限。

两工具链的全线程 epoch 请求探针均扣除请求栈后核对堆费用，覆盖原生 TLS 阻塞、先退出后发布、额度拒绝、最大闭包、仍持控制对象的原生线程退出，以及最后释放。LatestTask 核心在 TLS 之前销毁时，仍保留 2163008 B 和 1 工作槽。控制对象保留阶段原生工作槽为零、费用 71576 B；控制对象释放后仅余 5784 B 固定注册表，最后私有运行时请求/费用均归零。内核栈提交、分配器和 OS 内部费用未计量。

全套并行 Rust 测试最初出现不同测试用例各自模拟整应用、合计超过单生产进程 64 槽的问题，失败记录保留为 `m4-system-threads-build-before-test-process-isolation.json`。现仅在 cfg(test) 对独立会话用例隔离，同用例仍可创建全部 8 会话和原有并发，不提高生产上限，也没有串行运行整个测试套件。

新的全工作区探针第一次超时，线程/账本已经为零，但尚有 48 B 请求。固定表原生栈诊断确定它来自 cfg(test) 隔离门的 Condvar 第一次 notify（会话 Drop），不是遗留工作线程。现在在第一个 Session 构造时初始化该测试设施，先于工作区 epoch；失败、原生符号栈和定位工具保留于 `m4-system-threads-workspace-retained.json`。追加验收日志又曾在计量结束前触发 64 B 测试输出分配，该失败也保留为 `...-workspace-before-final-log.json`；日志已移到停止计量后。没有忽略或减去最终活跃请求，没有放宽零值断言。

当前全工作区探针最大路径、512 项真实本地选择、源检查、重试、迟到保护输入和退出完成后，请求 live、SFTP 父票据、原 Session 根账本、managed_workers 及运行时 active 记录均为零。六类预热直接视图各 200 次零新增分配；真实本地 PTY 已预热，SFTP 没有连接实际远端。另有软件前端真实回环认证/目录/上传下载/确认回收验收，不能代替原生窗口。
