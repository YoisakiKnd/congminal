# SFTP 显式重试与重新审阅

2026-10-24。本轮补齐任务列表中的手动重试候选，仍为 Unix 测试入口，未包含在已交付的 Alpha.6 中。未引入新包、增加工作器或扩大 16 MiB SFTP 子池；完整 M6 与全计划继续执行。

## 实际行为

右栏任务列表提供明确的“重试”按钮，只有已结束、清理确认且尚未发布或明确被远端拒绝的失败/取消/未开始任务可用。已发布、提交不确定、回收未知和中断记录不允许直接重试，应先检查目标。操作还核对原会话、连接代次和配置快照，不迁移到当前的另一台主机；旧票据仍保留，重试创建新票据。

上传先在原工作池重新读取本地源的类型、大小和版本；下载先通过独立认证执行 LSTAT，取得当前普通文件的大小/mtime。两者都重新进入完整主机/源/目标审阅，覆盖同意恢复为关闭，只有重新明确确认后才创建文件任务。旧覆盖同意、传输进度、认证输入不重放；不删除旧部分文件，也不复用旧临时文件。

源准备仍限单槽，重复点击、满任务记录、预算不足或关闭状态会拒绝。清理未确认的源查询不能打开审阅；失败状态保持到用户取消，旧结果和重复完成消息不能解除错误或替换新目标。上传/下载与现有路径表单共用源准备、认证和任务机制，没有额外轮询或新线程。

## 验证

- [构建与回归](m6-sftp-manual-retry-build.json)：默认 511 项通过、36 项专用测试忽略；原生后端 feature all-targets Clippy、Linux/Windows all-targets 静态检查通过；Rust 1.88 工作区 28 项通过、2 项专用测试忽略。格式检查通过。跨编译不代表真机运行。
- [真实回环](m6-sftp-manual-retry-real.json)：16 类 Workspace 场景全部通过，测试生成隔离密钥/配置，没有使用用户 SSH 凭据。新增双向重试先传输各 32 MiB 并因目标已存在而失败；保留原目标/旧记录，修改源为新内容及新长度，再实际点击“重试”。检查完成前目标不变，默认不覆盖，重新明确覆盖后逐字节核对新目标。上传重试有 1 次文件认证，下载重试有 1 次源查询认证加 1 次文件认证；新旧任务各自只发一次对应通知。结束无存活测试子进程、SFTP 父额度归零。
- 新单测覆盖原字节目标、原会话失效、重复准备、已发布/不确定/回收未知门禁，以及错误/迟到查询结果不得重新打开审阅。macOS 文件系统拒绝非法 UTF-8 文件名，本机使用中文本地路径与含非法 UTF-8 的受管远端路径；Linux 非 UTF-8 本地路径分支仅经过静态检查，不能声称已运行验证。

## 内存与成本

[全线程请求分配探针](m6-sftp-manual-retry-allocation.json) 直接执行失败记录到重新读取 32 MiB 本地源元数据、默认不覆盖审阅，并保留旧记录；这段没有 SSH 或文件 payload 传输。审阅时存活请求 1,104,208 B、当时请求峰值 1,118,640 B，子账本用量 5,033,457 B，其中输入分类 8,376 B。200 次预热直接审阅绘制均无新增分配/扩容。

包含最大路径表单、属性查询错误、66 条固定文件记录、通知环和认证编辑的整个探针请求峰值 1,954,698 B；旧输入还存活时继续保留父预留，最后 Rust 请求、SFTP 子额度和父预留均归零。预热的字体/画布/PTY、分配器/C/OS/实际栈/RSS不计入请求测量；最终其他应用分项仍有 1,146,880 B，不能宣称整个程序占用为零或 RSS 受 16 MiB 限制。

重试会增加一次源元数据检查，下载重试另有一次独立连接/认证，不复用连接；这是明确的额外工作，不宣称无延迟影响。现有完整属性的普通下载不改变。此前连接/任务层成本保持历史适用范围，本轮没有新的公平吞吐、系统通知送达、原生输入到呈现或长测结论。[源码/工具/夹具与报告核对](m6-sftp-manual-retry-audit.json) 已对应当前工作树。
