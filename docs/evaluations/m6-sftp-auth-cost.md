# 认证 helper 的增量成本

候选是系统 OpenSSH、默认关闭的 Rust helper 和自写有界状态/进程/IPC 适配，没有新增 Cargo 包、加密实现或异步运行时。版本、源码、编译参数、可执行文件散列及完整样本见 [原始数据](m6-sftp-auth-cost.json)。当前只评为 Unix 测试候选；可见 UI、输入/IME、退出确认、Windows 安全端点和三平台/长测仍须完成，尚未进入默认运行路径。

## 同负载方法

同一 Rust 父状态/私有端点/有界独立流、模拟前端、OpenSSH 程序/配置、自建 sshd、生成的加密私钥、SFTP v3 客户端。比较返回固定公开假答案的最小 C 夹具和真实 Rust helper/IPC，两启动器均 exec SSH。C 夹具没有通用 UI、权限协议或真实凭据支持，不能作为产品后端；此对照只量化在同一父端设置之上的 IPC/helper 增量，不代表全部采用成本或成熟 GUI 工具的比较。

立即回答和等待 1 秒分别两个预热、五组交替。每例还列出 501 项目录，完成相同 32 MiB 上传/下载核对、64 KiB 顺序 ACK；关闭压缩和连接复用。前后空闲各 600 ms；等待区间取实际观察到的三进程重叠并裁去头尾各 100 ms，至少保留 500 ms。两模式的模拟前端均以 2 ms 轮询，CPU 包含测试框架和该轮询，不作为真实 GUI 的空闲结论。

## 结果

中位数（固定假答案夹具 / 有界 IPC）：

| 指标 | 固定夹具 | 有界 IPC |
| --- | ---: | ---: |
| 立即回答到 VERSION | 182.535 ms | 192.429 ms |
| 等待 1 秒后到 VERSION | 1212.809 ms | 1217.352 ms |
| 立即回答例上传 | 254.35 MiB/s | 254.21 MiB/s |
| 立即回答例下载 | 251.26 MiB/s | 253.68 MiB/s |
| 等待例上传 | 258.60 MiB/s | 256.41 MiB/s |
| 等待例下载 | 258.17 MiB/s | 257.72 MiB/s |
| 认证受管峰值 | 279048 B | 280253 B |
| 整体受管峰值 | 3430086 B | 3430086 B |

立即回答增加约 9.9 ms（约 5.4%），等待例约多 4.5 ms；这些是新增认证交接相对固定答案的成本，不是零成本，也不是输入到呈现的 P95/P99。五个样本不足以报告尾部百分位。首轮立即回答约多 21 ms，定位到答案取出后仍等下一轮 poll 才发送；现合并 Waiting→Send，仍最多四次有界写、没有增加连接槽或工作上限。[首轮数据](m6-sftp-auth-cost-initial.json) 保留。两轮系统状态并非完全可复现，不把全部变化解释为该改动的严格单因素收益。

各模式 32 MiB 数据均核对成功，上传/下载的中位吞吐变化均在 1% 内，差值不作加速承诺。等待组有一次基线上传明显更快，逐对比较的最差变化约 -7.8%，其余四对的上传变化约 -1% 至 +0.4%；不能称全部单次样本都满足 5%。现有样本未证明稳定退化，弱网/多任务/长测继续作为默认采用前门槛。既有无认证流另有 [五组普通路径回归](m6-sftp-auth-parent-adapter-bench.json)；不能把固定假答案夹具视为已有可用认证 UI，再据此声称整个产品只回退某一百分比。

等待区间总 CPU 中位约为单核 0.840%/0.855%，差约 0.015 个百分点，包含测试前端轮询；前后短空闲 CPU 中位均为 0。该结果未代替无任务/隐藏面板或长期空闲验收。等待时都是 3 个进程、合计 5 个线程：Rust 测试父端 3 线程、SSH 和 askpass 各 1 线程；父端额外线程来自测试前端/工作槽，IPC 本身未创建线程。立即回复的 C 夹具有时短到未被 5 ms 采样捕获，不能据采样中的 2 进程称它没有 askpass 进程。

等待时总 RSS 峰值中位为 14172160/14467072 B，约多 288 KiB；立即回答例为 13828096/14417920 B，短进程采样分辨率和缓存会影响差值。观察到的最高总 RSS 为固定 14237696 B、有界 14499840 B；不把这些当作硬 RSS 上限或全部应用成本。所有试次受管额度最终归零，采样未见已观察子进程残留。

本机 release helper 为 549032 B，固定 C 夹具 33840 B；Rust release 当前保留调试信息，二者都未剥离。测试父二进制约 5 MiB 包含测试框架/夹具，不是用户发布程序。C 编译器只用于评估夹具，不是用户运行依赖；未来打包需要带 Rust helper，并确认安装位置、权限和平台身份验证。

## 资源及接入结论

同轮发送后的分配探针仍有覆盖：Rust 请求峰值 165887 B、账本峰值 172119 B，结束均零；10000 次等待 tick 无分配/realloc。原来“sending”采样现在已释放发送 Secret，存活请求从 133075 B 降为 132052 B，证明本次路径没有为提速额外留答案副本。[当前分配记录](m6-sftp-auth-cost-allocation.json)。探针排除分配器、C/OS、RSS、线程栈和预初始化共享上下文，M4 完整内存准入继续待办。

相同探针在 Rust 1.88 运行，各阶段存活/峰值、等待零分配及最终归零一致。[最低版本记录](m6-sftp-auth-cost-allocation-msrv.json)。

同轮发送后的 8 类真实父端/helper/OpenSSH 场景也复验通过，包含最大 UTF-8 答案、两种取消、主机确认和超过网络期限的用户等待。[组合回归](m6-sftp-auth-cost-parent-regression.json)。

稳定源码默认 debug/release 各 383 通过、27 忽略，原生各 392 通过、29 忽略；默认三目标/本机原生 all-target Clippy、Rust 1.88 原生 release 编译通过。[构建记录](m6-sftp-auth-cost-build.json)。新增忽略项是显式环境测量，不在普通测试中自动启动 sshd。

继续使用这个默认关闭的 Unix 候选推进可见认证界面，明确每次认证需要一个临时 helper、约 536 KiB 文件及本机测得的增量；目前不引入通用 UI/SSH 运行时，也不将 C 假答案夹具用于产品。输入呈现 P95/P99、冷启动、实际 GUI 空闲/隐藏、多任务/弱网、30 分钟、Windows/Linux 原生和最终发布包尚未验证，未据此批准完整默认交付。优化和实测均未改变 16 KiB 提示、1023 字节答案、双槽、16 次挑战/120 秒阶段及原应用总预算。
