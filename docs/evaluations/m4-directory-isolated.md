# 本地目录隔离候选与成本

2026-10-25。为补本地目录在慢文件系统上的取消/退出边界，新增原字节协议、一次请求的隔离父端和最小目录 helper 候选。**父端仅用于测试，普通左栏和 SFTP 选择器仍用原后台读取；本轮没有完成或勾选慢文件系统验收、M4 或 M6。** 无新增 Rust 包，也没有为正常浏览增加子进程。主程序内部协议入口由默认关闭的 `directory-helper` 开发开关编译；普通构建不包含该入口或其参数检查。

## 实现与资源

目录 helper 在配置、字体、窗口及工作线程初始化前分流，复用同一 `local_directory` 扫描/显示规则。测试了主程序内部模式，也实现了不链接 GUI/SSH 认证组件的独立 `src/local_directory/helper_main.rs`，由工具显式以 Rust 编译，不是默认 Cargo/安装包产物。它只读目录项和类型，不读文件内容，不修改文件，不经过 shell 传递路径。

父端通过已有的受控进程组/非阻塞二进制管道发送单次请求，路径最多 16 KiB；回复为结构化状态、绝对路径和最多 512 项，每名最多 1024 字节，扫描仍最多 8192 项。最大完整回复 542,220 B。保留系统原名字节，仅显示时转义；拒绝非法类型、名字、排序、重复项、超限、截断和尾随数据。不可读项用明确标记传递，不解析展示文本。目录迭代器在生成回复前离开作用域。

父端保留原 3 MiB 目录工作票据、通道原 256 KiB 预留，另为 16 KiB 读缓冲及余量持有独立票据；Listing 缩小额度时缓冲仍有自己的票据。子程序有独立 4 MiB 元数据账本，写缓冲也有额度。这些不是父/子进程全部堆或 RSS 上限：尚未做此候选的全线程请求分配探针，系统/标准库目录内部、实际栈等仍在验收范围外。父端未接共享池，不能据此声称应用级并发和进程额度已完成。

读写共享整个请求期限，小幅持续输出不能反复重置期限。错误和成功都显式清理受控组，清理错误优先于协议成功，保留 PID 身份到回收。正常取消/超时实测已回收测试子进程并归还父额度。

仍有重要边界：现有进程适配在 spawn/回收时调用系统操作，`kill` 后仍可能在 `wait` 等待。整次读写期限不构成 spawn/系统回收的严格时间上限，进程隔离也不能证明不可中断内核调用会按期限结束。停滞夹具使用可终止的 `sleep` 和逐字节输出，不是真实挂载盘/NFS 故障。后续需要有界异步回收及仍持有资源的所有权，不能用“发出终止”冒充“确认回收”，也不能放松已有 join 门禁。

## 验证与成本

- [最终构建/回归](m4-directory-isolated-build.json)：普通 526 项、预览主程序 529 项及 helper 18 项通过；专用忽略分别 38/39 项。macOS 组合 feature、Linux/Windows 静态 Clippy、格式、默认依赖树通过；独立 helper 的本机无告警编译和 Linux metadata 检查通过。后两平台不等于真机运行；该 helper 候选目前为 Unix。
- [真实最小 helper 与成本](m4-directory-isolated-minimal-cost.json)：6 项目录测试通过、2 个专用夹具按需执行；其中新增 5 项覆盖协议、最大 DTO、取消前拒绝、受控停滞进程、整次期限。实际 helper 与直接读取逐项比较原名、类型、标签、路径和完整性，覆盖隐藏切换、链接、中文/换行名和 32 MiB 稀疏文件的元数据。非法 UTF-8 最大名/路径在协议测试验证，不冒充 macOS 真实文件名运行证据。
- 同一报告保留 2 轮/模式预热及 5 组交替样本。每次试验查询同一个 512 项目录 50 次，逐项核对相同模型；每批前另有 2 次非计时查询。最小 helper 相比直接读取的每次增量配对中位 **1.295 ms**，范围 **1.252–1.309 ms**；成功路径总耗时相对增量中位 **639.45%**。直接读取缺少进程隔离取消语义，不是故障等价替代，但启动成本不能当成消失。
- 最小 helper 二进制 **546,096 B**。5 ms 采样中额外同时存活进程最多观测到 1 个，其 RSS 峰值观测值约 **0.70–1.94 MiB**；父进程约 **8.80–8.83 MiB**，直接模式父进程约 **8.42–8.45 MiB**，均包含测试框架。短进程会漏采，观测最大值不是上限，RSS 相加可能重复计算共享页。逐 PID 采到的 CPU 最大值合计仅是整次夹具 CPU 下界，含测试准备，不能当作完整 CPU 计费或纯查询 CPU。
- [主程序内部模式对照](m4-directory-isolated-cost.json) 使用同模型的独立五组交替：每次增量中位 **2.507 ms**，额外进程观测 RSS 约 7 MiB。该历史源码在后续增加独立 helper 文件、Unix 字段限定和默认关闭开发开关之前，不能冒充最终快照。优化前无缓冲的记录和加入总期限回归前的记录另保留为 `m4-directory-isolated-cost-initial.json`、`m4-directory-isolated-cost-before-deadline-test.json`。
- [Rust 1.88 实际运行](m4-directory-isolated-msrv.json) 单独构建最小 helper，运行协议、取消/期限和真实目录一致性；只作最低工具链兼容证据，不重复完整成本比较。[证据核对](m4-directory-isolated-audit.json) 区分最终快照和历史记录。Windows 死字段静态失败及修正前的最小 helper 数据也保留，未删除失败证据。

## 采用结论与后续

不采用每次启动完整主程序的目录后端。最小 helper 保留为测试候选，尚未替换默认路径、加入预览包或批准默认采用；它明显减少启动/驻留成本，但仍有每次启动开销，不能宣称性能不受影响。已有 SFTP 16 MiB 池与 I/O 份额未因本轮提高。

后续补有界生命周期复用/按需退出、异步回收所有权、全线程分配和实际慢文件系统，再决定接入。原生窗口输入/传输、下载目标选择、M4 完整账本与交互延迟、M7/M8、终端兼容及三平台长测保持原目标，不因这一候选替代完整交付。普通 Alpha.6 与此前 SFTP 实验 ZIP 未重新打包，没有提交或推送。

复现当前候选（Unix；输出到临时目录）：

```sh
python3 tools/check_local_directory.py --minimal-helper --output /tmp/congminal-directory-cost.json
python3 tools/check_local_directory.py --minimal-helper --runtime-only --toolchain 1.88.0 --output /tmp/congminal-directory-msrv.json
```
