# M4 第二批：布局持久化评估

日期：2026-10-21。macOS arm64，Rust 1.99.0，offline release。新增 Cargo 依赖为零，复用标准库文件/线程/条件变量；自写小型版本化布局格式，不引入通用序列化包和后台运行时。操作见 [工作区说明](../execution-m4.md)。

## 接入与成本边界

默认 `restore-layout = false`，没有布局文件读取/写入和布局工作线程，单终端直接绘制仍可用。开启后增加一个专用线程，空闲阻塞等待；不启动外部程序来解析/保存布局。原生退出测试使用的 osascript 仅为测试工具，不是程序运行依赖。

布局只含 UI 树、顺序、焦点、侧栏开关/逻辑宽度。文件最多 4 KiB，固定 4097 字节读取缓冲，最多 8 个叶子、15 树节点、8 层；格式不包含任意字符串。检查版本、编号连续/唯一、焦点归属、比例和宽度后才启动新会话。所有标签均先检查当前尺寸下的可见网格准入；每轮最多创建一个当前配置的 Shell，全部成功才交换布局。尚未提交的会话受已有 PTY 输出 1 MiB 队列限制，不扫描/绘制历史，最多准备 7 个加原会话。提交后应用工作区 64 MiB 历史池及现有画布/网格上限。

400 ms 防抖，一项运行写入、一项最新待写、各一个读取/保存结果；没有随输入数量增长的任务队列。布局不变时不构造/序列化快照。普通 PTY/按键/鼠标移动不会触发保存；只在结构、焦点或侧栏改变时比较小快照。磁盘 I/O 均在后台，UI 锁内不读写文件。退出时立即提交防抖中的变化，最多等待 250 ms，不 join 卡在内核 I/O 的线程。

保存使用同目录独占临时文件、写入/文件同步、关闭、重命名；错误清理临时文件，旧目标保留。Unix 权限 0600。未同步父目录，不承诺断电后最新变动持久；强制退出、超时和多个实例最后写入的边界见操作说明。完整 512 MiB 全局账本仍未交付，不能据本批分项限制宣称进程 RSS 硬上限。

## 交互与恢复微基准

复现微基准：`cargo test --offline --release bench_layout_persistence -- --ignored --nocapture`。见 [原始数据](m4-layout-bench.json)。同一 release 实现，六轮交替关闭/开启持久化；每轮 1000 个按键，轮间计时外睡眠 5 ms 并推进 PTY，避免队列未消费导致测成拒绝路径。P95/P99 在每轮排序后取值，再取六轮中位数；不是系统输入至呈现的延迟。

八标签格式为 131 字节，重复解析/编码 10000 次；恢复场景为八个真实 PTY，六轮，每轮独立工作区。恢复计时从已有首个会话/Renderer 后开始，包括后台读入、额外七个会话分轮启动和提交，不是完整进程启动或所有 Shell 的首帧就绪。具体数值由原始 JSON 记录，见下表。

| 指标（六轮中位数） | 关闭 | 开启 |
|---|---:|---:|
| 按键处理 P95 | 0.125 µs | 0.125 µs |
| 按键处理 P99 | 1.645 µs | 1.292 µs |

八标签解析+编码单次均值 545 ns；额外七会话分轮恢复总时长中位数 10.046 ms，创建会话轮次 P50 的六轮中位数 1.218 ms，观察到单轮最大 2.659 ms。普通输入的差值很小，P99 有采样波动，不据此宣称交互加速。单次系统启动调用不可抢占，这不是 4 ms 的硬时限。

初始基准每批发 10000 个输入，触发了有界条目队列的拒绝/提示路径，不能作为普通输入性能结果；保留 [初始记录及无效原因](m4-layout-bench-initial.json)，没有用这些数据宣称优化收益。另保留 [与其他 Cargo 检查同时执行的中间记录](m4-layout-bench-concurrent.json)，最终单独运行上述基准，避免把并行验证负载混作功能成本。

## 原生 GUI 启动与空闲

[最终六轮配平对照](m4-layout-runtime.json)（含源码/二进制 SHA-256，保留 [退出修复前的初始组](m4-layout-runtime-initial.json)，只在组内比较）：同一 release 二进制，布局关闭/开启但文件不存在；Shell 就绪标记后 exec sleep，观察三秒空闲并自然退出。计时为 spawn 至 Shell 标记，不是首帧；首个样本未剔除，没有清空操作系统缓存，不作为冷启动证明。

| 指标（六轮中位数） | 关闭 | 开启 |
|---|---:|---:|
| 启动至标记 | 111.28 ms | 113.62 ms |
| RSS | 98.70 MiB | 98.64 MiB |
| 线程 | 13 | 14 |
| 空闲单核 CPU | 0.00078% | 0.00069% |
| 子进程 | 1 | 1 |
| 子进程 RSS | 1.016 MiB | 1.016 MiB |
| 子进程空闲 CPU | 0% | 0% |

最终组启动增加约 2.34 ms（2.1%）；RSS 差值约 -0.055 MiB，初始组约 +0.289 MiB。两组均确定多一个线程；微小的 RSS/CPU 差值有采样和系统框架波动，不能据此承诺零成本或更省内存。两组绝对 RSS/线程基数不同，只在各自组内比较。退出后确认没有生成一个无变化的默认布局文件。该组不包含恢复多会话的成本，也不替代长期压力或其他平台测试。

## 正确性与原生退出

本机 debug/release 正常回归为 207 通过、11 个手动基准/压力默认忽略；fmt、本机及 Linux x86_64 / Windows GNU 的 all-targets clippy `-D warnings` 通过。交叉检查只代表编译检查，不代替真机文件替换和 GUI 测试。

新增覆盖：八窗格布局往返与焦点/比例、不同配置独立文件、损坏/未知版本/截断/重复编号/超深/超大输入、普通文件检查、原子替换并发读取和失败保留、最新任务合并及退出等待上限、提前操作/分轮中断、首个及中途会话启动失败、所有标签的网格预算、历史总配额、普通终端流量不保存，以及防抖未结束时主动退出的集成保存。

[正常退出实测](m4-layout-quit.json)：实际恢复三个 GUI 标签和三个 Shell，向该测试 PID 发送 NSRunningApplication 正常退出请求，进程退出码 0、原布局保留。macOS 的退出委托先排入 Rust CloseRequested 并唤醒循环，取消 AppKit 直接终止，由 Rust 正常保存后结束。初版使用 NSTerminateLater 时测试请求超过五秒仍未返回，已改为适合当前自管循环的关闭路径。

尝试使用 CGEventPostToPid 定向发送新标签键没有观察到第四个会话，原因未确认；保留 [尝试结果](m4-layout-quit-input-attempt.json)。该尝试不能用于证明原生键入后的 dirty-layout 保存；退出前提交由真实 PTY 的工作区集成测试验证，原生输入交互仍需补验收。没有向其他应用发送按键，也没有将最后的强制测试清理当作正常退出成功。

## 结论与待验收

采用自写有界适配，功能默认关闭，用户可显式启用。不会把“后台执行”或“没有新增包”解释成零性能成本。开启会增加线程与少量 RSS，恢复会额外启动配置的 Shell；禁用后下次启动恢复原有布局 I/O/线程行为，不会删除已有布局。

仍待：30 分钟重复创建/恢复压力、Windows/Linux 真机文件替换及退出、三平台输入法与动态 DPI、慢盘/文件系统异常的完整实测、macOS 系统注销/关机协商、断电持久性和完整全局资源准入。当前配置的 Shell 初始化仍会执行，恢复不会重放旧命令；布局文件也不含旧目录或敏感文本。

最终源文件与 release 产物校验见 [构建记录](m4-layout-build.json)。上一批评估及原始文件保持原测量版本，不能用于代表本批开启持久化的性能。
