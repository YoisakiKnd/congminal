# M4 图像缩放与缓存额度交接

本机 macOS，零新增依赖、线程或子进程。只覆盖图像缩放工作集与生成结果向字形缓存的所有权交接；完整全局账本仍未完成。

缩放前按输入/输出尺寸计算两轴权重、行累加缓冲及输出像素容量，向原始 Image 所属账本申请。权重改为连续 taps 与 offsets，保留原面积平均/双线性计算顺序。临时数据销毁后只保留输出容量额度；缓存先申请已有模型费用的差额，再原子接管像素额度。拒绝、缓存淘汰及跨账本交接均先销毁数据再归还原额度。缓存命中路径与持久 Glyph 布局保持原样。

七组独立 RGBA 输入的输出校验值逐项相同。全局分配探针只测缩放新增的 Rust 请求字节，包含 realloc 新旧重叠，排除输入；每一组新增账本峰值均覆盖探针峰值，输出销毁后账本回到输入容量，最终归零。探针与计时使用不同构建，计时为五组交替前后对照，不并发性能任务。

| 输入→输出 | 请求峰值，前→后 | 缩放及销毁中位耗时，前→后 |
| --- | ---: | ---: |
| 32²→32² | 10,240→8,336 B | 2.862→2.049 µs |
| 128²→24² | 9,984→8,848 B | 24.262→21.362 µs |
| 16²→64² | 24,576→23,184 B | 22.667→20.236 µs |
| 2048²→128² | 139,264→143,504 B | 4.502→4.216 ms |
| 1024²→1024² | 4,390,912→4,325,520 B | 2.124→2.221 ms |
| 1×16384→512×1 | 421,912→293,064 B | 17.363→16.840 ms |
| 16384×1→1×512 | 393,240→284,888 B | 17.906→17.328 ms |

连续权重表的保守容量使 2048²→128² 峰值增加约 3%；1024² 同尺寸用例耗时增加约 5%，不宣称零开销。常见 emoji 用例约快 12%。输入像素、PNG 解码与缩放的额度同时存活；拒绝不会静默借用其他账本。返回结果临时持有一个额度拥有者，不给每个持久缓存条目添加票据。

整套五组 release 基准：VT 130.0→129.9 MiB/s，输入 P95 250→250 ns；四窗格整帧 605→595 µs、局部帧 25→25 µs。十组独立预热整帧 3.053→2.989 ms，单行更新 0.318→0.308 ms。未观察到热路径退化；这些是本机 CPU 基准，不代表真实窗口输入到呈现或 Windows/Linux 真机验收。

Debug/release 各 281 项通过、13 项显式忽略；macOS、Linux GNU、Windows GNU 三平台 all-target Clippy `-D warnings` 通过，release 构建通过。新增覆盖：196 组尺寸边界的权重一致性、仅够输出时拒绝完整工作集、Image 跨作用域账本归属、缓存满池交接/差额淘汰/拒绝析构/跨账本。

原始证据：[分配与缩放](m4-scale-resize.json)、[整套基准](m4-scale-bench.json)、[独立帧](m4-scale-render-isolated.json)、[构建及源码摘要](m4-scale-build.json)。后续仍需轮廓解析、光栅化、缓存桶及任务元数据准入；缓存模型的固定费用不等同于精确 HashMap 分配器成本。
