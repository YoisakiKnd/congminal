# M4 字体映射拥有者、弱缓存与固定错误

2026-10-25。字体 Storage/Arc 控制块已接入现有 `font-metadata-reserved`；路径 HashMap 改成固定 128 槽的文件身份弱缓存，移除其路径副本与动态桶。最后一个拥有者先退役对应弱引用，再销毁数据和元数据票据。映射/解析错误以固定大小值返回，不先分配临时错误 String。无新增 Rust 包、线程或运行时子进程，原总额度和字体映射上限没有提高。**本页为本机字体资源证据，不是完整 M4、完整应用堆/RSS 或三平台运行验收。**

## 准入与所有权

映射入口独立检查路径：非空、最多 16 KiB、无 NUL，随后申请 64 KiB 临时工作预留，再打开文件。Unix 非阻塞打开后检查普通文件类型；单文件仍最多 512 MiB，映射地址空间/数量继续使用原独立额度。映射额度不足不绕过限制改读完整堆副本；只有实际 mmap 失败才进入原有精确长度堆读取。工作预留覆盖有限路径转换及相关 Rust 临时数据，不覆盖 C/OS 或内核等待。

`Storage::shared` 在分配 Arc 前申请 `size_of::<Storage>() + 32`，包含结构体、控制块及对齐余量。本机两版工具链实际请求 104 B、预留 120 B；堆回退的文件字节另由 `font-owned` 收费。切片及重复命中只共享该拥有者，不复制文件和控制块。

所有强引用都由私有 `Shared` 封装，通过 `Arc::into_inner` 释放。最后一份 Storage 移到栈上时仍持有票据，先移除缓存弱引用，使 Arc 堆块确实可销毁，再释放映射/堆字节及最后的元数据票据。普通 Arc 内部的票据会早于仅弱引用保留的控制块释放，不能满足这一顺序，所以不能直接沿用旧 Arc 析构。缓存退役使用 checked 原子递增、不复用的拥有者 ID，避免旧地址释放后被复用时误删新条目；耗尽明确拒绝，不回绕。

固定槽以预算身份、已打开文件的身份、长度和修改时间匹配。Unix 用设备号/inode；Windows 通过 [GetFileInformationByHandleEx](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getfileinformationbyhandleex) 读取 [FILE_ID_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info) 的卷号和完整 128 位文件 ID，避免用在 ReFS 上不保证唯一的旧 64 位字段。身份/时间不可用或槽满时继续正常加载，只是不缓存，不猜测身份。Windows 分支仅完成静态检查，行为和成本仍待真机。

缓存查找、发布、退役只在有限槽操作期间持锁；文件打开、元数据读取、mmap/堆读取均在锁外。并发冷加载可以产生临时重复映射，仍先经过原配额；发布时复用已经发布的相同拥有者并释放多余候选。配额不足可以拒绝同时冷启动的额外候选，不承诺用一份映射额度容纳任意并发冷启动。

## 冷锁遗漏与修复

完整流程探针发现新缓存的 macOS 标准库锁首次使用会保留 **64 B** Rust 请求；最后票据为 0 时请求仍为 64 B，见[失败记录](m4-font-map-allocation-before-static-lock.json)。没有把这份全局分配排除后宣布归零。

macOS 缓存现使用原位 `os_unfair_lock`，本机 SDK `os/lock.h` 确认其 4 B/零值初始化布局。封装只接受 `&'static self`，保证锁地址稳定；Guard 不可跨线程移动，析构与 unwind 时由取得锁的线程释放。没有替换成忙等循环。Linux/Windows 封装继续使用原标准库锁；它们的实际分配/等待成本未经过本机运行证明。固定槽和原位锁为静态程序数据，不是动态堆；真实静态/系统/驻留成本仍由整进程测量观察。

## 错误与释放回归

文件错误保存 OS 数字代码/错误类别，其他错误保存枚举或静态文字；缺失表只保存四字节 tag。说明/警告的最终输出仍由上一阶段有界文本拥有者负责准入，不再通过 `io::Error::to_string` 或每个表错误的 `format!` 生成中间缓冲。

[当前工具链](m4-font-map-allocation.json)和 [Rust 1.88](m4-font-map-allocation-msrv.json)使用全线程 epoch Rust 请求计量，保守计入 realloc 旧、新请求重叠。预算/线程上下文、配置和输入文件/FaceInfo 预先建立；输入 FaceInfo 的 230 B 仍计入预算，但其请求不在本次 epoch 中。实际栈、计量器附加头、分配器、C/OS/RSS 不在请求计量内。

- 冷真实映射、硬链接缓存命中及最后切片保留：请求均为 104 B，只有一次分配、一个 10,804 B 映射；切片最后释放后请求/映射/数量归零。余下 230 B 是尚存的输入 FaceInfo，不冒充泄漏或全应用归零。
- 真实文件直接调用精确堆读取回退函数：请求 10,908 B（10,804 B 字节 + 104 B 控制块），释放后请求归零。它验证回退函数，不是强制制造了 OS mmap 失败。
- 16 个真实损坏字体经映射到 `load_face` 错误返回后仍被保存，另用固定栈缓冲核对 `head` 错误；不保留错误堆分配，也没有残留映射。
- 本机默认 `Fonts::load`：存活请求/额度 **15,924 / 16,004 B**；随后实际生成 A、中文、雪人和 ZWJ 家庭样本，变为 **17,692 / 18,414 B**。请求峰值当前工具链 **346,802 B**、1.88 为 **346,787 B**，预算峰值均 **1,308,987 B**。这一部分包含真实发现、加载和首次字形路径，不只是合成的容器。
- 样本生成后四个字体映射合计 256,480,520 B，属于独立映射地址空间，不能解释成等量堆或 RSS。最后请求、受管额度、映射额度和数量全部归零；根额度占满后的映射拒绝没有新增分配。

这些是本机已安装字库及上述样本的证据，不覆盖所有字体、完整字号范围或所有协议/排版特性。窗口、根预算上下文本身、通用任务/配置输入等仍需后续完整计费。文件系统 I/O、取消、文件/映射的内核关闭确认和硬期限也没有由账本归零证明。

五项新增常规回归覆盖固定缓存槽满/空洞/替换/旧代次移除、ID 耗尽、硬链接/文件替换/预算隔离、四线程八轮冷发布及最后引用释放、macOS 静态锁 unwind 释放。已有精确额度测试仅增加新控制块费用，原有工作余量不扩大。[完整构建](m4-font-map-build.json)：普通 **546** 项、预览主程序 **549** 项及 helper **18** 项通过，专用忽略分别 38/39 项；Rust 1.88 字体相关 **57** 项、三目标静态 Clippy、格式及默认 release 通过。Windows/Linux 交叉检查不算运行验收。

[Workspace 分配复验](m4-font-map-workspace.json)请求峰值 1,957,957 B，最后请求及 SFTP 子/父预留归零，模态预热直接绘制仍零新增分配；此时另有 1,146,880 B 应用资源，不宣称全应用归零。字体分类/预算类型未再增加，原 16 MiB SFTP 池、9 MiB I/O 余量和后台线程数不变。

## 同负载成本

[最终对照](m4-font-map-cost.json)使用生产 System 分配器，将相同夹具注入[改动前冻结源码](baselines/m4-font-map-before.tar.gz)和当前临时副本。各场景/版本两次整次预热后五组交替，**每次 50 个新扫描/默认加载，或 50 批各 1,000 次查询**。查询 API 计时不含后续验证/结果析构，加载 API 计时不含随后用于验证的真实字形生成。每轮仍为 803 face/1,161 名称，目录、查询及抽检字形指纹一致。

| API 场景 | 五组配对耗时中位变化 | 配对范围 |
|---|---:|---:|
| 新扫描 | -0.85% | -2.34% ～ +0.09% |
| 缓存查询 | +0.63% | -0.15% ～ +3.42% |
| 默认加载 | -1.00% | -2.30% ～ +1.30% |

扫描、查询、加载的整进程 RSS 高水位配对中位差依次为 -64 KiB（-320～+128）、-80 KiB（-80～+0）、+32 KiB（-208～+144）；CPU 差值中位均为 0 秒。

最初每次五个扫描/加载的[短样本](m4-font-map-cost-short-samples.json)中，默认加载中位约 +1.97%，有一组 +9.69%；因此扩大每轮工作量，原数据及[原驱动](baselines/check-font-map-short.py)均保留。长窗口未复现那个大幅回退，但也不把约 1% 的变化宣称成确定提速。系统字库和温缓存不是固定所有机器的环境。

`time -lp` CPU/RSS 包含整个测试进程、框架、验证、析构、映射/缓存，不能按差值逐字节归因于控制块或静态槽；CPU 只有 0.01 秒分辨率。上述不代表冷盘、关闭功能启动、原生输入到呈现、Windows/Linux 或 30 分钟验收。SDK/API 适配仍属项目现有系统接口路线，没有新运行时子进程成本。[核对记录](m4-font-map-audit.json)关联五份当前报告、工具/共享驱动/夹具、基线与上一字体元数据阶段及保留的失败/短样本。
