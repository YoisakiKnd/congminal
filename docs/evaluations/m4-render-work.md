# M4 渲染工作集准入与复用

2026-10-25。已将每视图的行指纹及共享绘制工作集接入 `render-reserved`，去掉每帧新建的 changed/dirty 数组，复用待绘制指纹、连字索引、ASCII 词和 emoji 缓冲。无新增 Rust 包、线程或子进程。**这只完成本页所列工作集，不是完整 M4、完整堆/RSS 账本或原生输入延迟验收。** 搜索装饰、界面字符串、字体发现/头部及任务等元数据继续待办。

## 额度与失败行为

本页工作集的每份 Vec/String 持有随容量移动的票据。扩容前同时预留旧块和新请求容量，失败保留已拥有的容量；扩大/释放时更新账本，预热后的绘制不逐行申请额度。视图交换同时交换指纹和票据，关闭视图才归还该容量。清理渲染缓存会释放共享工作集及当前指纹；其他视图仍为其保留的指纹付费。

待绘制指纹填好后与旧指纹比较，无变化立即返回；有变化仍将上下相邻行纳入擦除/补画。旧指纹在完成绘制后提交。指纹额度不足时不新建指纹/dirty 数组而直接全绘制，并使旧指纹失效，避免把新像素配上旧指纹而跳过后续更新。额度不足时连字可降级到普通字形；emoji 生成只使用已有容量，不扩容或把截断前缀提交为完整序列。

组合字符合成返回原字符串的剩余切片，不再逐格分配 String。emoji 字体接口本来的文本上限仍为 1024 B；渲染缓冲按该上限请求，较长完整序列沿用原来的逐字形降级。终端模型仍保留完整原文。长 ZWJ 序列、组合后缀来源、短缓冲、额度拒绝、视图释放和拒绝后的连续像素更新均有回归。

行索引的请求范围来自终端 2048 行上限，连字/词缓冲来自 4096 列上限，实际容量纳入额度；扩容重叠也计入。工作集固定描述符、实际线程栈、分配器元数据及系统分配不在本页 Rust 请求计量内。全局原有额度没有提高。

## 同负载成本与像素指纹

[最终对照](m4-render-work-cost.json) 使用系统分配器；将完全相同的夹具分别加入[改动前冻结源码](baselines/m4-render-work-before.tar.gz)和当前临时副本。每字体/版本有两次整次预热，再做五组交替。每次均交替两个视图/画布（160×48 与 81×25），含 ASCII、粗体、组合符号、ZWJ、国旗和键帽。点阵通过映射额度为 0 取得，轮廓为本机 Maple Mono NF CN、15px、scale=1；不是固定所有平台/机器的字体环境。

全部五组、两字体、完整/空闲模式的两幅画布合并 64 位像素指纹相同；原有增量/全绘制像素数组比较也通过。每阶段 2000 帧，完整绘制阶段强制失效，空闲阶段确认无 damage。下表为 after/before 总耗时的配对变化；总时间还含视图交换及测试检查。

| 场景 | 中位变化 | 五组范围 |
|---|---:|---:|
| 点阵完整绘制 | −5.11% | −6.89% ～ −3.84% |
| 轮廓完整绘制 | −3.77% | −5.32% ～ −3.22% |
| 点阵空闲帧 | +0.37% | −0.68% ～ +2.91% |
| 轮廓空闲帧 | −0.41% | −1.73% ～ −0.13% |

每个原始绘制耗时样本、nearest-rank P95/P99 均保留。较短的 200 帧尝试存在较明显空闲波动，保留为 `*-short-samples.json`，没有用它替换最终较长窗口。全行宽 emoji 预留版本也保留为 `*-before-cluster-cap.json`；收紧后仍保持原接口上限及完整序列语义。

5 ms 全进程采样的 RSS 峰值配对中位变化：点阵约 −80 KiB（−128～0），轮廓约 +48 KiB（+16～144）。包含测试框架、字体发现/映射/缓存，短峰可能漏采，不能将差值逐字节归因于工作缓冲，也不是常驻或完整 RSS 上限。绘制时间不包含原生窗口呈现、IME、剪贴板、应用其余 UI 或输入到显示延迟；本轮不关闭那些验收项。
