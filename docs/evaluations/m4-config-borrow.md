# M4：会话启动借用配置与最小字体请求

2026-10-26，macOS arm64。新建、布局恢复和 SSH 重连不再克隆整份 Config/ShellConfig；PTY 同步启动只借用参数，字体任务只接收 FontConfig。没有新增包、线程、子进程或生产额度。配置解析、持久配置对象和剩余字体副本仍需完整计费，不勾选完整 M4。

## 变更与生命周期

`Session::spawn_with` 接收独立的 shell 引用和尺寸，保留原配置的环境、光标和历史设置；普通启动继续由 `Session::spawn` 传默认值。窗格、逐轮恢复和重连直接借用当前配置及原配置档/SSH Launch，不先复制配置再覆盖 shell/尺寸。

`CommandRef` 是程序名、参数、工作目录和环境的借用视图。引用只持续到同步 PTY 启动返回，原生后台工作器不保留配置引用；Unix 的 CString/argv/envp、Windows 的命令行/UTF-16 环境转换仍按原生接口构造，尚未因此完成其全部准入。Windows 引号规则和 COMSPEC 回退保持；目前只有静态检查证据。

字体任务从 `LatestTask<Config, ...>` 改为 `LatestTask<FontConfig, ...>`，不再携带 shell、环境、快捷键、主题和连接配置档。字体家庭、有效字号、行高和连字值及“自定义字体”判定相同，取消、防抖和最后结果生效规则不变。剩余家庭列表副本仍需单独资源票据。Config/ShellConfig 的 Clone 只在测试构建保留，正常构建不能重新走整份克隆接口。

新增真实 PTY 测试用独立 shell 覆盖无效默认程序，检查工作目录、环境及 19×7 尺寸，启动返回后销毁所有源配置，再进行输入输出和回收。隔离 SSH 的五轮连接/回显及中断重连额外覆盖实际远程会话。没有把跨目标编译当作 Windows/Linux 真机验证。

## 性能

[原始数据](m4-config-borrow-cost.json)：同一 System 分配器夹具，两次预热后五组交替配对；每轮 1000 次字体请求构造/销毁，以及真实工作区 10 次新增窗格、READY、关闭。32 KiB 环境仍传入实际新 shell，未通过减少原有功能换取结果。

| API | 配对中位变化 | 五组范围 |
| --- | ---: | ---: |
| 字体请求构造/销毁 | −98.67% | −98.89%～−98.46% |
| 新增窗格 API | −4.26% | −13.10%～−2.55% |
| 新增至 READY | −0.67% | −6.02%～+1.43% |
| 关闭 API | −1.18% | −11.22%～+6.82% |

两组自身中位约为：字体请求 6593.53→88.84 ns，新增窗格 1298.06→1188.71 µs；它们的比值与配对中位不是同一统计量。就绪和关闭受调度影响，不称为稳定提速。整测试进程高水位 RSS 配对中位 −544 KiB（−688～−320 KiB），CPU 中位 −0.01 s（−0.02～约0 s），包含测试框架、初始化、验证、子进程和回收。不是原生 GUI 输入到呈现、全部字体加载耗时或整程序 RSS 上限；普通小配置的改善不能按此比例外推。
