# M4 字体容器、说明与警告交付

2026-10-25。新增 `font-metadata-reserved`，覆盖轮廓字体的 Box、后备/emoji 列表容量、字体说明和警告的输出缓冲及列表槽。说明与警告先计算有界 UTF-8 字节数，再申请额度并写入一次分配的缓冲；静态点阵说明及额度不足提示不依赖堆分配。无新增 Rust 包、线程或运行时子进程。**这不代表完整字体管线、完整 M4 或全部堆/RSS 已计费。**

## 所有权与失败行为

`Text` 的动态 String 与票据一起移动；静态提示只借用字面量。警告和后备列表最多 32 项，扩容前预留旧、新块的重叠容量，拒绝时保留原内容。每份动态说明/警告最多 64 KiB；超过上限直接拒绝整份输出，不返回截断的 UTF-8 文本。格式化第二遍也检查写入边界，即使格式化器两次输出长度不同，也不能偷偷扩容。

`Source::Outline` 的 Box 在创建前计入 `size_of::<Outline>()`；后备/emoji Vec 的票据原子合并到 Box 外部拥有者。列表的数据、Box 本体均在票据归还前释放，避免把票据放在 Box 内部、早于其堆块销毁。列表内 Pending 字体原始名称由此前 `font-discovery-reserved` 的共享记录继续持有，不重复复制。

Box 准入失败返回 None 并释放此次输入，已有 Fonts 不由构造函数修改；`Fonts::load` 仍按已有规则降级到内置点阵，调用方可能提交这份降级结果，**不宣称所有字体重载失败都会保留原界面字体**。说明/列表/警告的拒绝以一条静态“不完整”提示保留可见状态；即使根额度为零也能提供点阵字体的静态说明和该提示。配置解析原本最多 16 个 family，加载端也独立执行这个限制。

后台加载完成后直接转交 `Warnings`，不克隆整份字符串。启动与重载均借用其中的 `&str` 写入原警告展示路径；启动局部作用域在进入窗口事件循环前结束，重载在当轮交付后结束，释放不再拖到窗口关闭。配置警告的原 Vec 在构建显示前缀时被消费，显示副本也在该作用域结束时释放。配置解析、终端警告展示内部和通用任务对象本身的计费仍是 M4 余项。

## 分配与边界证据

[当前工具链](m4-font-metadata-allocation.json)及 [Rust 1.88](m4-font-metadata-allocation-msrv.json)均用临时副本的全线程 epoch 请求计量器，保守包含 realloc 旧、新请求重叠。有效的最小 sfnt Bytes、预算/线程初始化和 64 KiB UTF-8 输入在测量前准备；不包含原始 Bytes 的控制块、映射缓存、计量器附加头、分配器/C/OS、实际栈、完整字体加载或原生窗口。

夹具使用真实 `try_outline`，构造 32 条各 64 KiB 的动态警告、64 KiB 说明、32 个后备及 32 个 emoji Loaded Face 槽。后两项是容器辅助函数的合成最大负载，超过当前平台默认列表长度，不是声称安装了 32 个 emoji 字体。结果两版工具链一致：

| 生命周期 | 存活请求 / 账本 |
|---|---:|
| 完整对象保留 | 2,172,480 / 2,172,480 B |
| 转交警告，字体仍保留 | 2,172,480 / 2,172,480 B |
| 字体释放，仅警告待交付 | 2,098,688 / 2,098,688 B |
| 警告交付后释放 | 0 / 0 |
| 两份简单轮廓字体重叠 | 1,152 / 1,152 B |
| 替换后仅保留新字体 | 576 / 576 B |
| 全部释放 | 0 / 0 |

请求与账本峰值均为 **2,172,480 B**，共 58 次分配请求（其中 21 次扩容）；随后两份简单字体再申请两个 Box。转交不新增分配；根额度被占满后的文本/警告拒绝也没有新增分配，并保留静态不完整提示。这里的 576 B 是本机工具链的 Outline 类型大小，不是跨平台固定常数。

新增五项常规回归覆盖 UTF-8 精确额度、两次格式化长度变化、警告转交和上限、旧/新扩容重叠拒绝、两份字体重叠时新构造拒绝及旧对象仍有效、零额度点阵降级。[完整回归](m4-font-metadata-build.json)：普通 **541** 项、预览主程序 **544** 项及 helper **18** 项通过，专用忽略分别为 38/39 项；Rust 1.88 字体相关 **52** 项、三目标静态 Clippy、格式和默认 release 构建通过。交叉检查不算 Windows/Linux 运行验收。

新增统计分类后本机 Budget/Stats 为 280/232 B。[文件任务回归](m4-font-metadata-file-quota.json)仍使用原 16 MiB 池和 9 MiB I/O 余量，最大字段请求 2 个运行/11 个排队后由额度拒绝，最后请求及父额度归零。[Workspace 回归](m4-font-metadata-workspace.json)的请求峰值为 1,957,975 B，最后请求、子池和 SFTP 父预留归零；路径、选择、审阅、重试和退出的预热直接绘制仍零新增分配。不是整个原生应用每帧零分配或真实远程 GUI 验收。

## 同负载成本

[最终对照](m4-font-metadata-cost.json)把同一份目录/查询/加载和字形指纹夹具分别注入[改动前冻结源码](baselines/m4-font-metadata-before.tar.gz)及当前临时副本，使用生产 System 分配器。各场景、各版本两次整次预热后五组交替；每次五个新目录、五批各 1,000 次查询或五次默认加载。查询计时不含随后验证/析构，加载计时不含随后实际生成的 A/中文/雪人/ZWJ 家庭字形；不是冷盘、启动到窗口或输入到呈现延迟。

| API 场景 | 五组配对耗时中位变化 | 配对范围 |
|---|---:|---:|
| 新目录扫描 | -1.15% | -3.28% ～ +2.64% |
| 已缓存目录的名称查询 | -0.39% | -12.39% ～ +8.50% |
| 默认字体加载 | +0.39% | -1.41% ～ +1.73% |

扫描、查询、加载的整个测试进程 RSS 高水位配对中位变化依次为 +16 KiB（-16～+64）、+0 KiB（-16～+48）、+32 KiB（-32～+64）。CPU 差值中位均为 0 秒（工具分辨率 0.01 秒）。API 时间在本轮接近，短查询波动较大，不据此宣称稳定提速。

目录、查询和加载抽检字形的指纹均一致，每轮扫描 803 face/1,161 名称，没有触发限制。性能变化及 RSS 均按整个本机环境解释；新的账本和双遍有界格式化不能写成零成本。`/usr/bin/time -lp` 的 CPU/RSS 包含整个测试进程、测试框架、验证、析构、映射和缓存，不能按 RSS 差值反推单个 Fonts 的大小；CPU 只有 0.01 秒分辨率。

启动作用域修正前的六份报告及核对记录保留为 `*-before-startup-drop.json`，包括当时扫描耗时中位 +2.57%、加载 +0.11%、查询 −0.68% 的成本。最终报告重新对应当前源码；不挑选较快的历史样本替换最终结果。[证据核对](m4-font-metadata-audit.json)验证源码、清单、工具及共享驱动/夹具、归档和上一字体发现阶段的基线关系、指纹和额度释放。

继续待办：字体映射 Storage/Arc 控制块及弱缓存、路径/IO/解析错误对象、预算/同步对象本身与通用任务元数据、搜索装饰/界面文字等。同步文件系统/解码和窗口关闭的硬延迟、三平台运行及 30 分钟长测继续单独验收。所有新旧字体虽然共享原预算，但未覆盖部分不能据此解释成完整 512 MiB 受管堆/RSS 上限。完整 M4–M8 和终端兼容目标保持执行中；既有安装包未重打包，未提交或推送。
