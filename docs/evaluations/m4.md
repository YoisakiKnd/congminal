# M4 首批本机评估

日期：2026-10-21。macOS arm64，Rust 1.99.0，offline release。实现及未完成范围见 [工作区说明](../execution-m4.md)。

## 方案与边界

新增 Cargo 依赖为零。多会话/布局/合成适配复用现有平台事件、Session、Renderer 和有界任务执行器；全工作区一个字体集合和字形缓存，每个窗格保留独立 ViewState 与可见画布。普通单会话直到首次启用工作区动作仍直接绘制，不增加一份合成画布。

实际准入为最多 8 会话、工作区历史池 64 MiB、单窗格逻辑网格 65,536 格及工作区 8M 像素画布。每会话队列、搜索、链接、通知与复制继续保留分项限制；8 会话数量限制同时约束其总量。后台解析活动优先、其他轮转，全轮约 4 ms 的合作式预算，未完成扫描安排后续 deadline。系统通知默认关闭，共享单辅助进程/10 秒闸门；不把未测量的外部工具纳入默认性能保证。

这不是已经完成 512 MiB 全进程/RSS 账本的声明。字体映射、重排/扩容瞬时副本、分配器保留内存和全部外部进程尚未接入统一所有权准入。该项和目录/连接浏览在首批评估时仍未勾选。布局持久化已在后续批次接入，默认关闭；新增实现的测量与边界另见 [持久化评估](m4-layout.md)，下列首批原始数据保持原测量快照。

## 微基准

基线为开工时的 `02d7940` 工作区快照 `/tmp/congminal-m4-baseline-01a158a4`。为比较同一负载，向基线和当前代码仅增加相同的 cfg(test) 忽略重排基准，生产算法保持各自版本。五轮交替测量，保存 [最终原始数据](m4-bench.json)、[初始数据](m4-bench-initial.json) 和 [中间数据](m4-bench-intermediate.json)。最终文件包含源文件 SHA-256，以区分实现迭代。

每轮输入 1000 个事件；P95/P99 先在每轮排序取分位数，再取五轮中位数。只测事件处理至队列，不包含原生输入法、系统呈现或 PTY echo。

| 指标 | M4 前 | M4 后 |
|---|---:|---:|
| VT 吞吐 | 133.3 MiB/s | 134.1 MiB/s |
| 3616×2416 全帧 | 2.866 ms | 2.897 ms |
| 单行更新 | 0.294 ms | 0.296 ms |
| 原事件入口 P95 / P99 | 250 / 2000 ns | 209 / 2625 ns |
| 64 MiB 历史搜索片 P95 | 150 µs | 145 µs |
| 搜索总时间 | 26 ms | 25 ms |
| 重排片 P50 | 12.490 ms | 0.668 ms |
| 重排片 P95 | 13.135 ms | 0.794 ms |
| 20 次重排总时间 | 253 ms | 14 ms |
| release 二进制（debug=1） | 1,612,184 B | 1,724,984 B |

全帧约 +1.1%、单行约 +0.8%，均在本轮门槛内；不把它们写成“完全无成本”。P99 增量约 0.625 µs，绝对值远小于 1 ms 的处理增量门槛；不是原生端到端延迟的证明。二进制增加 112,800 B，约 7.0%。

新增 Workspace 默认入口：P95 的五轮中位数 250 ns，P99 为 2333 ns。新增四窗格 1600×900 合成负载：每轮 100 帧，全帧中位数 574 µs、单行 24 µs，画布总容量 11,224,704 B。字号/格子数量与上面的 3616×2416 基准不同，**不能直接用两个帧时间推断四窗格更快**。此场景侧栏关闭，未包括系统提交像素成本。

重排场景为约 64 MiB 历史、80↔79 列交替、20 次；前后最终历史均为 67,107,840 B。常见硬行移交旧缓冲、消费完释放旧逻辑行、精确扩容和过大行容量回收带来收益。1200 组确定性随机宽字符/软换行/空白光标案例与原算法一致；大软行仍存在临时缓冲，收益不能外推到所有内容。

## 重排及多会话资源压力

同一 M3 场景前后各 60 秒，1 Hz `proc_pidinfo` 时间序列见 [m4-reflow-stress.json](m4-reflow-stress.json)：

- 前版 654,486 轮，30–60 秒 RSS 稳定 176.3125 MiB。
- 当前算法 1,016,436 轮，30–60 秒 RSS 稳定 92.4844 MiB，约降低 47.5%；历史仍受同一 64 MiB 限制。
- 前后常态线程均 5；新版本采样含加载期 1 线程，不把加载期数值作为空闲优势。该场景直接复用单会话压力入口，隔离重排优化，不声称它覆盖了多窗格呈现。

四窗格切换/重排/重复创建关闭另测 60 秒，见 [m4-workspace-stress.json](m4-workspace-stress.json)：1,237,650 轮；4 个常驻真实 PTY，每 257 轮创建再关闭一个临时会话，每 67 轮调整窗口宽度。历史约 53,280,000 B；临时第 5 会话成功创建会重新分配配额，淘汰的历史不会因关闭恢复，不能把这一数值解释为已经装满 64 MiB。

画布总容量约 6.47–6.50 MB；10–40 秒 RSS 约 107.38 MiB，后段约 110.25 MiB，未见持续单调增长。常态 14 线程，采样最大 15，进程加载期最小 1；瞬时线程峰值可能发生在采样间隔内，不宣称硬峰值就是 15。观察到 tick 最大 44 µs、按键处理最大 21 µs；场景采用实际 PTY echo 加直接网格追加，不能代替所有窗格无限刷屏下的原生端到端延迟验证。

压力测试先于最后的共享系统通知闸门/侧栏签名缓存及快捷键整理；这些改变不修改本场景关闭的系统通知或字符重排路径。最后构建另经正常测试、交叉检查、微基准和启动/空闲复测，保留迭代记录而非混称一次全平台验收。

## 默认 GUI 启动与空闲

[最终六轮配平先后顺序](m4-runtime.json)，保留 [初始六轮](m4-runtime-initial.json)。以 spawn 到 Shell 写就绪标记计时，标记后 exec sleep，测 3 秒空闲并自然退出；不把该指标称作首帧呈现。

最终中位数：启动 132.63 → 136.24 ms（约 +2.7%，在 5% 门槛内）；RSS 115,515,392 → 115,384,320 B（约 110.16 → 110.04 MiB）；线程均为 14，唯一子进程为 Shell 的 sleep，未启动系统通知工具。空闲单核 CPU 0.00258% → 0.00265%，增量约 0.00007 个百分点，子进程为 0%。首次冷样本 1157/546 ms 仍保留，没有为取更好结果删除。

初始一组启动中位数 118.95 → 120.74 ms，线程均 13；不同采样时刻系统框架状态不同，只在组内比较，不拿两组绝对值拼接为性能改善。最终启动和绘制存在小幅成本，不能宣称零影响。

## GUI、平台与验证限制

本机 debug/release 正常测试各 **189 通过、10 个手动基准/压力默认忽略**；包括真实 PTY 的会话隔离/关闭/搜索、IME 与鼠标坐标、侧栏窄窗、粘贴跨焦点/失败/关闭、8 会话与启动失败、历史配额、网格容量回收、重排参照和系统工具闸门。fmt 与本机 clippy `-D warnings` 通过；Linux x86_64 / Windows GNU 的 all-targets clippy 通过，仅代表交叉编译检查。

[四窗格实际 Renderer 预览](../previews/m4-workspace.png)已检查中文、软换行、搜索高亮、窗格位置、左右栏和状态栏。它是本程序生成的画布，不是操作系统截图。GUI 冒烟测试启动、输出、自然退出通过；系统截图失败 `could not create image from display`，未取得 OS 截图视觉验收。

仍待：Windows/Linux 真机 GUI、三平台输入法/动态 DPI、X11 INCR 及外部剪贴板所有者异常协议、同步平台剪贴板 API 的延迟成本、真实系统通知/外部工具峰值、30 分钟压力和完整 512 MiB 全局账本。读取预算和请求关联已实现，不等于所有平台异常 IPC 都已完成验收。

最后补齐标签焦点记忆，并通过交互回归、release 测试和交叉检查；这是微基准后的小范围交互修正。首批构建源文件/产物校验见 [m4-final-build.json](m4-final-build.json)，不把不同源码快照悄悄标为同一次测量。
