# 认证父端与独立 OpenSSH 流组合验收

`sftp/openssh_auth.rs` 已把 Rust Front/Backend、私有 Unix 端点、独立 helper、OpenSSH 和 SFTP v3 客户端串联起来，仍仅编译进测试。当前提供单独的 Unix 认证连接入口，尚未接可见界面或默认发布路径。无新增 Cargo 包；Windows 私有 ACL/端点继续待实现。

## 生命周期与期限

连接入口核对会话/代次和预算身份，结构化传递 helper、票据路径、SSH 程序及参数。系统工具继续处理身份、代理、配置及主机校验；只将该独立路径设为 BatchMode=no，不写终端输入、不经过 shell。工作槽在二进制读、写和 flush 中推进端点，回调没有额外线程或动态闭包分配。

用户输入等待使用原认证阶段的 120 秒期限，等待期间暂停单次网络 IO 计时；请求接收/答案发送保留各自 5 秒绝对期限。退出用户等待后继续消耗剩余网络等待额度，持续收零碎协议数据仍沿用原有单次 Read/Write 语义，不声称整个传输已有硬期限。普通流调用相同代码但服务回调为空，其调度成本需要复测。

SFTP 客户端验证 VERSION 后立即 `finish` 认证阶段，清理票据/socket 并关闭 Front 状态，后续数据不再受认证计时器影响。客户端增加保留 IO 拥有者的握手失败路径：先显式结束受控 SSH/helper，再清理认证端点，清理错误优先于原握手错误；正常结束通过取回 transport 显式 finish。Drop 仍只是异常兜底，完整应用退出时的工作器确认尚未接入。

## 真实组合验证

工具 `tools/check_auth_parent.py` 只生成临时密钥/配置和回环 sshd。前端由测试线程模拟，使用真实短生命周期 Secret 回答，后台在原工作槽推进 IPC。以下 8 类场景通过：正常口令、1023 字节 UTF-8 口令、错误口令、前端取消、任务取消、首次主机接受/拒绝、延迟回答。未知主机例验证提示包含指纹，只有显式接受写入该例的隔离 known_hosts。

延迟例在 1 秒网络 IO 超时下等待 1.5 秒再回答，成功完成 SFTP VERSION；不提高网络超时来让测试通过。四个正向例都在认证阶段关闭后列出本工具的远端目录，完成 1 MiB 上传、独占临时名提交、短写输出下载及内容核对。最大受管峰值 3419280 B（含 3 MiB 目录/工作预留），8 MiB 测试池结束均零；采样未见已观察客户端子进程残留。这里不覆盖自行 setsid 的任意代理程序。[完整记录](m6-sftp-auth-parent.json)。

完整默认 debug/release 各 383 通过、26 忽略，原生各 392 通过、28 忽略；默认三目标与本机原生 all-target Clippy、Rust 1.88 原生 release 编译均通过。[稳定源码回归](m6-sftp-auth-parent-build.json)。新增普通测试验证独立等待期限、服务失败的组回收、网络期限恢复及代次失配不启动进程。Linux/Windows GNU 静态检查不等于真机运行，Windows 也没有编译 Unix 认证端点。

## 夹具修正与证据边界

首轮运行器遗漏 --ignored，结果为 0 passed/1 ignored，已被校验器拒绝，没有计作通过；[原始记录](m6-sftp-auth-parent-runner-initial.json) 保留。随后密集的错误认证/取消使隔离 sshd 累计来源惩罚，后续场景在提示前收到 EOF；[诊断日志](m6-sftp-auth-parent-penalty-diagnostic.json) 明确记录激活约 15 秒惩罚并丢弃连接。工具现在先查询自身 sshd 的展开配置，支持 PerSourcePenalties 时只在本工具拥有的服务端关闭该跨场景惩罚；客户端策略、系统配置和产品超时没有改变。[先前等待失败](m6-sftp-auth-parent-wait-initial.json) 同样保留。这与旧的无网络 ssh -V 并行时序调查不同，不据此关闭旧待办。

进程/RSS 样本包含 Rust 测试框架和模拟前端；功能等待和测试线程不能作为应用成本对照。当前未证明 helper 采用后的公平认证开销、GUI 输入/IME、完整退出确认、真实密码/多因素或 Windows/Linux 行为。接下来复测普通适配性能，再补至少五轮同负载认证及等待 CPU/RSS/进程/线程成本，然后接可见界面、活动窗格远端目录和共享队列；M6 全部完整交付项仍保留未勾选。

## 普通流适配性能回归

服务回调改动后，已按原方法复测两个预热和五组交替：同一 OpenSSH/配置/服务器/协议，501 项目录、32 MiB 双向逐字节核对、64 KiB 顺序 ACK，包含前后各 600 ms 空闲采样。中位数如下（阻塞基线/有界普通流）：

| 指标 | 阻塞 | 有界 |
| --- | ---: | ---: |
| VERSION 就绪 | 62.161 ms | 60.477 ms |
| 目录 | 134.552 ms | 134.630 ms |
| 上传 | 238.37 MiB/s | 245.30 MiB/s |
| 下载 | 243.14 MiB/s | 242.05 MiB/s |
| 受管峰值 | 3169340 B | 3431484 B |

本机正常单任务未观察到超过 5% 的吞吐退化，小差值不作为加速承诺。仍增加固定 262144 B 工作预留，结束均零；两者都是测试程序 2 线程加 SSH 1 线程、共 2 进程，没有新增传输线程。各轮总 RSS 峰值的中位为 13500416/13467648 B，最高为 13533184/13549568 B，差异不作节省内存的结论。前空闲 CPU 中位均为 0，后空闲约为 0.0031%/0% 单核；短窗口采样不替代长期空闲测试。

100 次同步创建锁等待中位 203 µs、P95 418 µs、P99 576 µs、最大 668 µs；仍是热缓存无 GUI 的争用测量。这轮证明普通路径的适配回归，不包含认证 helper；helper 的公平认证成本、Windows 等待及长测继续待办。[原始五组数据](m6-sftp-auth-parent-adapter-bench.json)。
