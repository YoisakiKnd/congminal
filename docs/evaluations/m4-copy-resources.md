# M4 输出复制的额度、取消和平台拥有者

2026-10-25。新增 `clipboard-reserved`，用户复制的输出缓冲及普通复制请求使用 `CopyText`，额度随作业→在途请求→平台拥有者移动，不转回调用线程的当前 Scope。无新增包、线程或运行时子进程。本页只验收输出复制缓冲和窗口复制代次；普通粘贴读取、链接检测、平台协议/原生送达及完整资源元数据仍待。

## 边界与拥有者

每个复制文本仍最多 **2 MiB UTF-8**。按原有 8 B 起步、倍增到上限，扩容前同时准入旧、新容量，完成后按真实 capacity 收紧。拒绝保留此前已复制的内部字节，但作业不交付半截结果；取消或丢弃时释放。查询复制从借用文本精确申请后分配，避免先创建未计费的请求 String。

CopyOutput 使用源 Terminal 的预算。完成时把 String 和票据一起移动到 CopyText，作业自身归零；源终端、窗格或调用 Scope 消失不会提前还票。没有 Clone 接口。Linux 的 `Window.clipboard` 持有该拥有者直到选择丢失、替换或窗口销毁，答复选择请求不创建另一份发送 String。普通粘贴读取该选择时创建的副本仍属于待接入的输入链路，不能据此宣称所有剪贴板缓冲均已计费。

菜单复制链接目前将链接检测返回的临时 URL 再复制到已准入文本；链接检测/临时 Hit 自身尚未计费，该路径存在一次额外 URL 副本。移交检测缓冲的票据和消除这份副本继续在 Links 接入中完成，本页的直接复制成本不是整个链接检测/菜单手势的成本。

## 最新复制与失败

复制代次是 Congminal 窗口字段，不随 PaneState 交换，不新增 Arc/线程。新复制清除当前旧请求和作业并递增代次；其他窗格的旧作业在 tick 前取消，旧请求在平台取走时丢弃，因此旧窗格不能晚到后覆盖新复制。到 `u64::MAX` 后明确拒绝并提示重启，不回绕复用身份。已由平台持有的剪贴板内容继续有效，直到后续复制成功替换它。

额度拒绝发生在向平台发布前；Windows 转换额度拒绝也在清空系统剪贴板前，因而保留系统原内容。OS 写入自身失败使用 CopyFailed 提示；不能将 OS 操作异常也解释成原内容一定完好。认证覆盖层消费该结构事件，不把它回落为认证文字。测试读取真实终端提示时按宽字符占位规则重建文本，没有放宽拒绝断言。

## Windows 转换

去掉临时 `replace` String，先统计 UTF-16/换行/NUL 长度，再准入、构造精确 Vec。保留原有 LF→CRLF 行为（已有 CRLF 也按原表达式转换）、代理对及嵌入 NUL 的编码序列；这不是嵌入 NUL 在原生接收端完整送达的证明。

转换拥有者还预留同尺寸 **GlobalAlloc 请求字节**；Windows 代码在系统块释放或成功转交后才销毁转换缓冲和票据。系统接管后的共享剪贴板不属于本应用拥有者。这里覆盖请求字节，不覆盖 OS 分配器取整、头部或物理驻留页。

最坏的 2 MiB 纯 LF 输入产生 4194305 个 u16（含末尾 NUL）：文本 **2097152 B**、Rust 转换缓冲 **8388610 B**，本机实际 Rust 存活请求 **10485762 B**；再加尚未实际执行的同尺寸 OS 请求预留，总额度 **18874372 B**（18 MiB + 4 B）。这份共同编码逻辑在 macOS 运行，Windows 全部 native API 行为仍需真机验收。

## 分配证据

[当前工具链](m4-copy-resources-allocation.json)和 [Rust 1.88](m4-copy-resources-allocation-msrv.json)采用全线程 epoch Rust 请求计量，保守包含 realloc 旧、新重叠。输入字符串、源终端/历史、预算及上下文锁在区间外建立；计量器附加头、分配器/C/OS、实际栈及完整初始元数据不在本页数字内。

| 阶段 | 实际存活请求 | Clipboard 额度 |
|---|---:|---:|
| 逐字符增长到 2 MiB | 2097152 B | 2097152 B |
| 请求转交/平台继续持有 | 2097152 B | 2097152 B |
| 选择释放 | 0 B | 0 B |
| 最坏文本及 Windows 转换 | 10485762 B | 18874372 B |
| 满池拒绝新文本/超限/新转换 | 原值不变，零新增请求 | 原值不变 |
| 最后销毁 | 0 B | 0 B |

独立文本池从冷增长的请求峰值和当时预算峰值均为 **3145728 B**，19 次请求，其中 18 次扩容；实际窗口拥有者移交不增加分配。Windows 构造后累计 21 次请求、18 次扩容。人工压力票据把最终预算峰值抬到 32 MiB，不能当成实际堆峰值，也不能把未执行的 GlobalAlloc 预留当成真实 Rust 分配。

拒绝零新增的结论针对这些核心缓冲 API；宿主生成/显示警告的完整路径不在该区间内，不能从中推导全部 UI 错误路径零分配。

另一个区间直接调用真实 CopyOutput，分片读取 **1920000 B**，最后返回的容量为 **2097152 B**；作业归零后额度继续跟随结果，源终端销毁后仍正确收费，最终结果销毁后本轮请求及整个源池归零。这个区间的根峰值包括测量前的终端资源；扩容重叠由上面的独立文本池证明，不借大历史的预算高水位掩盖文本漏记。

初版当前工具链探针在清空文本后观察到 **64 B** 保留，来自测量期间首次观察另一预算锁；MSRV 初轮也未通过归零检查，但该失败报告未记录差值。预热全部参与的预算锁后，两工具链的复制缓冲区间均归零，原始失败记录保留为 `*-initial.json` / `*-before-lock-warm.json`。这不是生产预算锁已前置计费的证明，根预算/同步对象及冷启动完整元数据仍待收尾；没有从计数器中直接减掉这 64 B。

## 同负载成本

[冻结源码对照](m4-copy-resources-cost.json)使用相同 System 分配器夹具主体：每版本两次预热，五组交替。薄适配器的完整代码/哈希保留在 JSON：直接文本比较原来的 `to_owned` 与新 CopyText；Windows 形状的转换比较原来的 replace/encode/collect 表达式与实际新 helper；CopyOutput 本身调用原有/新版真实 API，不作替身。

每轮 1000 次 64 B 输出复制、8 次 1.92 MiB 输出复制、5000 次 700 B 文本复制，以及 8 次较大 Windows 格式转换。短作业计时含构造与 step，长作业构造在计时外；哈希和最终析构在 API 计时外。大作业总计时包含调用方步进/样本记录；样本 Vec 预分配且不允许扩容。UTF-8/UTF-16 指纹相同。

| 场景 | 五组配对耗时中位变化 | 范围 |
|---|---:|---:|
| 64 B 输出复制 | +13.38% | +4.75% ～ +17.41% |
| 1.92 MiB 输出复制 | +2.57% | −0.71% ～ +4.75% |
| 700 B 直接复制 | +57.70% | +56.52% ～ +62.77% |
| Windows 形状的转换逻辑 | −15.09% | −22.23% ～ −12.82% |

批次折算中位约 **550→623 ns**、**12.33→12.55 ms**、**21.9→34.9 ns**、**1.73→1.47 ms**。百分比是配对总耗时的中位，不等于两个折算中位之比。新增准入的直接复制增加约 13 ns，不宣称零成本；Windows 数字是本机共同逻辑，不能推广成 Windows 真机时延。

第一版长复制约回退 8.45%；最终显式内联小写入路径，罕见扩容/准入放入冷 helper，保持额度和长度保护不变。首版报告保留为 `*-before-cold-grow.json`。最终每轮 936 个真实 step 样本中，五轮 P99 约 **0.122～0.126 ms**、最大约 **0.189 ms**；只覆盖该 ASCII 夹具，不证明全部 Unicode、分配器阻塞或硬 2ms 时限。

整测试进程 RSS 配对中位 **−1776 KiB**（−1792～−1744 KiB），CPU 中位 0s（0～+0.01s，分辨率 0.01s），包括终端构造、parser、哈希和析构。不能逐字节归因于文本，不能作为 Windows 原生进程、系统剪贴板内存或 UI 输入到呈现的测量。
