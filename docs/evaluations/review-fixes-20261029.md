同时修正：监控额度/工作器失败不再每帧重试和重绘，显式刷新可重试；慢采样返回后重新排定下一次采样，不依赖额外键鼠事件唤醒。Git PID 测试先确认进程已发布 PID；SSH 转发夹具用原子文件替换发布完整参数，避免断言读取半份日志。

## 分配验证

在临时源码副本使用已有 epoch 全线程 Rust 请求计量器，生产分配器保持不变。stable 与 Rust 1.88 各跑四个独立用例，均通过。输入、父预算和全局预热在 epoch 前；比较本轮保留请求/费用、峰值请求/费用及最后归零。

| 用例 | 保留请求 B | 峰值请求 B：stable / 1.88 | 保留费用 B | 峰值费用 B |
| --- | ---: | ---: | ---: | ---: |
| 1,000 条、每条 1 KiB 转义放大 status | 5,216,000 | 5,219,072 / 5,219,072 | 5,216,000 | 5,311,600 |
| stdout/stderr 各 1 MiB 超量输出，保留 32/4 KiB | 36,976 | 49,152 / 49,152 | 37,088 | 1,097,952 |
| 2,100 文件目录，截断至 2,000 | 85,611 | 301,569 / 4,392,337 | 1,703,936 | 5,242,880 |
| 本机真实 CPU/内存/磁盘/进程采样 | 94,746 | 742,471 / 742,471 | 262,144 | 33,816,576 |

所有用例最后请求与费用归零，管道用例没有读取工作线程。解析拒绝用例新增分配为零。1.88 目录峰值明显较高，仍保留原值和对应预留，不用 stable 的数字覆盖它。

管道请求包括调用方取消令牌的延迟同步分配。确定性夹具在输出结束后延迟退出，强制进入等待：输出释放后剩余 112 B，调用方令牌释放后归零；对应调用方费用 224 B，另断言延迟同步不超过其 128 B 余量。生产 LatestTask 已用已准入令牌，初版夹具使用 `Cancellation::default()` 导致范围不一致。未将额外字节加进输出费用，也没有删除原失败记录。

本证据不包括原生 malloc、操作系统对象、真实线程栈/RSS，也不是完整配置、全部请求/错误元数据、GUI 或全平台分配证明。

## 性能对照

使用 System 分配器，临时副本分别构建基线与候选，不把计量器用于计时。每种负载、每侧先跑两轮预热，再跑五组交替顺序配对。Git 每次在相同 500 文件修改仓库内预热两次后测七次查询，内容指纹一致。监控复用既有冷采样/200 次常规采样/5 次进程刷新调用组合。

| 项目 | 基线 / 候选中位 | 配对变化中位 | 范围和解释 |
| --- | --- | ---: | --- |
| Git status API | 50.86 / 51.31 ms | +1.19% | 单组 -19.02% 至 +25.27%，波动较大；另一次相同等待策略复测为 +1.42%。不宣称 Git 加速或尾延迟达标 |
| 监控进程采样 | 4.260 / 3.060 ms | -29.42% | 进程集合随主机变化，候选有 512 PID 上限，不能当成任意相同进程集合的吞吐提升 |
| 监控无磁盘采样 | 见原始记录 | 0.00% | 本机仪器分辨率内无变化 |
| 监控含磁盘采样 | 见原始记录 | +0.12% | 单组约 -0.53% 至 +0.83% |
| time -lp maxRSS 变化 | Git -64 KiB；监控 +224 KiB（配对中位） | — | 是整次测试命令的工具统计，包含夹具/预热影响；不是父子进程总内存或子进程 RSS 上界 |

首个安全修复候选的 Git 查询回退 **+46.50%**，没有接受该结果：双管道实现错误地在 stdout EOF 后固定睡 5ms，多条短命令累积了延迟。最终 Unix 等待真正仍打开的两个管道，全部 EOF 后先进行两次短退出等待，再降频；既避免固定延迟，也避免对关闭 stdout 的忙轮询。该失败对照和后续复测均保存。

Windows 使用 Job 和句柄白名单，但这轮只有交叉编译；其管道轮询、系统采样及原生呈现性能不能由本机数字代替。
