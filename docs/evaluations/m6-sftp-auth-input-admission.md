# 原生输入限量与 IME 暂存收尾

本阶段为可见认证补平台入口，未启用认证 UI。`ClipboardRequest::Paste(ClipboardRead)` 已可指定字节上限及严格 UTF-16；现有普通终端调用全部采用默认策略，认证的 1023 字节策略尚待工作区选择和绑定。macOS IME 的普通提交采用通用输入上限，组合采用 1024 字节上限；不能将它们称为已接通的认证输入。

## 平台行为

- macOS 剪贴板和 NSString/NSAttributedString 转换先看 UTF-16 单元数，再看 UTF-8 字节数，最后才创建 Rust String。UTF-16 单元数是 UTF-8 字节数的下界，明显超限时无需请求 UTF-8 编码。显式字节长度保留内嵌 NUL，交由认证模型整次拒绝，避免 C 字符串截断；无效/超限整次拒绝。
- Windows 在全局内存大小和请求上限内找 CF_UNICODETEXT 的终止符，先核算 UTF-8 长度再分配。严格模式拒绝孤立代理；普通模式保留既有替代字符行为。系统格式本身以 NUL 终止，不能声称该格式可传递内嵌 NUL。
- X11 在途读取保存原请求策略，不让下一请求覆盖；自身剪贴板先检查缓存长度再克隆。外部读取限制 XGetWindowProperty 长度，要求 UTF8_STRING、8 位格式、无剩余数据及精确字节上限；Xlib 按四字节单位取值，最多取到上限向上对齐后的部分，随后再拒绝超限。无 owner 立即回报失败，没有新增轮询或线程。

macOS 不再为 marked text 另存一个明文 String：NSTextInputClient 的范围查询只需 UTF-16 长度。提交/组合回调取代旧暂存前先清理并释放旧暂存；拒绝会结束组合并标记按键已消费，避免回落为部分普通按键。被抑制的暂存同样清理。三个 IME 调试入口已去掉提交文字、组合文字和待交接文字的格式化内容，日志仅保留控制状态。

这项修改也改变普通 macOS 超限组合的行为：原来先完整分配再由应用截取 1024 字节，现在原生入口整次拒绝并清空组合。有效范围内的输入保持原有上屏和 UTF-16 范围语义。

## 分配与清零

[探针工具](../../tools/check_input_allocation.py) 在临时源码副本注入同线程 GlobalAlloc 请求统计，实际工作区和产品分配器不变。输入源、NSString 和队列容量在计量前准备，故结果只回答“解码输出/暂存是否在分配前限量”，不证明整个事件队列的额度覆盖。所有内容都是公开夹具。

当前工具链和 Rust 1.88 的结果一致：

| 场景 | 分配 | 扩容 | 请求峰值 | 结束存活 |
| --- | ---: | ---: | ---: | ---: |
| 精确 1023 字节 UTF-8 | 1 | 0 | 1023 B | 0 |
| 精确 1023 字节 UTF-16 解码输出 | 1 | 0 | 1023 B | 0 |
| 超限 UTF-8 / UTF-16 字节长度超限 | 0 | 0 | 0 | 0 |
| 非法 UTF-8 / 孤立 UTF-16 代理 | 0 | 0 | 0 | 0 |
| 两种空输入 | 0 | 0 | 0 | 0 |
| UTF-8 内嵌 NUL / 普通替代字符路径 | 1 | 0 | 3 B | 0 |
| 实际 NSString 转换、替换暂存、拒绝回调合计 | 2 | 0 | 1023 B | 0 |

最后一项在 allocator **释放前**检查两个已初始化暂存区域，2 次检查、0 次失败；不读取释放后的内存。初始替换顺序的峰值是 2046 B，已改为先释放旧暂存，不通过增加额度掩盖重叠。[优化前](m6-sftp-auth-input-admission-allocation-before-pending-release.json)、[最终](m6-sftp-auth-input-admission-allocation.json)、[Rust 1.88](m6-sftp-auth-input-admission-allocation-msrv.json)。

不新增 Cargo 依赖、后台线程或周期定时器；新请求策略与 X11 在途策略都是固定大小元数据。UTF-16 严格分支先检查/核算再写入，禁止自动扩容。分配数据不包括 allocator、ObjC/C/OS 内部副本、栈、RSS，也不包括源对象创建；系统剪贴板和输入法仍可能同步等待或在内部编码，未证明硬时限或 GUI 输入尾延迟。

## 回归与后续边界

新增 4 项常规测试：两项平台解码策略边界，两项本机真实 NSString/NSAttributedString、UTF-16 组合范围及超限回调。默认 debug/release 各 402 通过、27 忽略，原生可选后端各 411 通过、29 忽略；默认/原生本机及 Linux/Windows 默认 all-target Clippy、Rust 1.88 原生 release 编译通过。[稳定源码回归](m6-sftp-auth-input-admission-build.json)。交叉检查不代表 Windows/Linux 原生行为已验证。

另以 CONGMINAL_TRACE=1 运行真实组合/提交回调夹具，检查控制状态日志确实输出、公开夹具文字未输出；这是对应回调的日志回归，不代表所有模块或操作系统的日志审计。[记录](m6-sftp-auth-input-admission-trace.json)。

以下仍必须在认证进入生产前完成：

- 在输入/组合开始时捕获完整视图 token，清理失配、取消、切换后的迟到结果；不能在回调到达后补套“当前 token”。认证粘贴必须实际选择 1023 字节严格策略。
- 原生队列、所有在途副本及焦点上下文的统一准入、清理和数量上限。当前 probe 的 1023 B 峰值只覆盖指定暂存序列，不能套用到一轮多个已排队事件；Editor 预留一个事件不代表已覆盖整条原生链路。
- macOS 普通 key_events 回退、Windows/Linux 原生 IME、真实窗口焦点/呈现和输入 P95/P99。此次测试直接调用 NSString 和回调，不包含原生窗口或实际输入法进程。
- X11 的 INCR、超时和强请求身份。当前保留在途请求直到答复；不能简单清空后复用同一 property，使旧回复误配给新请求。还需三平台外部剪贴板真机验证。
- 工作区认证面板、完整配置/主机身份、SFTP 全局分项额度和共享队列、工作器退出确认、Windows 安全 IPC 及其余 M4–M8、长测，保持原计划。
