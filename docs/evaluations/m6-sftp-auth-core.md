# 可见认证核心的边界验证

当前已实现挑战/一次性答案状态、秘密编辑缓冲和单次请求/答案帧，全部仅在测试中编译。没有真实 helper、IPC 服务或认证界面；普通 SFTP 兼容流仍为 BatchMode。不能以本轮结果勾选完整认证、密码/多因素、远端界面或三平台运行。

## 状态与帧

每条挑战包含窗格、代次、进程内单调连接 ID 和序号；同一 owner 的新连接也有不同 ID，不复用旧回复。一个输入槽和一个通知槽，总计最多 16 条挑战，认证阶段创建起最多 120 秒。重复回复、跨窗格/代次/连接、其他额度池的答案都拒绝并清理传入秘密。答案移动到后台，一次取走；空答案与取消不同。confirm 只接受明确 yes/no，不把空值当作同意；none 不占用输入槽。

UI 回答/关闭通过条件变量唤醒等待，外部任务取消合作式检查间隔最多 20 ms；调度延迟不是硬实时保证。取消、到期或锁中毒优先清理已排队答案，不能先把它交给 helper。前端/后端关闭各自使对端失效。超时单元验证在持锁状态推进私有测试期限，避免依赖短睡眠抢调度；产品期限没有放宽。真实 GUI 切换/关闭和工作器退出确认尚未接入。

秘密最多 1023 字节，允许显式空输入，拒绝 NUL/CR/LF 和超限；UTF-8 边界内编辑，不扩容，不实现 Debug/Clone/Display。删除清理尾部，析构先 volatile 清零全部初始化存储，再释放 Vec 和额度。只在完整帧验证 UTF-8 后才暴露解码答案；部分字符在接收期间不能成为公开答案。

提示最多 16 KiB，显示保留换行并转义控制字符、双向标记和无效 UTF-8 字节；最坏显示容量为四倍，没有按英文文本猜认证类型。帧使用固定头、版本、保留位与长度验证；请求在验证全部 32 字节能力值后才给包体额度。此处只实现能力值容器/校验，系统随机生成、私有票据与套接字权限仍待实现。错误头、部分 EOF、额外数据和取消会清理暂存。请求包和 nonce 头释放前清零；答案帧直接借用其拥有的 Secret，不制造另一个答案 Vec。

## 实际分配探针

工具 `python3 tools/check_auth_allocation.py --output /tmp/auth-allocation.json` 在临时源码副本注入测量分配器，不修改应用分配器。追踪当前测试线程的 Rust GlobalAlloc 请求字节，realloc 保守计旧/新重叠；不含分配器额外开销、C/OS 内部分配、线程栈、RSS 和预先初始化的共享账本上下文。

在同一 128 KiB 测试池中刻意同时保留请求编码、解码原文、16 KiB 全控制字节提示及其 64 KiB 显示、1023 字节编辑答案和解码答案，覆盖复制重叠。它是核心组件组合压力，不是实际父/helper 进程树内存测量。

| 场景 | Rust 请求峰值 | 记账峰值 | 最终请求/记账 |
|---|---:|---:|---:|
| 请求/提示/答案组合 | 100834 B | 101466 B | 0 / 0 |
| 实际条件变量等候并到期 | 488 B | 608 B | 0 / 0 |

Rust 1.99 与最低支持的 1.88 均实际运行了探针，得到相同的请求/记账峰值及最终归零。接近答案上限的 10000 组 UTF-8 删除/插入均为零分配、零 realloc，两轮分别约 2.69/2.37 ms；只是单次微基准，不比较编译器快慢，也不是 GUI 延迟、统计分位或全部认证开销结论。[当前工具链](m6-sftp-auth-core-allocation.json)、[Rust 1.88](m6-sftp-auth-core-allocation-msrv.json)。

探针确实发现并修复了遗漏：初版在等待后实际存活 400 B、记账 304 B。先把探针共享账本上下文本身预热，分离其 64 B 懒初始化；组件仍为 336 B 对 304 B，存在 32 B 漏记，峰值 488 B 对 480 B。现在 Body 另外计入 256 B 元数据，覆盖 Arc 头及标准库同步对象的懒分配；等待后记账 432 B，覆盖实际 336 B。提高的是组件向相同池申请的费用，128 KiB 测试池、全局及 SFTP 目标上限没有提高。[初版](m6-sftp-auth-core-allocation-initial.json)、[诊断](m6-sftp-auth-core-allocation-diagnostic.json)、[分离账本初始化后的诊断](m6-sftp-auth-core-allocation-wait.json)。账本上下文自身的全局归属仍计入 M4 待办，不把排除项说成已全部覆盖。

## 回归与剩余工作

新增 12 项测试覆盖编辑/清理、一次性及过期答案、hint、确认/通知、配额、提示上限、取消/到期/中毒/关闭、分片帧、32 个能力字节的错误匹配、异常长度、半帧 EOF、无效答案及额外数据。默认 debug/release 各 375 通过、25 忽略；原生功能各 384 通过、27 忽略。默认三目标及本机原生 all-target Clippy、Rust 1.88 原生 release 测试编译通过。[构建记录](m6-sftp-auth-core-build.json)。Windows/Linux 是静态检查，尚未运行本轮分配探针或真实认证。

没有新增 Cargo 包、默认线程、程序或网络访问；模块仍由 cfg(test) 隔离。后续按 [认证交接方案](../design-sftp-auth.md) 实现安全能力来源/私有票据、套接字/helper、后台流服务回调和可见界面，测量实际进程与等待成本，补工作器退出确认。不能沿用无 helper 时的成本结论。
