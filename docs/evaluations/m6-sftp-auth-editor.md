# 认证编辑模型与清零证明

`ssh/auth_editor.rs` 已实现认证界面的编辑模型，仍只在测试模块编译，尚未接窗口事件、绘制或远端文件入口。它不把答案交给普通搜索栏/日志，也没有 Debug/Clone/Display。公开 Mask 只包含掩码字符数、光标、选择范围和组合字符数。

## 行为与归属

编辑和 IME 暂存各复用固定 1023 字节 Secret。支持 Unicode 光标、选择、删除/替换及显式空答案；Key::Char 使用四字节清理暂存，不为单字符额外创建 String。Text/Preedit 事件以拥有的 String 消费，成功、超限、无效和迟到路径都会在释放前清理已初始化区域；不截断成另一个密码。组合输入期间不提交、移动或删除主答案，最终提交替换选择并清理组合内容。

每次 Editor 创建新且不回绕的视图 token，包含原挑战 Ticket；即使重新打开同一挑战，旧的 IME/粘贴结果也不能用于新视图。实际原生事件还须捕获/转交该归属，不能把“当前 token”事后套在迟到事件上。UI 须在唤醒及输入前调用 sync，过期、外部关闭或已被别的编辑器提交时清理本地答案/组合。状态明确区分编辑、已提交、已取消和被拒绝，取消不标成提交成功。

加入 Front.cancel_input(Ticket)：只取消绑定的当前挑战，旧界面不能借取消操作杀死后续请求。确认型提示拒绝普通输入/通用 Enter 提交，同意须显式调用并已查看提示；拒绝可直接执行，默认没有同意。普通 Secret 同样须由视图标记提示已查看后才允许提交，该标记只是接口条件，真实完整提示展示仍待实现。

## 额度与分配验证

创建前预留 `size_of::<Editor>() + 128 + 1023 + 128` 工作额度，另外两份 Secret 各自准入。额外 1151 B 覆盖原生桥接在分配前按 1023 字节限量后的一个事件副本；目前平台尚未提供该入口，不能用编辑器事后拒绝证明超大原生副本已准入。没有提高应用总预算。

6 项功能测试覆盖 Unicode 编辑/掩码、组合和长度、空答案、视图 token、旧挑战取消、确认默认拒绝、额度失败不改变挑战、事件清理与过期同步。默认 debug/release 各 389 通过、27 忽略，原生各 398 通过、29 忽略；默认三目标/本机原生 all-target Clippy、Rust 1.88 原生 release 编译通过。[稳定源码回归](m6-sftp-auth-editor-build.json)。

分配探针在临时源码副本运行，覆盖 16 KiB 原提示形成的 64 KiB 显示、两个秘密缓冲、最大输入/组合事件、迟到/无效事件和移动提交。当前与 Rust 1.88 的请求峰值均为 70080 B，账本峰值 73690 B；各采样点存活有覆盖，结束请求存活及账本均零。10000 组删除/重新输入 Unicode 字符无分配/realloc，热缓存微诊断约 5.0/4.8 ms，不当作 GUI 输入延迟。

同一临时分配器只登记本线程明确拥有、保持初始化且不会重分配的区域，在 allocator dealloc **之前**检查。4 个 String 事件（正常提交、组合、迟到、无效）和取出的答案共 5 次检查全部为零；不读取释放后的内存，也不将答案字节打印进记录。该工具只注入临时测量程序，没有替换产品分配器。[当前工具链](m6-sftp-auth-editor-allocation.json)、[Rust 1.88](m6-sftp-auth-editor-allocation-msrv.json)。

数据不包括分配器开销、C/OS/输入法/剪贴板内部副本、线程栈、RSS和预初始化的共享预算上下文。接收的事件在该测试中精确按长度分配，不证明任意大容量 String 或平台已有截断副本都受限；这些属于下一步原生桥接准入。
