# 第三方依赖与适配策略

更新日期：2026-10-20

状态：已确定的开发约定；本文没有批准任何具体包，也没有把未测量的影响标为零。

## 1. 选择原则

允许使用第三方 Rust 包、系统库和外部程序。选择依据是功能正确性、实际性能、资源边界和维护成本，不以“零依赖”作为今后的硬性目标。

每项候选先说明会影响哪些路径，再通过最小原型和同负载测量确认。结果不明确时标记“未验证”，不进入默认发布路径；测试原型可留在隔离分支或默认关闭的实验能力中。不能用“运行在后台”“用户没有点击”“包很小”代替测量。

采用顺序：

1. 评估成熟实现，在接口外建立薄适配层，明确输入、输出、取消和资源所有权。
2. 关闭不需要的默认功能，限制线程、缓存、队列和并发；需要时改为按需调用或独立进程。
3. 同负载验证后，只有满足预算且无明确回退的方案进入默认功能。
4. 不能验证、不能控制资源，或优化后仍不能达标时，换用更轻的实现，或自行编写相关适配/必要组件，再做同样的验证。

自写适配指连接现有接口、进程/通道管理、结构化数据解析、调度与缓存等。SSH 的加密、认证、主机验证优先采用经过维护的实现；不会因性能问题直接自行实现密码学。自写组件同样需要证明其正确性、资源边界与性能，不能默认认为更快。

## 2. 必须明确的影响

| 维度 | 必须记录的内容 |
|---|---|
| 启动 | 冷/热启动时间，模块初始化、字体/配置扫描、外部程序启动是否延后到使用时 |
| 交互 | 输入到处理/呈现的延迟分布，UI 线程是否执行阻塞工作，满队列、取消与超时行为 |
| 吞吐与绘制 | VT 解析、整屏/单行更新、搜索、传输、Git 查询各自的同负载结果 |
| 内存 | 受管堆、RSS/PSS（平台可用时）、峰值、缓存高水位、映射、任务停止后的释放情况 |
| 后台 | 功能关闭、面板隐藏、无任务、断线和失败重试时的 CPU、唤醒、线程与进程数 |
| I/O | 磁盘读取、网络请求、重复扫描、缓冲复制、进程间通信及序列化成本 |
| 交付 | 发布包/二进制大小、编译时间、传递依赖、所需外部工具和支持平台 |

库的成本计入本进程；外部程序同时记录 congminal、子进程和合计数据。进程隔离能改变开销发生的位置，不能把子进程成本当成消失。共享库、只读映射与系统缓存的计量方式应注明，避免重复计算或漏算。

开发/构建工具依赖与用户运行依赖分开记录；构建依赖即使没有运行时成本，也要注明编译、下载、打包影响。

## 3. 对照实验与接入门槛

以下是初始工程门槛，不是对当前性能的测量结论。功能开关、场景和预算明确后再评审具体结果。

### 3.1 测量方法

- 记录确切版本、启用功能、传递依赖、平台、硬件、构建参数和输入数据。
- 使用 release 构建，保持相同功能、输入规模、缓存状态与并发；区分冷启动、热缓存和稳态运行。
- 比较未引入候选的可比实现与候选实现。新增能力没有同功能基线时，先做最小原型，不把新增功能的全部成本直接归因于依赖。
- 至少交替运行五次记录中位数、范围与原始样本；短操作的 P95/P99 使用足够事件样本，初始至少 100 次，注明统计方法。
- 无任务/关闭功能、单会话、多会话刷屏、大目录/仓库、大文件、弱网/断线分别测量。
- 做至少一轮 30 分钟的重复启停/切换压力测试，检查内存、句柄、线程和缓存是否持续增长；保存时间序列，而不只保留最终值。
- 计划支持的平台分别验证；未验证平台必须标记，不用本机结果推断全部平台。

### 3.2 判定标准

| 项目 | 初始接入要求 |
|---|---|
| 既有功能回退 | 关闭新增功能时，启动、VT 吞吐、绘制成本的稳定回退不超过 5%；差异接近噪声时增加样本 |
| 输入响应 | 同场景 P95 延迟增量不超过 1 ms，且不突破该阶段交互预算；P99 同时报告 |
| 空闲开销 | 无任务/隐藏面板不保留无用途的循环轮询和线程；CPU 增量目标不超过单核 0.2 个百分点，超出先定位 |
| 内存 | 适配层与依赖共享已分配的分项/全局预算；可配置或可验证的峰值与淘汰/释放行为，不为包另开无限额通道 |
| 正在使用的功能 | 在同功能基线或明确的任务预算下评估；说明每会话、每任务及多任务合计成本 |
| 失败与取消 | 满队列、超时、取消、断线后不堆积任务；关闭不会等待不可控的阻塞调用 |
| 发布 | 解释体积、编译和安装成本，不引入与本功能无关的大范围能力 |

5% 和 1 ms 是评估门槛，不是允许故意变慢的配额。测量未通过时先裁剪、隔离、调整适配或换实现，再重新测量；仍不达标则不纳入默认方案，转向自写适配/组件。必须改变目标或提高资源预算时，先更新方案并明确说明用户可感知的代价，不能静默放宽。

新增功能本身通常需要资源；“不会影响性能”只在明确场景和测量分辨率内表述，不能作全场景的零成本承诺。

## 4. 各模块的选型方向

以下只是候选方向，尚未完成具体包的选择和性能验证。

| 模块 | 允许比较的方案 | 重点测量 | 不达标时的适配方向 |
|---|---|---|---|
| SSH | 系统 OpenSSH 子进程、成熟 SSH 库 | 连接/认证耗时、每连接资源、并发、取消、与主线程隔离 | 自写连接配置与进程/通道适配，保留成熟加密与认证后端 |
| SFTP | 成熟 SFTP 库、OpenSSH 子系统通道及有界协议适配 | 吞吐、复制次数、并发请求、缓冲峰值、目录读取 | 自写流式传输调度或 SFTP 协议适配；不自行实现 SSH 加密 |
| Git | Git CLI、成熟 Git 库 | 进程启动、大仓库扫描、diff 峰值、闲置刷新成本 | 自写去抖、缓存、结构化输出和按需读取适配，不重写完整 Git |
| 搜索 | 成熟匹配库、自写文本扫描 | 查询取消、Unicode/格子映射、大历史分片、结果内存 | 自写有界纯文本扫描，正则按需接入 |
| UI/布局 | 轻量组件库、现有软件渲染上的组件 | 输入法、脏区域、每帧分配、启动体积、隐藏面板开销 | 自写局部布局/组件，复用终端渲染与平台桥接 |
| 监控/通知 | 系统接口适配、跨平台库、独立采样程序 | 采样成本、线程、唤醒、隐藏/断线行为 | 自写小范围平台适配和有界调度 |
| 任务调度 | 标准库工作池、轻量执行库、按需运行时 | 线程数、空闲唤醒、取消、内存及队列所有权 | 自写有限工作池/事件桥接，避免引入无预算的后台运行时 |

所有后端通过项目内部接口接入，终端状态、布局和业务功能不直接绑定候选包的数据结构。明确谁创建/销毁线程、进程、文件与网络句柄；后端可替换，现有行为测试继续适用。

## 5. 每项依赖的评估记录模板

在首次接入前，为该项功能创建单独记录（例如 `docs/evaluations/<feature>.md`），至少填写：

```text
功能与候选：
候选类别：Rust 包 / 系统库 / 外部程序 / 自写适配
确切版本、启用功能与传递依赖：
接入范围与许可证/分发方式：
影响路径：启动 / 渲染 / 输入 / 后台 / I/O
预算与资源所有权：
对照实现、场景、平台与原始数据位置：
启动、延迟、吞吐、内存、CPU、线程/进程、体积结果：
关闭/隐藏、取消、超限、异常与重复启停结果：
未验证场景与平台：
结论：采用 / 优化后重测 / 自写适配 / 替换候选 / 不采用
用户可感知影响与理由：
回退方式及再次评估条件：
```

依赖升级、启用额外特性、更换后端或改变调用频率后，对受影响路径重新评估。不能用旧版本、单连接或小数据的结果替代新场景的验证。
