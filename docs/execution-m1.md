# 代码评估与第一阶段执行记录

日期：2026-10-20。评估基于当前工作树，包含上一批底层加固；对照基线是本轮开始前的工作树快照，不是把尚未提交的加固改动丢弃后重新比较。

## 评估结果

现有 VT 解析、终端网格、字体/图像解析、软件渲染和三平台 PTY 已形成可运行的单会话终端。上一批实现了有界 I/O、历史与字形缓存预算、映射生命周期及畸形输入回归。开始本轮时测试基线为 142 项通过、2 项手动性能测试忽略。

继续增加功能前，主要缺口如下：

| 代码现状 | 影响 | 安排 |
|---|---|---|
| `Congminal` 同时拥有终端、PTY、解析器、选区与窗口状态 | 多会话容易复制状态或混用生命周期 | M1 拆出 `Session`；M4 才开放多会话 |
| 配色/内边距热更新也会重建字体，字体加载在 UI 线程执行 | 无关设置增加磁盘扫描、释放缓存并阻塞输入 | M1 独立样式更新；字号/字体更新后台执行 |
| 快捷键硬编码，部分由 macOS 菜单截获 | 用户无法统一配置，跨平台符号键含义不同 | M1 动作表、显式焦点入口和平台按键适配 |
| 分项上限存在，但缺少统一观察入口与后台结果归属 | 难以发现积压，异步旧结果可能覆盖新状态 | M1 快照、取消和版本校验；M4 全局准入账本 |
| 搜索、命令边界、布局、远程通道及通知模型尚不存在 | SSH/SFTP/Git/监控直接接入会反复返工 | 按 M2–M8 逐层实施 |
| Unicode、协议查询、动态 DPI 和非 macOS 真机覆盖仍不完整 | 终端兼容性与输入法有剩余验证风险 | 与各功能阶段并行推进，不以交叉编译替代运行验证 |

结论：适合继续演进，当前重点是拆分和约束资源，而不是整体重写或立即引入大型 UI/异步运行时。

## 本轮目标与实现

目标：落实 [路线图 M1](roadmap.md) 的代码基础，交付缩放、自定义快捷键和三套主题，验证既有吞吐/绘制及后台资源边界。

- `src/session.rs` 拥有终端、解析器、PTY、队列、选区、预编辑和会话鼠标状态。窗口继续负责绘制与平台交互。关闭时先解除输出背压，再销毁 PTY；退出状态和 EOF 到齐且输出排空后才结束。
- `src/action.rs` 定义动作、按键规范化与焦点目标（终端、组合输入、失活）。组合输入期间不处理终端快捷键，未配置的普通 Ctrl+C 仍发给前台程序；备用屏幕保留历史导航按键给程序。
- `src/tasks.rs` 提供可唤醒的取消令牌和最新任务执行器。容量为一个运行任务、一个待办输入、一个结果；替换请求先失效旧版本并取消旧任务，旧结果不能提交。
- 字体请求防抖 40 ms，字号限制 4–200 逻辑像素。复位回配置字号；字号增量不写回配置，配置热更新保留当前缩放增量。未使用字体更新时不创建工作线程；首次使用后复用一个阻塞等待的工作线程。
- 配色和内边距变化复用字体与字形缓存。字体提交后统一重算网格、PTY 和候选框坐标；网格发生重排时清除无法保证定位正确的旧选区。保留历史内容，历史仍受原有预算约束。
- `[keybindings]` 支持最多 128 个自定义组合键；发送文本每项最多 8 KiB。错误项提示并保留其他有效项，规范化后重复的组合键提示冲突。`none` 消费按键，`pass-through` 交给 VT 编码。macOS Copy/Paste 菜单点击仍可用，键盘组合统一交给配置分发。
- `[appearance] theme` 支持 `dark`、`light`、`midnight`。终端前景、背景、光标、选区、16 色和预编辑背景均来自主题；`[colors]` 显式覆盖在循环切换主题后仍保留。
- 按需资源快照汇总网格容量、历史负载、组合符字符串、输入/输出队列、帧缓冲容量、字形/整形缓存负载、活跃字体文件所有者字节数和字体任务槽位。统计不进入每次输入/绘制的热路径。
- 配置监视器关闭时通过条件变量立即取消等待；不再依赖等待下一秒轮询才退出。

默认 `Primary` 为 macOS 的 Cmd，其他平台的 Ctrl+Shift：`Equal/Plus` 放大，`Minus` 缩小，`0` 复位，`F6` 循环主题，`F12` 在终端显示资源快照。复制/粘贴和历史导航保留原默认值；完整例子见 [默认配置](../assets/congminal.example.toml)。系统占用的组合键仍受操作系统约束。

## 边界与后续目标

资源快照是分项负载/容量统计，尚不是 512 MiB 的全局内存准入实现，也不等于 RSS。容器桶元数据、原生窗口表面、系统库、临时对象和子进程需单独计量。字体文件字节数包含只读映射与读取回退，按所有者计算，不把每个切片重复计入；映射大小不代表全部驻留。

取消是合作式的。正在执行的文件系统调用不会被强制中断；加载前后检查取消，UI 不等待线程 join，旧结果释放后处理最新请求。当前渲染字体和最多一套后台字体可暂时共存，因此字体更新不是零内存成本。工作线程闲置后保留供复用，使用条件变量等待。

本轮没有引入第三方包或新外部运行程序；性能与候选安排见 [M1 评估](evaluations/m1.md)。SSH/SFTP/Git 后端尚未选定，必须在各自阶段完成候选测量后接入。

下一目标为 M2：先实现有界、可取消、分片扫描的纯文本历史搜索，再实现 OSC 8 与可见 URL 的显式打开。M3 建立 Shell 目录/命令边界和通知事件；M4 在全局账本落地后开放多会话、分屏与左右侧栏；M5–M8 依次接入 SSH、SFTP、Git/监控与美化完善。

## 验证与限制

验证数据与可复现命令记录在 [M1 评估](evaluations/m1.md)。单元/真实 PTY 回归覆盖了组合输入、焦点、中文、主题切换、连续缩放/复位、取消过期任务、满输出队列关闭及退出前排空尾部输出。

Windows/Linux 的键盘适配已做交叉编译与 Clippy 检查；三平台真机输入法、鼠标/剪贴板组合操作及动态 DPI 仍需后续运行验证。短期重复切换测试不替代 30 分钟压力验收；未完成这些项目时，不将整个 M1 标为跨平台完整验收。
