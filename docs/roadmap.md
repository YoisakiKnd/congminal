# congminal 功能开发计划

更新日期：2026-10-20

状态：基础加固及 M1–M3 已实现并完成本机验证；跨平台运行、系统通知与长测的待验收项目单独列出，M4–M8 继续按计划推进。

目标：在现有终端内核上构建支持本地与远程工作的跨平台终端工作区，持续控制内存、交互延迟和后台开销。

## 1. 范围与约定

- 将“左右侧行”按“左右侧栏”规划：左侧导航与资源，右侧上下文工具；均可隐藏、切换和调整宽度。
- 允许第三方 Rust 包、系统库和外部程序；接入前必须明确并测量启动、交互、吞吐、内存和后台成本，遵循 [第三方依赖与适配策略](dependency-policy.md)。未验证或不能达标时，先优化/更换方案，否则自行编写相关适配或必要组件。核心本地终端独立可用。
- SSH 优先比较系统 OpenSSH 与成熟库；加密、认证和主机验证使用经过维护的实现。自写范围优先是会话、进程/通道、调度与数据适配，不因性能问题直接自写密码学。
- 每个里程碑交付可运行的完整流程，包含配置、取消/关闭、失败状态和测试。实现项与验收项分别勾选；实现完成不表示所有平台验收均已通过。
- 本文的容量、刷新频率和性能数字是新功能的初始设计目标，应在实现时测量、校准并记录，不代表当前代码已经具备这些限制。

## 2. 现有基础

第一批 I/O 与资源边界加固已在工作区完成，详见 [底层加固说明](foundations.md)。包括 PTY 背压、异步输入、有预算的输出处理、历史和缓存预算、字体映射释放，以及解析边界和回归测试。

已有基础仍需持续回归。Linux、Windows 的交叉检查不能代替运行时测试；完整字素分段、动态 DPI、协议兼容性和长时间压力验证继续纳入计划。

## 4. 工作区布局

```text
┌───────────────────────────────────────────────────────────────┐
│ 标签栏 / 新建会话 / 工作区操作                                 │
├────────────┬───────────────────────────────┬──────────────────┤
│ 左侧栏     │ 终端区域                      │ 右侧栏           │
│            │                               │                  │
│ 会话       │ 本地 / SSH                    │ Git              │
│ SSH 主机   │ 左右 / 上下分屏               │ 系统与会话监控   │
│ 本地文件   │ 搜索栏与匹配定位              │ 传输状态         │
│ SFTP 文件  │                               │ 通知中心         │
├────────────┴───────────────────────────────┴──────────────────┤
│ 当前目录 / 主机与连接状态 / 分支 / 命令状态 / 后台任务         │
└───────────────────────────────────────────────────────────────┘
```

- 左栏默认显示会话与主机；文件浏览根据当前会话切换本地或 SFTP。
- 右栏按当前活动会话展示 Git、监控、传输和通知，不同时持续刷新所有工具。
- 小窗口优先保留终端面积，侧栏可收起或以临时面板显示；左右栏互不强制依赖。
- 搜索栏、侧栏和终端有明确焦点归属；在界面中输入时不会把按键发送给 shell。
- 本地、远程会话和远程路径有清楚标识，所有面板数据携带会话 ID，切换后不得显示旧主机结果。

## 5. 架构与依赖

### 5.1 在现有代码上逐步拆分

- `Session`：拥有终端状态、解析器、PTY、输出队列、选区、搜索和命令标记；每个会话独立关闭和取消。
- `Workspace` / `Tab` / `Pane`：管理会话引用、分屏树、焦点、可见性和布局；布局数据不拥有或复制终端历史。
- 窗口层管理统一帧缓冲与绘制区域；只向窗格可用内容区域计算终端行列，叠加界面不写入终端网格。
- 增加轻量 UI 组件：标签栏、文本输入、列表、可拖动分隔线、面板和通知；先复用现有软件渲染与输入法桥接。
- 字体映射、同字体/字号的字形资源按需共享，由资源管理器负责预算；避免每个标签重新扫描和加载完整字体库。
- `ConnectionProfile`：本地/SSH 参数与界面配置，保存非敏感元数据；认证交互由独立流程处理。
- `BackgroundTask`：搜索、Git、目录读取、监控、传输通过工作线程返回结构化结果，包含任务 ID、会话 ID、版本号和取消信号。
- 后台结果过期时丢弃；配置、当前目录或连接代次变化后，旧结果不能覆盖新状态。
- `ResourceManager`：提供全局预算、任务并发、历史与缓存淘汰、统计与诊断；在多会话上线前接入。

先移动现有职责并保持行为测试通过，再增加抽象；不重写已验证的 VT、网格、字体和渲染算法。

### 5.2 主要依赖关系

| 能力 | 依赖 |
|---|---|
| 缩放、主题、快捷键 | 动作分发、配置扩展、字体缓存失效 |
| 搜索 | UI 文本输入、历史定位、后台任务与取消、稳定行 ID |
| 标签与分屏 | Session 拆分、布局、焦点、全局资源预算 |
| 左右侧栏 | 布局与 UI 列表/输入组件；之后接入各数据提供者 |
| SSH | 会话生命周期、连接配置档、后端选型与能力检测 |
| SFTP | SSH 连接配置与认证、有界任务队列、远程文件模型 |
| Git | Shell 工作目录、本地文件模型、异步进程任务 |
| 监控 | 平台采样接口、远程执行通道、可见性与采样调度 |
| 通知 | 命令状态、连接状态、传输和监控的结构化事件 |
| 美化扩展 | 主题系统、布局、平台合成能力与绘制性能基线 |

### 5.3 第三方依赖与自写适配

第三方包和外部工具都是可选实现，本文出现的 OpenSSH、Git CLI、自写 SFTP 适配不表示已经完成选型。接入前先做同功能原型和五次以上交替测量，记录本进程与子进程的合计成本。后端通过内部接口接入，避免业务代码绑定包的数据结构。

未确认影响时标记未验证，不进入默认发布路径；优化后仍不满足预算，则改用轻量候选或自写适配。具体指标、门槛和评估模板见 [第三方依赖与适配策略](dependency-policy.md)。

- [x] 实现上一条/下一条命令跳转、选择和复制命令输出；记录耗时和退出码，标记与历史共同淘汰。
- [x] F12：应用内通知中心、平台系统通知接口、静音与事件类别开关。
- [x] 长命令完成、失败和后台状态变化生成通知；前台短命令成功默认不打扰，同一事件只通知一次。

实现与边界见 [M3 执行记录](execution-m3.md) 和 [性能数据](evaluations/m3.md)。

- [ ] 补 Bash 4.4+、Windows/Linux 运行、真实系统通知权限/送达/峰值内存、三平台输入法及 30 分钟长测；系统工具适配默认关闭，尚未通过依赖发布门槛。

验收：命令取消、非零退出、异步提示符、备用屏幕与 shell 退出不生成虚假成功；不根据提示符文本猜测退出码；通知不抢键盘焦点、不暴露认证内容。

### M4：多会话、分屏与左右侧栏

- [ ] F06：多标签与上下/左右分屏，独立 shell/PTY、标题、选区、历史和关闭状态。
- [ ] 支持新建、切换、关闭、标签重排、焦点切换及分隔线拖动；关闭一个窗格不影响其他会话。
- [ ] F07：实现可隐藏的左右侧栏、状态栏、宽度拖动、窄窗口适配和布局保存。
- [ ] 左栏接入会话列表、连接配置档和本地目录浏览；右栏先接通知与基础会话状态。
- [ ] 全局历史、字形缓存、网格、后台任务预算正式接入；将 M3 压测发现的重排临时缓冲/分配器 RSS 高水位纳入准入与复用评估；隐藏会话只维护状态，延后绘制。
- [ ] 布局恢复保存非敏感元数据；恢复 UI 不自动重新执行历史命令或恢复旧输入缓冲。

### M5：SSH 主机管理与远程会话

- [ ] F08：主机配置档支持名称、分组、目标、用户、端口、密钥路径和关联主题；先比较 OpenSSH 与成熟库，外部程序后端支持指定路径。
- [ ] 支持选择系统 SSH 配置中的明确主机别名；OpenSSH 后端委托工具展开 Include/Match、ProxyJump 等配置，库后端需通过兼容适配与对照测试，不能静默忽略不支持的配置。
- [ ] 通过 SSH 后端接口连接现有终端会话；OpenSSH 候选通过 PTY 启动，库候选适配有界通道；两者均保留认证和首次主机验证的交互，优先复用密钥与 agent。
- [ ] 连接状态区分启动中、认证中、活动、断开和失败；无法可靠判断的状态不猜测。
- [ ] 提供显式重连、连接耗时与错误信息；重连创建新的连接代次，不重放未发送输入或历史命令。
- [ ] 各 SSH 后端都执行主机密钥校验，并遵循所选配置与已知主机记录；应用不默认关闭校验。配置档不存明文密码/私钥内容，诊断输出隐去认证信息。
- [ ] 后续增加跳板机/转发配置界面；连接复用按平台能力启用，不以某个平台的 ControlMaster 支持作为跨平台前提。

验收：覆盖密钥、agent、交互密码、错误主机、拒绝连接、主机密钥变化、网络中断、跳板配置和工具缺失；连接取消与失败后进程、线程、句柄和队列释放。

### M6：SFTP 文件浏览与传输

- [ ] F09：为活动 SSH 会话关联独立的 SFTP 通道；比较成熟 SFTP 库与 OpenSSH 子系统加有界协议适配，按吞吐、峰值内存、取消和维护成本选型；使用自写协议适配时先限定并验证 SFTP v3。
- [ ] 目录列表使用结构化协议，不解析人类可读的 `ls` 输出；首版支持路径跳转、上级目录、隐藏文件、排序与手动刷新。
- [ ] 实现流式上传/下载、目标选择、进度/速度、取消、失败重试和传输任务列表。
- [ ] 非交互后台通道首版优先密钥/agent；需要新的交互认证时转到可见认证流程，密码/口令交互接入后使用短生命周期凭据通道。
- [ ] 普通 shell、SFTP、远程监控与 Git 各用独立通道，不能混写终端 stdin/stdout；连接配置相同不等于已自动共享认证连接。
- [ ] 远程文件打开采用有大小限制的临时下载和显式回传；不在浏览目录时批量下载文件。
- [ ] 第二步增加新建/重命名/删除、递归传输与续传；覆盖、删除等操作显示明确的主机与路径，批量操作先列出影响范围。
- [ ] 上传尽可能使用临时文件再提交最终名称；取消/失败可识别残留临时文件。续传只有在协议能力和文件状态验证通过后才提供。

验收：大于内存预算的文件可传输，内存不随文件大小增长；中文、空格、换行、前导短横线、符号链接、权限不足、大目录、断线、取消和磁盘满有正确行为；部分文件不会显示为传输成功。

### M7：Git 与状态监控

- [ ] F11：根据活动会话工作目录识别仓库，读取分支、暂存/未暂存/未跟踪文件及变更数量，提供受大小限制的 diff 查看。
- [ ] 比较 Git CLI 与成熟 Git 库；CLI 候选使用稳定、NUL 分隔的机器输出，库候选转换为同一文件模型；先交付本地只读状态，兼容 worktree、子模块、detached HEAD 和未初始化仓库。

## 7. 内存与性能约束

### 7.1 全局预算优先

多会话不能简单复制当前单会话上限。先引入进程级的受管资源账本，再开放标签和分屏。以下为初始目标：

| 项目 | 初始目标 | 到达上限后的行为 |
|---|---|---|
| 受管堆资源总额 | 默认 512 MiB，可配置合理范围 | 先淘汰非活动历史和可重建缓存；仍不足则拒绝新任务/会话，保留活动会话 |
| 历史 | 全局 128 MiB，单会话不超过现有 64 MiB | 优先回收非活动会话最旧历史，并使相关选区/搜索/命令标记失效 |
| 字形与整形缓存 | 全局初始 64 MiB | 共享可复用数据，按预算淘汰，不能按窗格数无限倍增 |
| 会话/可见窗格 | 默认最多 16 个会话、8 个可见窗格 | 明确反馈容量限制；上调前重新检查总预算 |
| 搜索 | 每会话缓存最多 1024 个定位结果，全局最多 8192 个；约 2 ms/片 | 增量扫描/跳转，取消旧查询；更多结果按需发现，显示数量是否完整 |
| 命令标记 | 单会话最多 4096 条、全局最多 16384 条且合计不超过 4 MiB | 随历史淘汰，超限清理最旧标记，不影响命令实际执行 |
| SFTP | 默认 2 个活动传输、64 个排队任务；共享传输缓冲初始 16 MiB；单包 1 MiB、每连接最多 32 个在途请求 | 排队或拒绝新任务，文件内容始终流式处理 |
| 目录/Git/diff | 共享缓存初始 32 MiB；单目录最多缓存 10000 项且不超过 8 MiB；单次 diff 初始 8 MiB | 虚拟列表、分页/增量读取、明确截断，按需加载 |
| 监控 | 默认 1 Hz，保留最近 5 分钟；同指标至多一个在途采样 | 合并/跳过过期采样；隐藏时停止或降频，失败后退避 |
| 通知 | 最多 1024 条且正文合计不超过 1 MiB | 聚合重复事件，淘汰最旧记录，批量任务合并提示 |

各分项是天花板，不是预分配配额；同时受总账本限制。增加总预算不能解除队列、单包、单文件、并发和超时限制。现有帧缓冲/网格上限继续有效，并在多会话版本纳入总账本。

受管堆预算不等同于整个进程 RSS：只读字体映射的驻留页、系统窗口表面、平台运行库和 ssh/git/shell 子进程内存需另行测量。字体映射增加数量/地址空间统计，子进程增加并发和生命周期约束；验收报告同时记录受管资源、RSS 高水位和子进程占用。

### 7.2 调度与绘制

- 搜索、网络、磁盘、Git 和监控不得在 UI 线程执行阻塞 I/O；队列有容量、超时、取消和过期结果处理。
- 活动终端输入优先；各会话轮转消费输出，单个高速输出会话不能占满全部处理时间。
- 只重画变化且可见的区域；侧栏图表、光标动画和进度条各有刷新上限。
- 列表按可见行绘制，日志和结果按大小限制；不要为搜索、diff、传输或通知复制完整历史/文件。
- 文件/网络任务使用有界工作池，不为每个文件、仓库或采样创建永久线程。
- 日常回归至少交替测量三次取中位数；依赖选型至少五次，并按 [接入门槛](dependency-policy.md#32-判定标准) 检查：既有路径稳定回退超过 5% 或输入 P95 增量超过 1 ms 时，先优化重测，仍不达标则替换候选或自写适配，不静默放宽预算。
- 性能目标是交互可预测与资源稳定；约 2 ms 的合作式时间片不视为严格实时保证。

## 8. 跨平台与数据正确性

- macOS、Windows、Linux 保持同一功能模型；平台差异通过能力检测和平台接口呈现。
- UI 文本输入复用输入法预编辑/提交逻辑；同时补动态 DPI 变化，保证侧栏、分屏、搜索输入与候选框坐标一致。
- 所有异步结果明确来源会话、主机和连接代次；路径、文件名和命令参数通过结构化参数传递，不直接拼接到 shell 命令。
- 路径模型保留系统原始表示；显示不可解码文件名时不能破坏后续操作的目标路径。
- 接入 OpenSSH 和 Git 前检查可执行程序与必要能力；工具缺失、功能不支持、数据未知、结果截断和连接失效各有不同状态。
- 工作区恢复只还原布局和可选配置引用；认证状态、命令输入和正在传输的数据不当作可恢复的普通配置保存。
