# M6：SFTP 独立通道与流式操作原型

当前`src/sftp`可由测试或显式的Unix `sftp-preview`主程序编译，普通构建不启用。最新进度：本地上传源选择补充：已加入共享工作池的有界本地选择器，保留原名字节并转义显示，选择后仍经后台源检查和完整审阅；不新增目录线程或 SSH 连接。普通521项、预览524项及helper18项通过，三目标静态检查与Rust1.88工作区39项通过；实际入口选择到上传下载，以及16类既有文件流程真实回环通过。512项目录的200次预热直接绘制零新增分配，P95约0.078ms；原16MiB池/9MiB IO余量保持，探针结束SFTP额度归零。[实现、证据与边界](evaluations/m6-sftp-local-picker.md)。此前实验ZIP未重打包，不包含本轮选择器；完整M6不勾选。下一步补慢文件系统取消/退出、原生焦点输入与传输及下载目标选择；M4完整账本、M7/M8、终端兼容和三平台长测继续按原目标执行。以下阶段按历史保留。

已实现 SFTP v3 结构化编解码、增量帧解析、32 项请求窗口、来源会话/代次标识、路径原名字节与转义显示、目录分页，以及顺序流式上传/下载原语。文件数据使用独立 `Read + Write` 通道，从不送入终端解析器。通道读写只能在后台，协议原型仍依赖下层提供可取消 I/O；原生候选已另行实现非阻塞 socket、可结束的 DNS 辅助进程与等待取消。不能把协议层合作式取消标为所有后端均已完成网络取消。

协议包体上限 1 MiB，路径 16 KiB，句柄 256 字节，数据块 64 KiB；NAME 页最多 8192 项。未知/重复请求编号、错误回复类型、伪成功及超限数据会使通道失效。单目录工作集先预留 3 MiB，最多展示 512 项、扫描 8192 项，达到上限或遇到不可导航名称时标明不完整；不会通过空 NAME 页推断 EOF。目录排序使用原名字节，控制字符、双向控制及无效 UTF-8 只在显示层转义；操作继续使用原名。

上传对唯一临时路径排他创建，逐块等待 ACK，验证输入长度及远端大小，支持服务端宣告的 fsync，收到关闭 ACK 后才提交重命名。默认 v3 不覆盖；显式覆盖要求协商出的 POSIX rename 能力。失败或取消保留可识别的临时文件，旧目标不会被静默覆盖。临时名生成、主机/路径确认、任务队列与重试界面尚未实现。

下载先验证大小，按实际短读推进，要求读足并收到 EOF，再复核大小、关闭句柄和刷新调用者提供的暂存输出。源文件不足、变长、本地写入/刷新错误均不能报完成；同大小内容变化还需要上层文件身份与时间/校验策略。本地文件的原子提交、fsync 和最终目标选择仍由后续文件任务层实现，目前没有自动打开或回传文件。

协议与流式原语阶段已执行：标准 debug/release 各 334 项通过、20 项忽略；macOS 本机、Linux GNU 与 Windows GNU all-target Clippy 无告警。另手动运行 4 项本地 `sftp-server` 互操作，覆盖原名字节、属性、目录/文件操作、扩展协商、32 MiB 流式文件、短写、原目标保留、源不足、临时名冲突、取消和零字节提交。32 MiB 大于 8 MiB 测试预算，操作受管峰值 140514 字节，结束归零。账目包含缓冲预留，不等于全部堆或 RSS。

## 原生会话接入进度

可选 `sftp-libssh2` 功能已加入 `libssh2-sys = 0.3.3`，锁文件包含 9 个包（本机正常依赖 4 个，另有构建工具）；默认功能为空，`cargo tree --edges normal` 仍只有项目自身。功能开关目前用于编译原生会话测试，界面尚未启用。启用时需要 C 编译工具与平台加密库开发环境；目前 macOS 实际构建使用 vendored libssh2 / OpenSSL 4，Windows/Linux 原生开关仍待真机构建及运行验收。

`src/sftp/native.rs` 统一持有会话、SFTP 与最多 32 个句柄，不把 C 指针交给业务层。令牌含连接唯一编号和槽代次，文件/目录误用、跨连接令牌、关闭后旧令牌在调用 C 前拒绝。一个连接保留一个文件流，数据调用最多 64 KiB；原生库内部预取的在途请求上限仍需结合调度层验收，不能把 32 个句柄当成 32 个在途请求。

会话接受已经建立的 TCP 流，主机记录先于认证验证；支持普通/哈希记录及有无结尾换行，遇到不支持的 CA/撤销标记明确拒绝。严格区分主机记录缺失、不匹配、凭据处理失败与服务端认证拒绝。认证密钥副本先准入、NUL 终止，调用返回前清零并释放；口令只借用当前调用的 CStr，不写入配置或会话字段。原生 socket 与库均非阻塞，poll/WSAPoll 只在活动请求等待网络时执行，检查取消和单次操作期限，空闲不启动循环。

`finish` 显式报告清理结果，先 shutdown，再按句柄、SFTP、会话顺序释放；不能清理的原生块保留其上下文和已收费额度并返回清理错误，不虚报归零。构造失败同样执行该检查。目录与协议原型共用限量、排序、原名和转义模型。

隔离工具已通过 13 类真实 Rust 会话场景：普通与哈希主机记录、加密测试密钥、错误口令、未知/变化/撤销记录、错误密钥、超大 NAME、畸形名称、取消、EOF、超时；未知/变化/撤销记录没有进入认证请求。最终正向用例补验旧令牌、类型误用、跨连接令牌、配额拒绝后原连接继续读取、32 MiB 内容比对与不覆盖已有目标。结束均归还受管额度。原始记录：[全场景](evaluations/m6-sftp-native-session.json)、[最终正向](evaluations/m6-sftp-native-session-positive-final.json)、[构建](evaluations/m6-sftp-native-session-build.json)。

## 可取消解析、TCP 建立与配置结果模型

`src/resolve.rs` 增加同程序内部解析模式，先于配置读取、字体和窗口初始化运行系统解析。父任务先预留 256 KiB，只接收最多 16 个去重地址、520 字节的固定二进制结果，检查端口、地址族、作用域、保留位和完整长度。解析最多等待 5 秒，取消/超时结束并回收自己启动的辅助进程；数值地址直接构建结果，不启动解析进程。系统解析器自身的内存属于辅助进程，单独采样，不算作父进程受管账目。

地址缓存最多 16 个目标、60 秒有效期，固定预留 32 KiB，按最近使用淘汰，命中不延长有效期；只缓存成功结果，支持显式失效。命中时仍先取得调用方的结果额度；数值地址不进入缓存。测试覆盖淘汰、过期、取消和额度不足，不以缓存绕过主机密钥检查。

`src/sftp/connect.rs` 使用非阻塞 IPv4/IPv6 socket，最多同时保留两个候选连接，下一地址通常延迟 200 ms 发起，失败时立即推进；包括解析在内总期限 30 秒。返回前关闭其他候选。Unix 关闭执行继承标志的设置及自有 PTY fork 通过短临界区协调，锁外执行网络等待；DNS 管道创建同样协调。Windows 实现使用不继承 socket 与 WSAPoll，但尚未做原生功能构建/真机验收。此处还未完整实现 RFC 8305 地址族交替与排序，不能称为完整 Happy Eyeballs。

真实回环工具已通过 14 类场景（新增 localhost）、IPv4/IPv6、拒绝后地址回退与 Unix 描述符标志检查。全部正向及故障用例继续归还额度；[缓存完整回归](evaluations/m6-sftp-connect-cache.json)。进程创建锁改动后，实际 PTY SSH 五轮连接及手动重连通过，[回归记录](evaluations/m5-ssh-connect-guard.json)；这不是 GUI 输入延迟验收。

`src/ssh/settings.rs` 暂仅编译进测试，为系统 `ssh -G` 结果提供最多 128 KiB、512 字段、单行 16 KiB 的模型。副本与索引分配前准入；保留全部选项、重复项顺序和路径原值，不自行执行引号/变量或代理命令。与同版本基线比较时，尚未由调用方处理的变化、未知及缺失字段都返回明确字段名，不输出值。目标提取不等于这些选项已适配原生后端；未来必须先处理算法、主机记录、代理等语义，才能允许连接。

隔离生成的真实 OpenSSH 输出已核对 Include、Match originalhost、ProxyJump、HostKeyAlias、带空格路径及多 IdentityFile 顺序；受管峰值 173165 字节（包含测试输入与两个结果），结束为零。[真实配置结果与域名连接](evaluations/m6-sftp-settings.json)。当前工具只生成受控配置，没有执行用户的 Match exec；Unix 捕获与组内取消已在下节补验；Windows 监督、普通应用接入及脱离原进程组的后台程序管理仍待完成。

最新默认 debug/release 各 345 通过、22 忽略；原生开关各 350 通过、24 忽略。macOS 默认/原生及 Linux/Windows GNU 默认 all-target Clippy 无告警，Rust 1.88 原生 release 测试编译通过；GNU 交叉检查不包含原生 C 依赖或真机运行。证据见 [构建与完整回归](evaluations/m6-sftp-connect-build.json)。完整 M6 交付继续保留未勾选，尚未进入普通应用的 SFTP 使用路径。


## Unix 系统配置查询监督

`src/ssh/capture.rs` 与 `settings::query` 已在测试模块接通真实 OpenSSH 配置查询。argv 分项传递，目标/用户/端口/密钥参数复用配置档验证；支持系统配置、`-F none` 和显式配置文件，单独区分程序缺失、权限、输出超限、非零退出及配置结果错误。`query` 验证必要目标字段后才返回。System 查询会遵循用户的 Match exec，不能当作无副作用的纯文件解析；当前没有在普通应用里自动调用。

捕获工厂只在工作额度准入后执行。工作预留 256 KiB，输出先预留最多 128 KiB＋128 字节元数据；通用命令上限 64 参数/总参数 16 KiB，配置查询期限 5 秒。stdin 和 stderr 定向空设备，不采集认证输出；stdout 使用非阻塞管道，越界时拒绝并清理，不积累整个输出。捕获结果与后续 Settings 副本/索引各自持有额度，分配重叠也计费。预留不等于全部 std/系统分配的实测堆上限。

Unix 命令独立进程组，使用 WNOWAIT 观察主进程结束，先结束受控组再回收 PID，避免向已经复用的组发信号。普通错误路径也检查清理结果，Drop 用作异常兜底。它覆盖正常继承进程组的子程序；自行 setsid、改变身份或权限的后台程序仍不能宣称得到完整树级管理。上一阶段 Windows 仅返回 Unsupported；本轮已补实现并交叉链接，状态见下节，仍不能用交叉编译替代真机验收。

修复了 Darwin 仅剩 zombie 主进程时组信号返回 EPERM 的情况：只在确认组内唯一成员就是尚未回收的已退出主进程时接受；其他权限错误继续报清理失败。单元验收覆盖精确输出边界、持续输出超限、非零退出、取消/超时、提前关闭 stdout 的长命令、主进程退出后子进程仍持管道，以及额度归还。

等待输出使用 poll；EOF 通常略早于进程退出，先给予两次最多 100 µs 的短等待，此后恢复最多 5 ms 的合作式等待，避免关闭 stdout 的长任务持续快速轮询。没有新增后台线程或依赖包；该模块尚只编译进测试，不代表普通应用已经能用 SFTP。

真实隔离配置核对 Include、Match、ProxyJump 和路径顺序；另以自建 `Match exec "sleep 30"` 验证约 57 ms 后取消，5 ms 采样未观察到派生进程残留。五轮交替对照中位：直接查询并构建同一模型 5.43 ms，有界监督查询 5.87 ms；初始化工具/文件缓存已热，样本不能当作跨机器保证。初版约多 5 ms 的固定等待已保留在早期记录，最终没有把开销写成零。受管峰值 456532 字节包含测试保留的基线、配置结果、输入及查询工作预留；结束归零。配置测试进程树观测峰值 14925824 字节，不是精确 RSS 峰值或完整 GUI 成本。

证据：[最终查询、取消与域名连接](evaluations/m6-sftp-query-supervisor.json)、[初版](evaluations/m6-sftp-query-supervisor-initial.json)、[只改管道等待的中间版](evaluations/m6-sftp-query-supervisor-poll-initial.json)、[当前构建与回归](evaluations/m6-sftp-query-build.json)。后续优先完成 Windows 捕获，再把配置选项、主机记录与认证落实到实际 SFTP 会话；目录界面、队列、原子提交、三平台及长测继续待办。

## Windows 捕获实现与可运行验收包

已移除 Windows 捕获占位实现。`capture_windows.rs` 使用创建属性同时设置 Job 与标准句柄白名单，Job 设关闭时结束成员且未启用 breakaway；创建失败直接报错，不回退为脱离 Job 的子进程。主进程退出后也结束 Job，查询 ActiveProcesses 归零才报告清理成功；清理额外期限 2 秒，失败保留明确清理错误并由关闭 Job 兜底。持有进程/Job 句柄，不按已经回收的 PID 发结束信号。输出只由唯一读端按 PeekNamedPipe 已可用字节读取，保留原有输出/工作额度上限，不建立读线程。

`Spec` 统一两平台的程序和独立参数，不提供隐式 shell、环境改写或工作目录。Windows 只运行 exe；裸程序名按明确 PATH 搜索，不隐式优先当前目录，显式相对路径按系统绝对化。参数保留原 UTF-16（包括未配对代理码），转义引号/反斜线，拒绝 NUL 和超过 32767 单元（含结尾）的命令行。编码器用独立向量核对，真实 CRT 还需在目标机跑 C 测试程序。临时可继承句柄在短创建锁内处理，读取、网络和等待都在锁外；Windows 固定 SSH 检查/解析辅助创建也参与该锁。Unix 普通 SSH 检查保持原来的创建路径，当前捕获/解析模块进入 UI 前仍需验收创建锁与主线程新窗格启动的交互延迟。

C 测试程序用目标 SDK 的编译期断言核对 Windows x64 结构大小、偏移、属性/标志及信息类别；完整 Rust 测试程序已交叉链接成 PE。验收包在 `target/windows-capture-validation/`，包含 `tests.exe`、`fixture.exe`、`run.ps1` 和 `manifest.json`。测试覆盖真实 CRT 参数（空值、空格、引号、反斜线、中文及原始 UTF-16）、二进制输出/非零退出、超限、超时、等候标记后取消、以及主进程退出而派生进程持管道。派生进程先证明进入等待阶段，不能因提前退出而误报清理成功。脚本只有确实运行 1 项、退出为零且看到 final=0 标记才设置 native_runtime_verified。

## 配置核心字段、路径与认证文件输入

`ssh/paths.rs`、`sftp/files.rs` 和原生 Verification 已接成后端测试链路：实际 OpenSSH -G 查询的 HostName/User/Port/HostKeyAlias、明确单值的主机记录路径及 IdentityFile，先展开路径，再限量读文件，交给独立 SFTP 会话。界面、完整配置策略与认证交互尚未接入，不能把这两个受控配置对照当成任意系统配置已经兼容。

路径不经过 shell，保留原名字节；支持当前用户 tilde、%%、%d/%h/%n/%r/%p/%k 及调用方有界环境快照提供的 ${NAME}。最多 16 KiB，临时工作先预留 64 KiB，完成后释放中间值并缩到输出实际容量；没有分配等量固定缓冲或启动线程。~otheruser、连接哈希等尚未支持的 token 返回 Unsupported，缺失环境值、NUL、超限和取消分别报错，不返回半截路径。非 UTF-8 home 的纯路径测试通过；Windows 原生路径行为仍需验收。

文件层单文件最多 1 MiB，只读普通文件；Unix 打开时使用 nonblock/CLOEXEC，以免 FIFO 等特殊输入先挂住后台任务。路径/File/Metadata 工作先预留 32 KiB，普通数据按句柄 stat 的大小＋1 哨兵及 128 字节元数据准入，读取按 64 KiB 分段检查取消，检查短读、额外数据及前后大小/修改时间变化。它能检测常见并发变化，不宣称是防伪造的原子快照；同步文件系统调用本身仍可能阻塞，不能将分段取消当作网络文件系统的硬超时。文件读取只供后台调用。

私钥输入不实现 Debug/Clone，拥有者释放前 volatile 清零，再释放数据和额度。当前用户拥有的 Unix 私钥按 [OpenSSH 权限规则](https://github.com/openssh/openssh-portable/blob/master/authfile.c) 拒绝组/其他用户权限；Windows ACL 核对尚未实现，原生私钥文件读取明确拒绝，不能借内存认证绕过验证。调用方应在认证返回后立即释放私钥输入，不放进配置或全局缓存；重复连接测试夹具为复验保留本地输入，其保守 4 MiB 预留和按大小收费的 Blob 均计入测试峰值。

修复了 HostKeyAlias=none 被误当成未设置的问题：它是字面别名。主机名和连接端口继续用于实际 TCP 连接，别名作为完整主机记录查找名，不再附加非默认端口；这与 [OpenSSH 查找行为](https://github.com/openssh/openssh-portable/blob/master/sshconnect.c) 对照。新的别名用例先验证变化的密钥被拒绝，再使用正确记录认证；%k 同样使用该别名。

另确认 -G 的 UserKnownHostsFile/GlobalKnownHostsFile 会失去原始引号，例如两条带空格路径被输出成一行。模型对含分隔符的主机文件值返回 AmbiguousPaths，不按空格猜测。明确单值和 none 可区分；保留多条 IdentityFile 的独立值及其顺序。完整系统配置尤其是多文件记录、代理、算法和其他认证方法仍需 OpenSSH 兼容通道，不能仅凭和默认 -G 输出相同就断言原生语义等价。

16 类真实回环场景通过，新增路径 token 和字面别名对照：系统 OpenSSH 使用同一生成密钥按 token 路径认证并返回 SFTP v3 VERSION，本程序通过查询字段、展开、文件输入和原生会话完成 32 MiB 内容核对。独立对照只连接自建 sshd 的 internal-sftp，不执行远端 shell。早期对照在 VERSION 前关闭 stdin 未收到回复，现改为收到 VERSION 再关闭；[早期记录](evaluations/m6-sftp-auth-path-oracle-initial.json) 保留。其他场景继续覆盖普通/哈希记录、加密密钥、错误口令/密钥、未知/变化/撤销主机、超大/畸形目录、取消、EOF 和超时。路径/别名正向受管峰值约 7.12 MiB（包含保守测试预留），结束归零，不能当成完整 GUI/RSS 成本。[16 场景及独立对照](evaluations/m6-sftp-auth-inputs.json)。

## OpenSSH 独立双向流兼容通道

`sftp/openssh.rs` 已将结构化 `ssh -T -s ... -- alias sftp` 接到 `capture::Stream` 和现有 SFTP v3 客户端。配置文件、Include/Match、身份、代理及主机记录仍由系统工具处理；不会把 -G 的扁平路径列表反解析成文件名。覆盖 ForkAfterAuthentication/RemoteCommand 以保持独立 subsystem 和受控前台进程，当前使用 BatchMode；已配置的密钥及 agent 可认证，新口令、首次主机询问及其他交互仍需可见认证桥接。没有接普通终端 stdin/stdout，也没有创建 PTY。后端继续仅编译进测试，尚未交付远端文件界面。

流工作预留 256 KiB，工厂在准入后执行，沿用程序/参数数量与长度边界。Unix 双端 nonblock，读写就绪使用 poll，取消检查间隔最多 5 ms。Windows 输出仍按可用数据读取，输入新增一个 OVERLAPPED 写槽、最多 64 KiB，单独按 State 大小＋128 字节收费；没有额外写线程或无界队列。管道使用随机名称、唯一实例及拒绝远程客户端，只有自身客户端读端参与子进程继承白名单。未完成 IO 的内核可变存储使用 UnsafeCell，稳定分配在请求完成前不移动或重借为独占引用。

Windows 取消先结束受控 Job，再取消并观察写入完成。依据 [CancelIoEx 的完成要求](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelioex)，不能在仅发出取消后释放 OVERLAPPED/数据；额外观察最多 2 秒，若系统仍未完成则报 Cleanup，并保留对象及额度，避免悬空指针和虚假退额度。正常完成后释放写槽；异常保留不是成功清理。该分支仅交叉构建，尚无 Windows 实际运行证据。

timeout 当前限制单次 Read/Write 等待，最多 30 秒；持续收到零碎数据可能延长整个协议操作，不能宣称已有整次传输的硬期限。调用方的任务取消控制总生命周期，显式 finish 报清理失败，Drop 只兜底。Unix 仍只覆盖继承原组的派生程序；自行脱离组的用户代理程序管理继续待办。创建锁与主线程新窗格启动的交互延迟也仍是 UI 接入前门槛。

真实拒绝场景补出了 Darwin 的退出尾声竞态：管道关闭时 WNOWAIT 可能尚未报告退出，组信号返回 EPERM。现在先终止自己持有身份的主进程，在仍未回收 PID 的前提下等待退出可见；只有确认该组唯一成员就是退出主进程才接受该特殊情况，其他权限错误不忽略。[早期失败](evaluations/m6-sftp-openssh-stream-initial.json) 保留。另外修复流在进程结束时提前返回 EOF、遗漏已缓冲尾部数据的问题；回收后仍逐块排空输出，加入 8192 字节按 97 字节读取的专门回归。

15 类真实回环场景通过：普通/DNS 目标、路径 token、字面主机别名、哈希记录、独立 agent、未知/变化/撤销主机、错误密钥、超大/畸形目录、取消、EOF 及超时。每例配置都使用实际带空格的多主机文件路径列表，Include/Match 生效；agent 例禁用磁盘身份，只加载本测试生成的密钥，不访问用户 agent。六个正向场景分别完成 32 MiB 上传、短写输出下载及逐字节核对，上传临时名在 ACK 后提交。共享测试预算 8 MiB，正向受管峰值 3418157 字节（约 3.26 MiB，含目录工作预留），结束零；采样未观察到客户端子进程残留。[完整互操作](evaluations/m6-sftp-openssh-stream.json)。

默认 debug/release 各 363 通过、23 忽略；原生功能各 372 通过、25 忽略。默认三目标及本机原生 all-target Clippy 无告警，Rust 1.88 本机原生 release 测试编译通过。[稳定源码构建记录](evaluations/m6-sftp-stream-build.json)。这轮通过不关闭之前 SSH 并行时序问题的调查。
