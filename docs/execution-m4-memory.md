## 准入、回收与失败

- 票据随资源所有权移动，自动归还；只在分配、插入、清理和销毁时更新共享账本。缓存命中、逐像素绘图、逐字节解析及每笔队列写入不额外更新共享账本。
- 画布增长先预留新缓冲的完整额度，保留旧缓冲及票据，分配/复制成功后才切换并释放旧缓冲；同时存活的峰值受到准入限制。因此最终尺寸能容纳，并不保证增长瞬间也能容纳。拒绝时旧画布尺寸和像素保留。
- 新窗格先准备画布，队列在启动子进程之前准入。额度不足先清理可重建的字体缓存，再请求非活动历史回收，仍不足则拒绝创建。配额提交成功后才因增加会话数缩减旧历史配额；压力回收可以在创建失败前已淘汰部分非活动历史，这部分不会回滚。布局提交异常会关闭新会话并回到原结构；分配器或并发额度压力下画布恢复也可能需要重试。
- 队列容量在整个生产/消费周期中预留，满时继续使用原有背压，避免读线程因全局额度临时不足丢输出或永久等待。会话已从 UI 关闭时，后台线程仍可能持有票据，直到线程与在途块真正释放；不会提前将这部分额度算作可用。
- 已结束会话保留文本，但释放输出队列引用及 PTY。输入写线程和读线程结束后归还对应票据，避免只读窗格长期占满队列预留。
- 缓存插入遇到共享压力会淘汰本缓存的旧值；新会话/画布准入前也可清理整个共享字体缓存。票据改为每个缓存一张汇总票据，不增大原有 HashMap 条目。极端压力下仍无法容纳的缓存项会拒收，新字形/组合可能进入原有缺字或组合降级路径，不能保证低额度下视觉完全不变。
- 字体映射额度或数量不足时直接拒绝该字体，不改用完整堆副本来绕过映射限制。仅系统映射失败时才尝试有额度的堆读取。字体加载可按原有规则降级。旧字体与新字体在热加载期间共享账本，表切片不会重复收费。
- LatestTask 工作线程继承创建者的资源上下文；取消、过期结果和异常路径按拥有者释放票据。没有增加资源采样线程、定时唤醒或外部程序依赖。

拒绝次数包含缓存可选插入的重试，不等于丢输入或用户动作失败次数。缓存清空会释放值，但可能保留哈希桶容量；这也是目前混合计费尚不能当成完整堆账本的原因。

## 重排行索引优化

检查性能回退时补充了元数据分配优化：对没有软换行且内容放得下的硬行直接保留行号并转移缓冲，先淘汰无需保留的历史再扩宽；历史行取出时一次为屏幕行留出空间；逻辑行索引按实际硬行数量预留；输出行索引有界预留并在满时先淘汰后插入；将 VecDeque 输出索引转移给 Vec，避免再次 collect。保留原有逐行转移数据和宽字符/光标语义。1800 组对照案例现同时验证普通调用和携带预检结果的调用。

## 网格与缩放准入

网格预留为 `2 × ((rows + 1) × max(2 × cols, 32) × sizeof(Cell) + max(2 × rows, 32) × sizeof(Row))`，覆盖两个屏幕、保留容量以及滚动准备空行的重叠。缩小时限制行索引及 cell 的保留容量；从历史拉回行先移除屏幕尾行再插入，避免行索引无故翻倍。每次实际尺寸变化先保留旧预留，再申请完整目标预留；提交时合并两张票据后收缩，不经过先归还再抢领的空档。RIS 复位复用两个网格，不重复准入。

`Session::spawn` 在创建 PTY/子进程前准入并准备网格。缩放则先生成持有额度的计划，再准备画布，最后变更终端并发送规范化后的 PTY 尺寸。准入拒绝或画布申请失败会丢弃计划，保留原文本、光标、选区和 PTY 尺寸。工作区先为所有可见窗格拿到网格/重排额度，再修改任何窗格；后续画布分配或系统 PTY 调用失败仍沿用错误处理，不能把它解释成所有系统操作均具备事务回滚。

重排预留按同时存活的缓冲估算，不扫描 RSS。一般路径计未被持久票据覆盖的输入容量、最多保留的输出 cell、两个备用缓冲及索引扩容余量，不再为完整逻辑长行拼接保留四份输入；高度变化也预留历史索引增长。同步路径确认全部硬行可复用时直接转移，合用已准入输入额度，只额外申请 cell 增长差额、补屏幕空行及索引余量；该路径的 64 MiB 硬行历史可在 128 MiB 账本中与另外 20 MiB 预留同时反复缩放。UI 大历史路径避免这一全历史预检，旧源保持可读，按一般模型准入并逐步构造独立输出，**不享有同步硬行捷径的较低额度**。因此相同小账本下可能拒绝同步路径原本能完成的缩放；内存和完成成本需单独评估。

UI 交换后，新网格持有目标票据，旧网格票据随退休状态保留；临时票据直到旧历史和网格确实分片销毁才归还。取消时源未被取走，输出分片清理后再准入一个最新目标，不保留任务队列。作业进行中的重复布局只记录目标尺寸，真正开始下一目标时重新准入，**不承诺该排队目标已通过整组窗格原子准入**；若届时失败，保留现有终端，画布可暂时裁剪显示旧网格。资源快照的 history/grid 字段只汇总会话当前状态，准备和退休状态另由历史/重排/网格票据覆盖，不能把该字段当作作业实际堆总量。详见 [执行说明](execution-m4-reflow.md) 和 [调度评估](evaluations/m4-tick.md)。

历史维护 cell 容量的保守下界：接收行时降低下界，淘汰时允许偏低，清空/取走后重建。新宽度不超过该下界时只检查硬行条件，跳过逐行容量求和；不会因缓存偏高而漏算增长，也不在逐字符路径更新该信息。

## 持久历史与压力回收

历史使用每实例一张汇总票据，按 `sum(cell.capacity × sizeof(Cell)) + rows.capacity × sizeof(Row)` 收费，包含行索引未使用槽。普通增长以 64 KiB 聚合，无法拿到整块时尝试精确额度；索引扩容前保守覆盖旧新缓冲重叠，并允许分配器原地扩容。稳定满额滚动直接轮换旧行，不逐行改全局账本。被全局压力限制后继续复用现有行，每批解析至多尝试一次恢复增长，避免每个字符或滚动反复抢额度。批次结束只归还实际已释放的容量，允许保留不足一个块的余量。

工作区原有 64 MiB 历史池仍按 cell 容量加有效行描述符分配单会话额度；它不是包含空闲索引槽的完整堆上限。共享账本另计完整容量，因此不能把两个统计相加。重排消费时输入数据和票据一同移动；只读源继续持有其票据。已准入重排工作集原子转交新历史，不再二次争抢全局额度，也不提前归还尚在转移/退休中的行。

UI 重排在原输出索引中分片校验和裁剪，完成后直接交给历史，避免构造第二份完整索引；流式索引末次扩容受输出行数上限约束。大量淘汰导致容量超过保留行数两倍且超过 32 槽时，只分片搬迁保留后缀以收紧空表。索引重叠仍由现有保守工作集覆盖，没有通过减小历史配额换取峰值下降。对照数据见 [索引评估](evaluations/m4-index.md)。

压力先清理可重建缓存，再按轮转顺序回收未选中会话的最旧历史，包括未选中的可见分屏。当前选中会话和进行重排的会话跳过。每 tick 以约 500 µs 合作式预算推进，每个会话最多处理 4096 cell 工作量，单行销毁、固定上限元数据和分配器不可抢占，不是硬实时保证。没有可回收会话时停止唤醒；重排源等待作业结束后再处理。额度仍不足时允许拒绝新动作，回收可跨 tick 继续，原创建动作不会自动重放。

淘汰会更新丢弃水位和文本 revision、夹紧滚动位置，裁剪命令标记及链接；搜索/复制根据文本版本失效，已丢弃行的选区无法再解析。UI 显示回收提示，不向终端注入告警文本。

分配探针测的是 Rust 请求的额外存活字节，并对 realloc 计新旧重叠；它不是分配器可用块大小、RSS 或对任意未来算法修改的自动证明。历史计费、所有权测试与本轮同负载数据见 [历史计费评估](evaluations/m4-history.md)。此前网格边界见 [网格评估](evaluations/m4-grid.md)。

## PNG 解码准入

先借用输入验证块结构、CRC 和头部，计算所有 Adam7 pass 的精确解压长度 `expected`。大缓冲分配前申请 `joined + expected + rgba + 4096`：`joined` 仅在多个 IDAT 时计总压缩字节，单 IDAT 直接借用输入；解压输出一次性精确预留，逐块写出检查不能突破该长度，4 KiB 覆盖有固定上限的哈夫曼/码长堆缓冲。借用的输入本身不重复收费，其所有权仍由调用者或字体映射持有。

扫描行在解压缓冲内原地恢复，保留每行过滤字节和上一行跨度；每个隔行 pass 单独开始，不再为整个 pass 创建第二幅解过滤图像。多 IDAT 只在准入成功后精确分配拼接缓冲，第二次遍历已验证的不可变块，不保存随块数增长的索引。

所有临时缓冲实际销毁后，将票据缩到返回 RGBA Vec 的报告容量，随 Image 持有到像素销毁。错误/拒绝路径归还已拿到的额度；返回像素不能被外部模块直接扩容。Primary+F12 新增 `png-reserved`。没有改动 4 Mi 像素、32 MiB 输入和精确解压上限，没有新增包或线程。像素测试、拒绝/释放验证及性能数据见 [PNG 评估](evaluations/m4-png.md)。

本节的 PNG 阶段只覆盖解码及返回 RGBA。后续已接入图像缩放、轮廓/光栅化和 COLR，生成像素原子交给字形缓存；GSUB/PSF 索引及整形工作集也已接入。见 [缩放](evaluations/m4-scale.md)、[光栅化](evaluations/m4-raster.md)、[整形](evaluations/m4-shaper.md)。仍不解释成完整字体管线计费；解码/字形生成同步执行，额度上限不等于 UI 耗时上限。

PNG 准入不足会返回错误；字体调用可能进入原有单色/缺字或组合降级及缓存路径，当前不保证额度恢复后自动重试，必要时需清缓存/重新加载字体。跨模块的失败分类与恢复策略仍待统一。
