## 边界与证据

SFTP 界面、协议和任务管理属于程序内置实现；连接、加密和认证复用系统 OpenSSH。helper 只在认证时按需运行。当前用户授权未包含测试凭据；本地测试使用临时生成的密钥和隔离服务，不接触用户的生产主机。

保留 `docs/evaluations/review-*-20261029/` 和 `review-monitor-bounds-20261030/` 等历史审计的原始文件；后续修改不倒填旧哈希，新增正式版验收记录。Rust 账本不是整个进程 RSS 或系统库分配的硬上限，外部 ssh 进程单独报告。

## 实现取舍

Windows 安全适配优先使用系统 API，避免为了 IPC 引入常驻线程、异步运行时或额外依赖树。认证使用本机命名管道，拒绝远程客户端，私有 DACL 与随机能力值共同限制访问；客户端核对服务端进程身份。协议与秘密容器复用现有代码。具体资源模型及实际测试结果随实现补录。

当前阶段：Windows 安全适配已在准备分支 `codex/release-v0.1.0` 提交；检查点 `025b237` 的三平台原生认证、Windows 本地文件拥有者、Clippy 和 helper 构建已由 [Actions 40981013654](https://github.com/YoisakiKnd/congminal/actions/runs/40981013654) 通过。覆盖了私有票据、消息边界、能力值错误、取消、1023 字节答案、文件变更、不覆盖/显式覆盖、取消保留暂存等；这还不是三平台端到端 SFTP 或原生窗口验收。

接入时发现原有目录批量下载在 UI 中调用 `create_dir_all`，上传选择在 UI 中调用 `symlink_metadata`。正式启用前需要移入后台工作槽，并验证路径边界；不能只把旧 Unix 入口直接打开到 Windows。

接入进度：三平台编译入口、Windows helper 后缀与系统临时目录、受限 PATH 解析、认证/文件选择/任务记录/退出确认已接通；Windows 生产入口和测试入口均通过交叉检查与 Clippy。上传类型识别已移到 Service 工作槽，目录预览与上传续传源/目标回归共 7 项在本机通过。续传路径改为借用输入后在额度作用域内复制，父路径比较不再额外分配。该批接入将继续经过三平台完整原生单元测试；目录创建和打开临时副本的 UI 磁盘调用仍在处理。
