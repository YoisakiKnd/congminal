目标：补全 SFTP 的三平台交付，维持资源边界和可取消清理，再发布第一个正式版本。用户已授权完成后提交并推送 main、v0.1.0 标签和 GitHub Release。

## 发布检查

- [x] 核对现状：现有 OpenSSH 子系统协议和 Unix 传输实现可以复用；Windows 私有认证端点及本地传输尚缺；当前默认安装包未包含 SFTP/helper。
- [ ] Windows：当前用户专属 DACL 的票据与认证 IPC，端点身份验证、消息上限、超时、取消及资源归还。
- [ ] Windows：源文件身份验证、私有暂存、句柄绑定的原子发布、默认不覆盖及显式覆盖，准确保留残留/发布结果。
- [ ] 三平台：接通工作区、文件选择、认证、传输、退出确认和 helper 自动发现；功能加入默认正式构建。
- [ ] 真实 OpenSSH：主机密钥首次确认/变更拒绝、密钥及密码认证、上传/下载/目录操作、覆盖、取消、异常断连与退出。
- [ ] 原生界面：可用 macOS 窗口验证；Windows/Linux 原生检查通过 CI 或用户提供的测试环境执行。编译通过不能替代运行验证。
- [ ] 内存与性能：新适配层按既有额度准入，固定工作槽，限制路径、提示、消息和句柄；保留分配测量与传输性能原始结果。
- [ ] 正式 README、配置示例、v0.1.0 发布说明、版本号与实际功能一致。
- [ ] 三平台构建及打包默认包含主程序/helper、文档与必要资源；版本校验、SHA256、稳定标签生成正式 Release。
- [ ] 复核测试、Clippy、MSRV、交叉检查和安装包 smoke；提交源码、推送 main、打 v0.1.0 标签，核对 Actions 与正式 Release。

## 边界与证据

SFTP 界面、协议和任务管理属于程序内置实现；连接、加密和认证复用系统 OpenSSH。helper 只在认证时按需运行。当前用户授权未包含测试凭据；本地测试使用临时生成的密钥和隔离服务，不接触用户的生产主机。

保留 `docs/evaluations/review-*-20261029/` 和 `review-monitor-bounds-20261030/` 等历史审计的原始文件；后续修改不倒填旧哈希，新增正式版验收记录。Rust 账本不是整个进程 RSS 或系统库分配的硬上限，外部 ssh 进程单独报告。

## 实现取舍

Windows 安全适配优先使用系统 API，避免为了 IPC 引入常驻线程、异步运行时或额外依赖树。认证使用本机命名管道，拒绝远程客户端，私有 DACL 与随机能力值共同限制访问；客户端核对服务端进程身份。协议与秘密容器复用现有代码。具体资源模型及实际测试结果随实现补录。

当前阶段：底层 Windows 安全适配。发布尚未执行，不能把移除“实验”标记作为验收完成。
