# congminal：DeepSeek 功能接手与 Codex 资源审查交接

交接日期：2026-10-26（Asia/Shanghai）。这是当前源码的接手入口，不是“全部计划已完成”的声明。

## 1. 任务、分工与完成定义

用户最新安排：**DeepSeek 先把计划中的功能完整实现，Codex 继续界定内存边界、审查资源所有权和优化代码。** 不再把所有功能开发串行阻塞在每一个底层计费小项之后。完整目标仍是 [roadmap.md](roadmap.md) 的全部未完成项及交付清单，范围没有缩小。

| 责任方 | 负责 | 交付物 |
| --- | --- | --- |
| DeepSeek | 用户可操作的功能闭环、界面、配置、后端适配、正确性测试、操作文档 | 小批可运行功能提交，完整正常/取消/失败/关闭流程，以及下面的功能交付报告 |
| Codex | 完整内存/并发准入、所有权与原生回收审查、同负载性能、热点优化、依赖成本复核 | 分配/额度/进程/线程证据、性能对照和需要修正的接口意见 |
| 双方 | 跨模块接口、平台差异、版本/发布门槛及终端兼容 | 清晰的接口变更与验收状态，避免功能实现与资源优化互相覆盖 |

功能开发仍必须使用现有预算/任务接口、有限队列和可见失败。不能先堆出无限缓存、无限线程或阻塞 UI，再等 Codex 事后补救。详细逐字节计量和最终优化由 Codex 负责，DeepSeek 不需要为每次普通界面修改新增一整套历史性能审计。

每个功能分别记录四种状态：**实现、功能验收、资源/性能审查、平台验收**。可以“实现完成、资源审查待做”，但不能把它写成最终发布已验收。只有真实通过的原计划条目才能勾选；遇到缺机器/凭据则写明缺什么，同时继续其他工作。

不要擅自合并 main、强推、重写历史、打发布标签或替用户进行远程写操作。当前用户只授权把交接基线和本文上传独立分支；后续功能在其基础上另开分支，逐批提供可审查提交。

## 5. 必须保留的资源与正确性约束

| 边界 | 交接时约束 |
| --- | --- |
| 窗格 | 最多 8；新建失败保留旧会话、焦点、布局和历史 |
| 应用额度 | 缺省受管混合额度512 MiB，字体映射独立1024 MiB；**不是整进程堆/RSS上限** |
| 工作区历史 | 共享64 MiB，需计入所属预算和回收机制 |
| 通用运行时 | 全局固定64个工作记录、每Budget最多64工作槽，已有一个回收器；SFTP执行器另计，不能称全进程线程上限 |
| LatestTask | 每Budget最多32个存活核心；每核心1运行/1待办/1结果，失效结果不提交，提交失败可见 |
| SFTP | 单工作区共享原16 MiB子池，2活动工作器、64等待、独立回收者；元数据输入须保留原9 MiB IO余量，可能在64槽前拒绝 |
| 本地目录 | 最多512结果/8192扫描，现工作预留3 MiB；错误/截断要显式显示 |
| 路径与文本 | 使用各模块既有上限；不把应用上限当作所有OS/文件系统均能接受。macOS已有PATH_MAX1024/NAME_MAX255失败证据 |

开发规则：

1. 分配/扩容前准入；新旧块搬迁重叠也要覆盖。结果移动到 UI、缓存、回调或晚到输入时，票据一起移动。不得在交付结果时提前归还额度。
2. 新异步任务优先 `LatestTask::new_named_in` / `try_submit` 或现有受限 Service；一般常驻工作用 `runtime::prepare/spawn`。不要 `thread::spawn`、线程池或 async runtime 按点击无限创建。
3. 函数返回、取消标记、Drop、超时、`is_finished` 都不等于原生线程/子进程已回收。join 拥有者必须保留费用；未确认则保留并反馈，不能开替代回收者掩盖。
4. UI 线程不等待网络、Git全仓扫描、磁盘遍历、原生工作器join或不可控析构。250ms关闭检查是软预算，不是硬系统调用期限。
5. 请求/结果标明会话、连接代次、目录/仓库身份、请求版本；切换、关闭、重连、改配置后丢弃过期结果，不能将旧输入、认证答案或写操作投给新会话。
6. `Session::spawn_with` 同步借用配置；不要重新引入整份 Config/ShellConfig 克隆。字体任务只传字体设置。
7. 锁内只更新状态/移动值；不在锁内调用用户回调、IO或销毁任意大型负载。UI绘制复用工作集，避免每帧拼接完整目录/历史/进程列表。
8. 不能通过增加预算、取消失败断言、改摘要或只反复重跑到绿来“解决”问题。记录第一次失败和具体修正。

### SSH/SFTP 特别约束

- 加密/认证/主机校验使用成熟实现，不自写密码学；不默认关闭主机验证，不往配置保存密码或私钥正文。
- 终端、SFTP、远程 Git 和监控使用独立通道。不要把机器协议或后台命令混写现有终端 stdin/stdout。
- 无语义 hint 的认证提示保留 `Unspecified`；不能靠英文提示词猜 Secret/Confirm，也不能让 Enter 直接发送未分类答案。现有完整身份/提示审阅、显式发送、焦点与输入代次门禁必须保留。
- 私有 helper/IPC 的能力、端点、用户/进程归属、秘密清理和晚到消息校验不能为方便点击而绕过。新认证流程沿用 [设计](design-sftp-auth.md) 和 [认证UI约定](design-auth-ui.md)。
- 清理结果区分 Confirmed/Failed/Unknown，文件发布区分尝试、拒绝、已确认及不确定。不能因稍后的取消/退出把已发布或不确定提交改写为普通取消/成功。
- 默认不覆盖；重试重新核对源/目标并再次审阅，覆盖同意不复用。失败/取消可保留可识别部分文件，清记录不等于删除文件。
- 未证明后台结束时保留窗口/退出状态；不确定或清理异常的显式确认流程不能删掉。

## 6. 推荐功能实现顺序

以可操作闭环推进，不等 Codex 完成所有M4计费细项才开始M7。已有模块在功能推进中持续补齐；远程Git/监控仍依赖独立执行通道及认证，不能旁路。

### A. 接手校准和已有体验收尾

- 从本分支完整构建并跑基础测试，确认默认终端和SFTP预览的差别。
- 复用现有左右栏、目录、连接、认证和传输视图；整理连接配置别名选择、状态/错误/手动重连及帮助。
- 补 M5 密码/二次认证真实流程、每会话主题和跳板/转发配置界面，保持主机校验与配置语义。
- 补 SFTP 下载目标选择、真实原生窗口/IME/焦点认证传输，修正已识别的平台缺口；默认入口发布需通过相应审查，不能只删 feature gate。

### B. M7 本地 Git 闭环

- 从活动本地会话工作目录定位仓库；状态涵盖分支、暂存/未暂存/未跟踪、数量及受限diff。
- 先给 Git CLI 建薄适配，使用NUL分隔机器输出，不解析人类可读status；与成熟库候选保持同一模型供Codex对照。记录工具缺失和版本。
- 支持正常仓库、worktree、子模块、detached/unborn HEAD；路径保留原名字节并转义展示，处理空格/换行/前导短横线/无效UTF-8。
- 目录/命令完成/手动刷新去抖；同仓库共享快照，大仓库可取消、截断且显示不完整。目录/标签切换后的旧结果不能串用。
- 状态和diff先只读，避免外部diff/textconv等隐式工作影响可控性；写功能再接暂存/取消暂存、提交、拉取/推送和冲突查看，必须由用户明确触发并防重复。
- 不后台自动提交或推送。执行后刷新并区分失败、取消与提交结果不确定；外部Git子进程及其子进程纳入生命周期/成本说明。

### C. M7 本地与远程监控

- 右栏先实现本地CPU、内存、磁盘、会话/连接与任务状态，平台适配在后台采样；清楚标注系统/本进程、单位和采样时刻。
- CPU用计数差分；无初始样本/权限/指标不支持时显示未知，不能用0冒充。
- 固定长度环形数据，面板隐藏降频或暂停；不要每帧采样、创建线程或持续全屏绘制。
- 独立SSH执行通道先支持用户主动启用的远程Linux，不要求常驻agent；断线后保留最后时间并标失效。
- 继续补延迟、网络速率、进程列表和阈值通知，限定列表/环形容量并处理采样失败。
- 数值上限/刷新间隔如需新增，写入配置与测试，注明是设计值还是已测值，交Codex复核。

### D. M6 完整文件工作流

- 远程文件显式临时下载、大小限制和修改后回传；浏览目录不自动批量下载。
- 新建/重命名/删除需完整主机/路径确认；批量先预览影响范围。
- 递归任务限制深度、项目/字节数和待办容量，定义符号链接/循环、权限/空间不足、取消和部分成功语义。
- 续传先验证协议能力、源/部分文件版本和目标状态；不能只按长度追加或把旧覆盖确认带入新任务。
- 保持现有任务列表/进度/速度/取消/手动重试/通知/退出处置形成同一个流程，不另建不受限工作池。

### E. 远程 Git 与执行通道

- 在独立执行通道接只读远程仓库状态，明显标记主机和远程路径；命令参数使用安全结构化边界。
- 不假定终端连接或SFTP连接已共享认证；认证、超时、取消、退出/重连归属均沿用现有模式。
- 远程写功能在结果确认与取消/不确定语义完成后加入，不偷用终端输入或远端守护进程。

### F. M8 通知、美化与发布体验

- 完成主题配置档、预览/恢复默认、标签/侧栏/状态栏、图标回退、光标闪烁、命令成败标记和可读性选项。
- 透明/模糊按平台能力实现，允许关闭；不支持时基本功能完整，静止时无无用途持续重绘。

## 8. 验证命令与证据使用

新机器先装 Rust>=1.88；首次可 `cargo fetch --locked`，`--offline` 只适用于缓存已齐。Linux需要X11开发环境，Windows需要对应工具链；libssh2等候选feature的系统依赖按实际错误处理，不能删feature换取通过。

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo test --locked --features sftp-preview
cargo clippy --locked --all-targets \
  --features sftp-preview,sftp-libssh2,directory-helper -- -D warnings
cargo build --locked --release --bin congminal
cargo build --locked --release --features sftp-preview \
  --bin congminal --bin congminal-ssh-helper
cargo +1.88.0 check --locked --all-targets
```

只在已装目标时做 `--target x86_64-unknown-linux-gnu` / `x86_64-pc-windows-gnu` 的静态检查；它们不是真机运行。现有CI见 [ci.yml](../.github/workflows/ci.yml)，普通独立分支push不会自动跑其仅main/tags的push规则，可通过PR或手动workflow触发；不能把没有运行的检查写成通过。标签 `v*` 会触发发布，勿随手打标签。

最新交接源码的冻结本机证据：默认601项、预览604项和helper20项；三目标静态检查、MSRV布局/工作区/会话/字体、release通过；九份资源/SSH/SFTP结果见 [m4-config-borrow.md](evaluations/m4-config-borrow.md)。这是交接快照结果，改代码后需重新验证受影响范围。

常用隔离工具（生成测试密钥/配置，不使用用户真实凭据）：

```sh
python3 tools/check_ssh_transport.py --scenario positive --output /tmp/ssh-positive.json
python3 tools/check_ssh_transport.py --scenario interrupt --output /tmp/ssh-interrupt.json
python3 tools/check_auth_parent.py --preview-entry --output /tmp/sftp-entry.json
```

默认 `cargo test` 会忽略专用回环/原生/压力用例，不能因此声称都测过。`--exact` 必须使用完整测试名并检查实际运行数量；“0 passed”不是验收。

原始性能/分配检查器会校验源码、工具、夹具和冻结基线；早期验证器只对当时快照有效，修改后的工作不要反写它们。请给新结果新文件名，Codex负责确定需要重跑的矩阵。已有失败和首版回退必须保留。
