# 本地状态监控面板（M7 F10）

右栏新增“监控”页，显示本机 CPU、内存、磁盘与网络速率，以及最近 5 分钟的趋势曲线。数据来自 `sysinfo` 的后台采样，界面线程只读已发布的结果，不做任何阻塞读取。

## 入口、配置与快捷键

| 项目 | 值 |
| --- | --- |
| 动作 | `Action::ShowMonitorPanel`（配置名 `show-monitor-panel`） |
| 默认绑定 | `Primary+M`（macOS 为 Cmd+M，其他平台为 Ctrl+Shift+M） |
| 右栏页签 | `状态` / `Git` / `监控`，点击行 0 的左/中/右三段切换 |
| 按钮行（行 1） | `刷新`（立即采样一次，不等下一个周期） |
| 关闭 | 关闭右栏（`Primary+B` 或切到别的页）即停止采样；关右栏时释放历史与额度 |
| 阈值告警 | `[monitor] alert-cpu` / `alert-memory` / `alert-disk`（百分比，0 = 关）+ `alert-seconds` 冷却 |

`[monitor]` 段（见 `assets/congminal.example.toml`）：

```toml
[monitor]
enabled = true            # 关闭后不创建任务、不采样，面板显示“监控已停用”
interval-seconds = 1      # 1–5，采样周期
history-seconds = 300     # 60–900，保留时长，换算成固定点数（上限 900）
disk-seconds = 10         # 5–120，磁盘单独降频（比 CPU/内存贵一个数量级）
alert-cpu = 0             # 0–100，超过就发一条通知；0 = 不告警（默认全关）
alert-memory = 0
alert-disk = 0
alert-seconds = 300       # 30–3600，同一条告警的最短间隔
```

越界值只产生配置警告并保留默认，不会静默放大采样频率或历史长度（`src/config/monitor.rs` 测试覆盖）。

## 正常流程

1. 打开“监控”页立即排一次采样，随后按 `interval-seconds` 周期复查；窗口失焦或切到别的页时暂停。
2. 行 2 显示 `CPU 12% · 8 核`，行 3 显示 `内存 4.2 GiB / 7.9 GiB（53%）`，行 4 显示 `磁盘 16 GiB / 82 GiB（20%）`（挂载点不是 `/` 时追加 ` · /home`），行 5 显示 `网络 ↓1.2 MiB/s ↑96 KiB/s`（拿不到读数时是 `网络 未知`），最后一行显示 `0 秒前更新 · 每 1 秒 · 42 点`。
3. 趋势三行从状态行之前开始：`CPU`、`内存`、`磁盘`，每条按右栏可用列数把历史点分桶取最大值，按 0–100% 映射到 8 级字符梯度。
4. 历史是定长环形队列：满了丢最旧的，保留时长变化时按新容量重建，运行期不扩容。

## 网络速率（本地，Linux）

- 行 5 的 `网络 ↓… ↑…` 是**全机非回环接口**的收发速率：读 `/proc/net/dev`，跳过 `lo`，把各接口的接收字节（第 1 个字段）与发送字节（第 9 个字段）求和，再用两次采样的字节差除以时间差算速率。
- 第一轮采样只有计数器基线，显示 `网络 未知`；计数器回绕、时间差小于 100 ms 或读不到文件时同样显示未知，**不显示成 0**。
- 平台范围：本机只有 Linux 读 `/proc/net/dev`；macOS/Windows 没有零成本、零新增依赖的累计字节接口，显示未知——宁可不显示也不猜。
- 远端主机也采速率：主读数那一趟把 `/proc/net/dev` 和 `/proc/stat`、`/proc/meminfo` 一起 `cat` 回来（**不多开一趟 ssh**），在合并输出里按 `Inter-|` 表头切出网络段，交给本地同一套解析；差值口径与本地完全一致（跳过 `lo`、首轮与 <100 ms 间隔报未知）。远端间隔至少 2 秒，所以速率比本机更稳。
- 速率文案比容量更细：`300 B/s`、`2 KiB/s`、`1.2 MiB/s`（`monitor::rate`），避免低速被容量格式化成 `0 KiB`。
- 成本：多一次小文件读取 + 一次 `Instant`，本机实测把“无磁盘一轮”从 56 µs 抬到 155 µs（1 Hz 下约 0.02% 单核）。速率**不进**趋势图，历史每点只多两个 `Option<u32>`（80 字节/点，900 点上限 72 KiB）。

## 进程列表（本地）

监控页底部列出 CPU 占用最高的 5 个进程（`进程（按 CPU）` 之后每行 `名字 42% 64 MiB`）。

- 数据来源：`sysinfo` 的 `refresh_processes_specifics(All, true, ProcessRefreshKind::nothing().with_cpu().with_memory())`——只读 CPU 与内存，不读可执行路径、命令行、环境与用户表。
- 降频：进程表比全局读数贵得多，固定每 5 秒才刷一次（`monitor::PROCESS_INTERVAL`），其余采样轮次沿用上一份列表；请求里带 `processes: bool`，未到期时采样线程根本不碰 `/proc/<pid>`。
- 上限：只保留 5 条（`PROCESS_LIMIT`），名字按 24 字节截断并去掉控制字符，名字为空时显示 `#pid`；`top()` 用固定大小的小表维护前 5 名（先比 CPU、再比内存），不把整张进程表收集成 `Vec`。
- 内存：每条 `Proc` 只有 pid + 名字 + 两个数值；进程列表**不进**采样历史（历史每点仍 ≤ 80 字节），只作为面板的一份当前值保存。
- 失败：进程读取失败不影响全局读数；远端主机（`远程 <主机>`）不显示进程列表，因为要额外一次 `ssh` 采样。
- 预览：`CONGMINAL_MONITOR_PROC_PREVIEW_PATH=/tmp/monitor.ppm cargo test monitor_shows_the_busiest -- --nocapture` 导出整帧，裁右栏 280 px 得 [m7-monitor-procs.png](previews/m7-monitor-procs.png)（假采样源，两行进程）。
- 实测成本（本机 8 GiB，`cargo test monitor_sample_cost -- --ignored --nocapture`）：全局读数中位 155 µs（含网络计数器）、含磁盘 734 µs、进程表 20 ms（首次 54 ms）。进程表在监控采样线程里跑，不在 UI 线程，5 秒一次约等于单核 0.5% 的占用。

## 远程主机（首版，Linux）

活动窗格是 SSH 会话时，监控页不再读本机，而是通过独立执行通道读远端：

- 每次采样一个 `ssh -o BatchMode=yes -o ConnectTimeout=5 -o LogLevel=ERROR -o ServerAliveInterval=15 [-p 端口] [-l 用户] [-i 密钥] -- 主机 cat /proc/stat /proc/meminfo`；
  磁盘到期那一轮再加一个 `ssh … df -P -k /`。不常驻 agent、不复用终端的 ssh 连接、不额外起线程（采样仍在既有的监控任务线程里跑）。
- 采样间隔抬到至少 2 秒（`monitor::REMOTE_MIN_INTERVAL`）：每次采样都是一个子进程，按本地的 1 Hz 跑不划算。状态行显示的就是实际节奏。
- CPU 用两次 `/proc/stat` 聚合时间片的差值算区间占用率；内存已用 = `MemTotal − MemAvailable`（没有该字段时退回 `MemFree`）；磁盘取 `df -P -k /` 的 Used/1024-blocks 换算成字节。
- 认证与主机校验不简化：`BatchMode=yes` 让需要交互密码时立即失败，主机密钥仍按 OpenSSH 默认校验，应用不代替用户接受新指纹。
- 往返耗时：主读数那一趟（`cat /proc/stat /proc/meminfo`）的耗时记进标题第一行，写成 `远程 dev@host · 往返 42 ms`；磁盘那一趟按 `disk-seconds` 降频，不计入这个数字，否则数字会忽大忽小。本机采样没有网络跳，标题里不出现往返耗时。
- 读不到就报错：连不上、远端没有 `/proc`、输出无法解析或超过 64 KiB，一律 `Error::Remote`（“远程主机未返回读数”），**不把 0 当读数**写进历史；失败进通知中心（`监控 · 采样失败`，每次失败只报一次）。
- 切换窗格/主机时清空历史、取消在途采样并重新排期，两台主机的曲线不会混在一起；远端目标与 Git 页用的是同一份 SSH 配置档。
- 取消：采样任务带取消令牌，取消或 5 秒超时会杀掉 `ssh` 子进程（`try_wait` 轮询 10 ms 一次），关闭右栏、失焦、切页都能立刻停下。

## 阈值告警

三个阈值默认都是 0（关闭）：阈值取决于机器和负载，由用户按需打开，升级后不会突然开始弹通知。

- 每轮采样落地后比对最近一个采样点：CPU 用全局使用率，内存与磁盘用 `percent(used, total)`；这一轮没刷新磁盘（`disk_total == 0`）时**不判磁盘**，避免把“没读数”当成 0% 用量。
- 同时超多个时按 `CPU → 内存 → 磁盘` 取第一个，一条通知只报一个指标，文案是固定的 `监控 · CPU 超过阈值` / `监控 · 内存超过阈值` / `监控 · 磁盘超过阈值`（不含读数、路径、主机）。
- 冷却：上一条告警发出的时刻 + `alert-seconds` 之前不再置位；冷却从**发出**开始算，不是从回落开始，所以读数在阈值附近抖动不会刷屏。
- 告警走通知中心（`Source::Monitor` + `Category::MonitorAlert`），受 `[notifications] monitor` 开关与 `mute-hosts` 约束；同类在 `dedupe-seconds` 内合并成一条并显示 ×N。状态页点击该行跳到监控页。
- 采样失败与阈值告警是两件事：失败只报一次（恢复后重新武装），告警按冷却重复。

## 取消、失败、过期与关闭

| 情况 | 行为 |
| --- | --- |
| 窗口失焦 | 停止排新采样（`LatestTask::invalidate`），保留历史，行 5 显示“已暂停（窗口失焦）· 保留 N 点” |
| 切到状态页 / Git 页 | 与失焦相同：释放采样线程、保留历史与额度，切回来立即续采，曲线不断档 |
| 关闭右栏 / 退出 | 取消在途采样，释放历史、采样线程与 `Kind::Monitor` 额度，`bytes()` 归零 |
| 采样超期 | 超过 3 个周期没有新数据（例如机器休眠后唤醒）显示“数据过期 · 上次更新 N 秒前”，不把旧值当新值 |
| 额度不足 | 显示“监控额度不足，已停止采样”，不创建线程 |
| 线程启动失败 | 显示“监控采样线程不可用”，下一周期重试 |
| 平台不支持 | 显示“此平台不支持本地状态采样”，不显示成 0 |
| 磁盘无读数 | 该轮没刷新磁盘（`disk-seconds` 未到）时沿用上一轮读数；一次都没读到则显示“磁盘 暂无读数” |
| 网络无读数 | 首轮采样、非 Linux 本机、远端读不到 `/proc/net/dev` 或计数器回绕时显示“网络 未知”，不当成 0 B/s |

代次隔离：每次提交递增 `generation`，回包必须匹配当前代次；暂停、切页或关闭后到达的迟到结果直接丢弃，不会写进新历史。

## 绘制细节

- 趋势图用 ASCII 梯度 `._-=+*#@`，不用 U+2581–2588：默认字体没有块元素，画出来是一整块实心矩形，看不出高低。
- 表头行进入绘制前按显示列裁剪（`crate::term::clip`），超宽不会挤到下一行；`chrome()` 本身也会在右边界截断。
- 曲线宽度 = 右栏字符宽度 − 标签列（5 列），与右栏宽度联动，不额外分配缓冲。

## 后台任务、线程、子进程、缓存与数据所有权

- 每个打开的面板一个 `LatestTask` 工作线程（命名 `monitor`，受全局 64 线程上限与 `LatestSlot` 准入）；同一时刻至多一个在途采样，新请求覆盖旧请求。
- 采样器（`sysinfo::System` + `Disks`）在该线程内惰性创建并长期复用，冷启动成本只付一次；暂停或关闭时线程结束、采样器随之释放，不留后台轮询。
- 无子进程：本地读数全部走系统调用。
- 缓存只有一个定长历史环形队列（默认 300 点 × 80 B ≈ 23 KiB，上限 900 点 ≈ 72 KiB），没有磁盘缓存，不跨会话共享；网络速率只保留上一次的计数器与时间戳（`Option<(u64, u64, Instant)>`）。
- 额度：`Kind::Monitor` 申请 `RESERVED(256 KiB) + 历史字节`，关闭归还；历史按容量计费，不随点数缩小。
- 阈值告警不新增线程、子进程或缓存：只在已有采样结果上做三次比较，`alert_pending`/`alert_at` 两个字段随面板一起释放。
- 数据所有权：`Panel` 持有额度票据、历史、任务句柄与最近错误；`Workspace` 持有 `Panel`；线程内持有采样器。回包只带 `Sample`（`Copy`）与挂载点字符串。
- 成本与依赖选择见 [监控评估](evaluations/m7-monitor.md)：本机常规一轮约 155 µs（含网络计数器）、含磁盘约 734 µs，磁盘因此单独降频到 10 s。

## 已知限制与未验收项

- 远端只支持 Linux（依赖 `/proc` 与 POSIX `df`）；macOS/BSD 远端未适配。
- 没有真机 SSH 主机与凭据：远端路径的测试用假 `ssh`（透传到本机脚本）验证命令形状、解析、取消与错误分类，**不等于**在真实远端验证过。
- 远端每 2 秒一个 `ssh` 进程；长连接复用（ControlMaster）与批量采样未做。
- 远端磁盘只取 `/`，多卷、挂载点列表与网络文件系统未覆盖。
- 远端速率是**主机整体**的非回环汇总（和本机同口径），没有按接口或按进程拆分；远端只支持 Linux。

## 未验收项（原文）

- 只有本地采样：远程（SSH）主机监控未实现，需要独立执行通道，按路线图另开一批。
- 没有分核 CPU、网络速率与进程列表；阈值告警已提供（见上文），但只有“超过即通知”，没有回落通知、持续时间窗口（例如“连续 5 分钟超过 90%”）或按指标单独冷却。
- 只有一块磁盘：多卷时取“非只读、最外层挂载中总量最大”的一个，界面不提供切换。
- 历史只在内存里，不落盘；重启后重新累积。
- 只在 Linux 本机验证；macOS/Windows 未运行，交叉编译不算真机验证。
- 右栏宽度很窄（约 20 列以下）时曲线会被裁到几列，没有做横向滚动或缩略模式。
