# M4 流式重排

更新：2026-10-21。已把软换行路径从“拼接所有逻辑长行，再切回屏幕行”改为逐段消费输入，接入现有终端缩放。硬行整体转移捷径继续保留。没有新增 Cargo 包、常驻线程、周期任务或外部程序适配。

## 当前实现

- 重排内核以状态机推进：裁剪尾部空白、分析当前逻辑行、转移短行/复制长行、释放无需保留的剩余输入。长逻辑行只记录长度、输入范围和坐标标记，不创建与逻辑行等长的 cell Vec。
- 短逻辑行优先直接转移首个输入缓冲；长行消费后立即回收旧行。备用池最多两个 Vec，只有容量足够且不超过新宽度保留上限的缓冲才能进入；连续窄 cell 整段复制，宽字符及其占位格单独处理。输出行/索引仍有上限，先淘汰再插入。
- 结果保留 VecDeque；同步消费与 UI 两条路径都能直接交给历史接管行索引，只把屏幕部分取成小 Vec。UI 在原索引中分片轮转校验，拒绝单行超额项，再分片裁剪到满足行数和容量额度的最新后缀；交接不重新分配或扫描整表。索引容量超过保留行数两倍且超过 32 槽时，改为分片迁移小后缀，避免少量文本长期持有大空表。
- 光标、软换行、彩色空白、组合字符属性与屏幕顶端仍按原算法映射。裁剪屏幕尾部空白不会缩小原始屏幕行数。确认光标后的一屏输出已足够时，剩余输入分批释放，避免逐 cell 构造最终不会显示的行。
- 重排输入、输出、当前行、两个备用缓冲和索引扩容都由原 ResizePlan 的临时预留覆盖。流式路径不再需要四份输入的拼接增长余量，改为一份输入、输出保留容量及固定行缓冲/索引余量。准入仍在取走历史之前；失败时原文本、光标、选区和 PTY 尺寸保留。
- 输出索引的最后一次扩容按保留行数上限截断，不再默认翻倍到超过上限的容量；没有收紧历史文本配额或放宽共享准入模型。取消清理先释放其他输出及其空索引，再回收历史借用的聚合额度。

持久历史按 cell 容量与完整行索引容量持有汇总票据；同步消费时连同行索引一起移入工作集，UI 只读源则继续持有旧票据。已准入工作集向新历史原子转移额度，不先释放再抢领；输出接管后还可能把屏幕行推入历史，须待该步骤完成才归还工作集余量。取消与退休先销毁行和索引，再释放所属额度。

缓冲复用沿用容量计费，历史最终仍受实际容量额度约束；复用旧容量可能改变同一字节额度下保留的行数。不能将“复用”解释为增加历史配额或保证与旧版本保留完全相同的历史行数。

## 步进边界

内核支持 `step(cell_budget)`。预算按扫描、复制、填充和回收工作计数，是合作式工作量；单行扫描、分配或系统分配器调用仍可能超过本步预算。新增手动基准分别记录推进片段和收尾成本：

```sh
cargo test --offline --release bench_stream_soft_slices -- --ignored --nocapture --test-threads=1
```

主屏宽度变化且历史与主网格容量合计大于 256 KiB 时，UI 已使用下面的只读分片路径；同步消费内核保留用于小网格和对照验证。片段耗时不能单独当作端到端缩放延迟。

## UI 调度

- 事件中只计算常数大小的容量/行数统计并预留目标网格、一般重排工作集，不检查全部历史的硬行可复用性。同步硬行捷径的低额度保证不适用于此路径。
- 作业不保存借用引用；每个步骤从仍由终端持有的只读旧行读取，构造独立输出。旧屏幕、历史、选区、搜索和坐标查询在准备期间仍可使用。长行不拼接；短行只复制当前有界行缓冲。这里不能复用仍被旧终端持有的输入 cell，峰值和总成本可能高于同步消费路径。
- 每个 Session 每次 poll 约 500 µs 合作式预算，以 4096 cells 为单位推进。阶段包括重排、屏幕整理/补齐、历史准入、变矮推行/变高拉回、宽字符修复、备用网格准备和提交。行扫描、索引扩容、分配器、固定上限的元数据操作不可抢占，因此不是硬实时上限。
- 工作区同时只允许一个窗格构造/退休输出，释放旧状态后轮换，不让四份新历史同时存活。焦点切换不抢走已有槽；作业结束或取消清理完成后，按轮转顺序选择下一个待处理窗格，关闭槽主也可继续。所有初始票据仍须先准入，其他会话的正常解析/事件仍按原轮转预算运行。
- 结果准备好后交换历史/两套网格所有权，更新 epoch、光标、命令标记及 PTY 尺寸；提交不遍历全部历史。新网格改持目标票据，旧票据与工作集预留继续随旧状态保留，分片销毁全部旧行后才归还。
- 进行中的新尺寸只保留一个最新目标。取消先分片回收未提交输出，旧终端保持原状；完成清理后重新准入最新目标，不累计任务或预留。若排队目标届时被拒绝，保留现有终端并反馈，不承诺该排队目标的整组窗格原子准入。
- 文本 epoch/revision、尺寸、主备用屏状态、历史行数/容量/丢弃水位/配额参与版本检查。配置/历史额度或告警改变源时，旧作业先取消清理再重新准备，不能提交过期结果。
- 准备与取消清理期间暂停该 Session 的 PTY 解析，输出继续使用 1 MiB 有界队列及现有读线程背压，键盘仍写入 8 MiB 有界输入队列。提交后恢复解析，退休清理可与解析交替。回显可能等到重排提交；不能把输入入队延迟当作回显延迟。
- 单窗格与工作区 deadline 都包含未完成作业；隐藏窗格也继续推进。画布已经缩小时旧网格的绘制 damage 与输入法光标框均裁剪到新画布。单窗格准入失败保留原画布/尺寸，不再把失败返回值当作退出请求。

小于等于阈值的网格、仅改高度、备用屏幕及画布重新分配仍有同步路径。退出/关闭直接销毁 Session 时，Rust 析构仍可集中释放其当前历史及作业状态；本轮没有把所有关闭销毁纳入窗口级退休队列。跨 tick 接入不等于所有 GUI 停顿均已消除。

## 验证与后续

重排累计 2100 组案例对照原始参考算法，比较普通调用、预检调用、1/17/4096 cell 消费步进和 17 cell 只读步进。另有 1000 组历史接管/逐行 push 对照；600 个种子中有 585 组宽度变化的终端完整形态/光标/历史/备用屏对照（跳过未变宽种子）；以及每阶段取消、宽字符修复、配额变化、退休额度、真实 PTY 输入/尺寸、连续目标合并、满输出队列关闭、单输出所有者、关闭槽主、画布/IME 裁剪、拒绝不退出和历史计费/压力回收等验证。新补输出索引上限、满账本直接交接、紧配额下与整表接管对照及校验/淘汰/收紧中途取消。Debug/release 各 267 项通过，13 项手动基准忽略；三平台交叉检查不代替原生运行。

同步消费内核的历史测量见 [流式评估](evaluations/m4-stream.md)，UI 路径见 [调度评估](evaluations/m4-tick.md)，计费与回收验证见 [历史计费评估](evaluations/m4-history.md)，本轮索引交接和分配峰值见 [索引评估](evaluations/m4-index.md)。持久历史 cell 和行索引已接入共享计费，全部元数据计费仍未完成；512 MiB 继续是混合准入额度，不能当作全部堆或 RSS 上限。

后续优化只读输出峰值及完成时间，补其余同步路径和关闭清理的延迟边界。启动成本、三平台真机、真实窗口输入到呈现及 30 分钟稳定性仍待验收。
