# congminal v0.2.6

新增可选的 GPU 绘制，标签和会话名显示前台程序：

- `window.renderer` 新增 `"gpu"` 和 `"auto"`（默认仍是 `"cpu"`，改后需重启）。终端和界面照常由 CPU 生成绘制列表，再交给 GPU 回放：Linux 用 EGL + OpenGL ES 3，macOS 用 Metal，Windows 用 Direct3D 11，均在运行时加载系统库，不是编译期依赖。`"auto"` 只在有硬件加速时用 GPU，软件光栅器（llvmpipe、WARP）退回 CPU。GPU 创建失败或运行中出错时自动退回 CPU，原因写进 `CONGMINAL_TRACE` 日志。Windows 上设置了 `appearance.opacity`（半透明窗口）时用 CPU。
- 程序没有设置标题时（如 nvim、多数 TUI），标签显示前台程序名，不再显示 shell 标题；Windows 上 ConPTY 默认的完整 exe 路径标题缩短为程序名。Unix 读取终端前台进程组；Windows 把每个 shell 放进只用于查询的 Job 对象（允许脱离，关闭时不结束进程）。只在有输出后探测，最多每秒一次，空闲窗格不唤醒。

GPU 回放与 CPU 绘制逐像素对照：CI 上三个平台都通过（Linux Mesa llvmpipe、macOS 托管虚拟机的 Apple Paravirtual device、Windows WARP），本机还在 Xvfb 下的真实窗口和 wine 下的 Windows 版里验证了截图、分屏、改尺寸和故障退回。Mac 和 Windows 真显卡上的窗口呈现和性能尚未验证，所以默认仍用 CPU；可以用 `ci/check-macos-metal.sh`、`ci/check-windows-d3d11.ps1` 在真机上检查。

不新增生产依赖、常驻线程或定时任务。升级后退出旧窗口并重新打开。许可证为 GPL-3.0-only。
