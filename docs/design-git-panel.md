# 本地 Git 面板（M7：状态、受限 diff 与显式写操作）

右栏新增 Git 页，显示活动窗格工作目录对应仓库的分支、暂存/未暂存/未跟踪条目和受大小限制的 diff，并支持**用户显式触发**的暂存、取消暂存、提交、拉取与推送。写操作只有五个：`git add -A --`、`git restore --staged --`（未出生 HEAD 用 `git rm --cached -r --`）、`git commit -m`、`git pull --ff-only` 与 `git push`。没有 stash、没有强制重置、没有 `--force` 推送，也不弹凭据（`GIT_TERMINAL_PROMPT=0`，缺凭据直接失败）。

## 入口、配置与快捷键

| 项目 | 值 |
| --- | --- |
| 动作 | `Action::ShowGitPanel`（配置名 `show-git-panel`） |
| 默认绑定 | `Primary+G`（macOS 为 Cmd+G，其他平台为 Ctrl+Shift+G） |
| 右栏页签 | `状态` / `Git`，点击行 0 左半/右半切换 |
| 按钮行（行 1） | 列表页八列：`刷新`、`差异`、`暂存`↔`取消暂存`（同一按钮按选中条目切换，选中冲突条目时变成 `解决`）、`全部暂存`、`提交`、`拉取`、`推送`、`分支`；提交输入打开时只有 `提交`、`取消`（新分支名输入是 `新建`、`取消`）；diff 页：`刷新`、`暂存侧`↔`工作区`（同一按钮切换）、`返回`；冲突解决页四列：`刷新`、`保留我方`、`保留对方`、`返回`；分支页五列：`刷新`、`切到`、`新建`、`删除`、`返回` |
| 拉取/推送 | 需要**两次点击**：第一次只进入确认态（按钮变成 `确认拉取`/`确认推送`，`提交` 那一列变 `取消`），10 秒内在同一个按钮上再点一次才执行；超时、点 `取消` 或改点另一个远端按钮都会作废 |
| 删除分支 | 同样需要两次点击（`删除` → `确认删除`，`返回` 列变 `取消`）；当前分支直接拒绝并说明原因 |
| 窄侧栏标签 | 按每槽可用显示列降级：完整（`取消暂存`）→ 双字（`撤存`）→ 单字（`刷 差 撤 提 拉 推`），不会被裁成半个词 |
| 列表行（行 4 起） | 单击只改变选中项（高亮），不打开 diff；“差异”按钮才打开选中条目的 diff |
| 提交输入 | 点“提交”后打开，字符/退格/左右/Home/End 都进入输入框；`Enter` 提交、`Esc` 取消；输入法组合串只显示不落盘，平台提交的文本按 UTF-8 插入 |
| 关闭 | 关闭右栏（`Primary+B` 或点击 `状态` 页）即取消在途查询并释放快照；在途写操作会跑完再释放任务 |

`[git]` 段（见 `assets/congminal.example.toml`）：

```toml
[git]
enabled = true            # 关闭后不创建任务、不运行 git，面板显示“已停用”
# program = "/usr/bin/git"  # 不写则用 PATH 中的 git
refresh-seconds = 2       # 0.5–60，实际下限 1s
timeout-seconds = 20      # 1–120，超时杀子进程并保留上一次结果
max-files = 2000          # 上限 5000
diff-mib = 8              # 上限 32
```

越界值只产生配置警告并保留默认，不会静默放大预算（`src/config/git.rs` 测试覆盖）。

## 正常流程

1. 打开 Git 页后，面板取活动窗格的目录：远程会话直接显示“未知”（远程通道未实现）；否则用 shell 的 OSC 7 目录，其次配置档/全局 `working_directory`，最后进程当前目录。
2. 首次查询延迟 300 ms 去抖后提交，随后按 `refresh-seconds`（至少 1 s）周期复查；`刷新` 按钮或重新打开面板会立即重排。此外每 500 ms 检查一次**仓库元数据指纹**（`.git/index`、`.git/HEAD`、`.git/refs` 的长度与修改时间，裸仓库直接读根目录下的同名路径）：终端里 `git add`/`commit`/`checkout` 会动这些文件，指纹一变就立刻排一次刷新，不必等周期复查。工作树里改文件不碰元数据，仍然只靠周期复查——面板不扫目录树，所以不会因为大仓库而变贵。远端仓库（每次 stat 都是网络往返）与面板隐藏时都不做这项检查。
3. 行 2 显示 `分支 master · repo`（detached 显示 `分离 HEAD abc1234`、未出生显示 `尚无提交`、裸仓库显示 `裸仓库 · 目录名`），行 3 显示 `暂存 0 · 未暂存 1 · 未跟踪 1`，超过 1 s 的查询追加 ` · 慢 1.2s`。
4. 行 4 起按路径排序列出条目，两列状态字母（`M`/`A`/`D`/`R`/`?`/`U` 等）与转义后的文件名。
5. 单击条目只选中（行高亮）；点 `差异` 打开选中条目的 diff，默认看有改动的一侧，diff 页可在工作区/暂存侧之间切换，`返回` 回到列表并释放 diff 文本。
6. 点 `全部暂存`（第 4 列）执行 `git add -A`，把新增、修改、删除与改名一次放进索引，不需要先选中条目，冲突条目也会被标记为已暂存；裸仓库与远端只读时只提示不发请求。
7. 选中条目后点 `暂存`：执行 `git add -A -- <路径>`（删除与改名同样进入索引）；已经全部进入索引的条目，同一个按钮变成 `取消暂存`，执行 `git restore --staged -- <路径>`（还没有任何提交时用 `git rm --cached -r --`，因为没有 HEAD 可回退）。
8. 点 `提交` 打开提交输入（固定 4096 字节额度），输入信息后 `Enter` 提交、`Esc` 取消；成功后立刻重读状态，失败保留错误提示并去抖重试。存在未解决冲突（`UU`/`AA`/`DD` 等）时按钮不打开输入，直接提示“有未解决的冲突，先点‘解决’选一侧”。
9. 选中冲突条目时第三列变成 `解决`，点它进入冲突解决页：行 2 显示 `解决冲突 › <状态字母><路径>`，行 3 是提示；点 `保留我方` 或 `保留对方` 执行 `git checkout --ours|--theirs -- <路径>` 写回工作区，成功后紧接着 `git add -- <路径>` 标记已解决，摘要为“已保留我方 1 个文件并标记已解决”。成功后面板自动回到列表并重读状态；失败（例如 delete/modify 冲突里该侧没有文件）显示 git 的原话，停在解决页可以换另一侧。`返回` 退出解决页，不做任何写操作。
10. 点 `拉取`：确认态下再点一次执行 `git pull --ff-only`，只做快进；分叉时 git 自己拒绝，界面显示错误摘要且不生成合并提交、不改工作区。
11. 点 `推送`：确认态下再点一次执行 `git push`，推到当前分支已配置的上游；没有上游时显示 git 的错误摘要。摘要取最后一条引用更新行（如 `abc1234..def5678  HEAD -> main`），不会把 `To <远端地址>` 带进界面或通知。
12. 拉取/推送的结局和暂存/提交一样进通知中心：`Git · 拉取完成`、`Git · 推送完成`（固定文案，不含路径、分支外的正文或远端地址）。
13. 点 `分支`（列表页第 8 列）进分支页：行 2 显示 `分支 › <当前分支>`，行 3 是提示，行 4 起列出本地分支——当前分支带 `●` 且默认选中，点一行只改变选中。五个按钮：
    - `切到`：第一次点击进入确认态（提示“再点一次‘确认’切到 <名字>（未提交改动会保留）”），窗口内再点才执行 `git switch <名字>`；
    - `新建`：打开名称输入（上限 255 字节，与提交信息的 4096 字节分开），`Enter` 执行 `git switch -c <名字>`，成功后摘要“已新建并切到 <名字>”；
    - `删除`：第一次点击进入确认态（提示“再点一次‘确认’删除 <名字>（只删已合并的分支）”），窗口内再点才执行 `git branch -d <名字>`；当前分支直接拒绝，未合并的分支由 git 自己拒绝并把原话交回；
    - `返回`：退出分支页；确认态下该位置变成 `取消`，只撤确认不离开页面。
    三种写操作成功后分支列表与状态快照一起重读，结局同样进通知中心。分支名在适配层先校验（非空、≤255 字节、不以 `-`/`.`/`/` 开头、不含 `..`、只允许字母数字与 `-._/+`），非法名不交给 git。

## 取消、超时、失败、超限与关闭

| 情况 | 行为 |
| --- | --- |
| 切走页签 / 窗口失焦 / 关右栏 | 取消在途查询（`LatestTask::invalidate`），结果丢弃；失焦保留旧快照，关栏释放快照与目录票据 |
| 切换窗格或目录 | 同一仓库（新目录在当前快照根内）复用旧结果；否则清空并重新去抖查询 |
| 超时 | 到 `timeout-seconds` 杀掉子进程并 `wait`，错误行提示超时，保留上一次结果 |
| 非仓库目录 | 显示“不在 Git 仓库中”，不启动重试风暴（按周期复查） |
| 缺少 git 程序 | 显示“找不到 git 可执行程序”，不创建任务 |
| 额度不足 | 查询前按 `Kind::Git` 申请内存票据，失败即报“额度不足”，不启动子进程 |
| 大仓库 | 条目数到 `max-files`、status 输出 4 MiB、diff 8 MiB 时截断并标 `已截断`；diff 最多 8000 行 |
| 写操作进行中重复点击 | 直接忽略（`write_loading` 期间不再受理），同一时间只有一个写操作，不会两个 `git` 抢同一个索引 |
| 写操作期间关闭右栏 | 任务保留到它自己结束再释放：中途杀 `git` 可能留下 `index.lock`，宁可等这次有界（`timeout-seconds`）的写完成 |
| 提交信息为空 | 面板层直接拒绝并提示“提交信息为空，已取消”，不启动子进程 |
| 提交失败（身份未配置、钩子拒绝、空白信息等） | 显示 git 的错误摘要（最多 200 字节、无换行），不改动工作区 |
| 有未解决冲突时点“提交” | 不打开输入、不启动子进程，提示先解决冲突 |
| 拉取遇到分叉 | `--ff-only` 直接失败，错误摘要进第 3 行，HEAD 与工作区不变（测试断言仍是本地提交） |
| 推送没有上游 / 缺凭据 / 远端拒绝 | 显示 git 的错误摘要；不重试、不弹凭据、不降级成强制推送 |
| 远端操作超时 | 联网操作至少给 `NETWORK_TIMEOUT`（60 s）且仍以 `MAX_TIMEOUT`（120 s）封顶；超时杀子进程并归还额度 |
| 确认态过期 | 10 秒窗口过后自动作废并提示“推送确认已过期，未执行”，避免很久以后再点一次被当成确认 |
| 关闭应用 | 任务在 `Drop` 中取消，子进程被杀，票据归还 |

代次隔离：每次查询递增 `generation`，回包必须同时匹配 `owner`（窗格 id）与 `generation`，切窗格/切目录后的迟到结果直接丢弃。

## 远程仓库（只读）

SSH 窗格里的 Git 页不改用终端的连接，而是每次查询另起一个独立 `ssh` 进程：
`ssh -o BatchMode=yes -o ConnectTimeout=10 -o LogLevel=ERROR -o ServerAliveInterval=15 [-p 端口] [-l 用户] [-i 密钥] -- 主机 git -C <远端目录> <子命令>`。
远端目录取自远端 shell 报告的 OSC 7 目录，只作为参数传递，不经过 shell 拼接。

- **认证与主机校验不简化**：`BatchMode=yes` 只是让需要密码时立即失败，不会在后台等一个输不进密码的提示；`StrictHostKeyChecking` 保持 OpenSSH 默认，应用不代替用户接受新指纹。失败按 stderr 分成三类提示：主机密钥未确认 → “先在终端里连接一次并核对指纹”；`Permission denied`/`too many authentication failures`/`no such identity` → “先用终端连接一次，或加载密钥/agent”；其余走有界 stderr 摘要。
- **只读**：按钮只保留 `刷新` 与 `差异`；`toggle_stage`、`open_commit`、`request_remote`、`open_resolve` 在远端一律拒绝并写“远程仓库暂只支持只读查看”，不启动任何写任务。
- **标明远程**：状态行前缀 `远程 · `；标题行仍是分支与仓库名。远端目录还没报告时第一行是“远程目录未知：先在远程终端进入仓库目录”，不是“路径无效”。
- **不做元数据指纹**：远端仓库的 `stat` 也要走一次 SSH，指纹检查只用于本地仓库。
- **不复用本地快照**：通道（程序/主机/用户/端口/密钥）变化时清空快照、diff、选中项、待确认状态与提交输入，再按去抖重查；本地仓库与远端仓库永远不会共用一份结果。
- 每个查询仍是 `git` 模块的一次 `run()`：一个子进程 + 两个读取线程（固定工作池）、账本票据覆盖 stdout/stderr 缓冲，取消或超时杀掉子进程；`ssh` 只是把命令搬到远端，线程与额度模型不变。

## 后台任务、线程、子进程、缓存与数据所有权

- 每个在途查询一个 `LatestTask` 线程（`git-status` / `git-diff` / `git-branches`，命名线程，受全局线程预算准入）；同一类查询一次只有一个在途请求，新请求覆盖旧请求。分支查询只在分支页打开时才有，退出分支页或关栏即取消。
- 写操作（暂存/取消暂存/提交/拉取/推送/切分支）共用一条 `git-write` 任务线程：同一时间最多一个在途写操作，`generation` 与 `owner` 一样参与校验，关闭面板后仍会结算。拉取/推送沿用同一线程与同一份票据模型，只是子进程时限更长（60 s，上限 120 s），没有额外线程或缓存。
- 每次查询最多一个 `git` 子进程（`run()`），stdin 关闭，stdout/stderr 各一个托管读取线程（`runtime::prepare("git-io")`），超限后继续读完丢弃。
- 缓存：仅保留最近一次 `Snapshot`（最多 5000 条、status 输出 4 MiB）、一份 `Diff`（最多 8 MiB）与一份分支列表（最多 200 个分支、每个名字 ≤255 字节），都按 `Kind::Git` 计费；退出分支页释放列表，关闭面板即释放全部。提交输入另有 4096 字节 + 256 字节的固定票据，取消或提交后立即归还。没有跨进程/磁盘缓存。
- 写请求的票据覆盖仓库根路径、路径列表与提交信息（`WriteRequest::new` 一次 `lease`），回复对象持有到被消费为止。
- 数据所有权：`Panel` 持有目录票据、快照、diff 与任务句柄；`Workspace` 持有 `Panel`；子进程与读取线程由 `run()` 内部回收。
- 环境：`GIT_OPTIONAL_LOCKS=0`（不抢 index.lock）、`GIT_TERMINAL_PROMPT=0`（不弹凭据）、`GIT_PAGER=cat`、`LC_ALL=C`。

## Git CLI 与库的比较结论

先交付 CLI 只读路径，理由：`git status --porcelain=v1 -z` 是稳定机器接口，NUL 分隔天然处理空格/换行/非法 UTF-8 路径；worktree、子模块、detached HEAD、未出生 HEAD、裸仓库与全局配置（`core.excludesFile`、`.gitignore`）语义与用户命令行完全一致，无需自建索引缓存。`git2` 需 libgit2 C 依赖与自有配置解析，`gix` 需要自建索引并与其 ignore 实现保持一致；两者都会引入第二套仓库语义。库路径的收益（无子进程、可增量读索引）留到需要高频刷新或写操作时再评估，届时转换为同一 `Entry`/`Snapshot` 模型即可（`src/git/mod.rs` 已按此分层：`status()`/`diff()` 是唯一接触子进程的地方）。

## 已知限制与未验收项

- 远程会话（SSH）的 Git 状态未实现，面板显示“未知”；远程写操作与远程监控同批处理。
- 冲突只能整文件选一侧（`--ours`/`--theirs`），没有逐段合并（hunk 级）与三方对比视图；`git checkout --ours` 对 delete/modify 冲突会失败，界面把 git 的原话交回，需要到终端处理。解决后不会自动 `git commit`，仍由用户在面板里显式提交。
- 拉取只做 `--ff-only`：需要合并或变基时请到终端处理；推送不支持 `--force`、`--tags`、多远端或指定远端/分支。
- 拉取/推送的摘要只取 git 输出的一行，不显示 ahead/behind 计数（避免为一次刷新多起两个子进程）。
- 远端认证沿用用户 git 配置（SSH agent、credential helper）：需要交互输入口令的远端会在 `GIT_TERMINAL_PROMPT=0` 下直接失败，不会弹窗。
- 提交不支持 amend、签名选项与多段信息。
- 分支页只列**本地**分支（`refs/heads`），没有远端分支、重命名、强制删除（`-D`）与“删除远端分支”；超过 200 个分支只列前 200 个并提示“只列出前 N 个”。切换与新建都用 `git switch`，需要 git ≥ 2.23（更老的 git 会显示它的错误摘要，不会静默降级成 `checkout`）。
- 切分支不做 `git stash`：未提交改动跟着走或由 git 自己拒绝，界面把 git 的原话交回；不提供“切走前自动暂存”。
- 提交时沿用用户 git 配置（含 `commit.gpgSign`）：需要口令的签名会在 `timeout-seconds` 后被杀并报超时。
- 子模块内部改动只按父仓库的 ` M` 记录显示，未递归进入子模块。
- shell 未发 OSC 7 时回退到配置的 `working_directory` 或进程当前目录，可能与终端里的实际目录不同（普通交互 shell 都会发 OSC 7）。
- 只在 Linux 本机验证；macOS/Windows 未运行，交叉编译不算真机验证。拉取/推送只在本地裸仓库（文件路径远端）上验证，没有真实 SSH/HTTPS 远端与凭据，网络延迟、代理与认证失败路径未在真机采样。
- diff 长行（如 `diff --git a/… b/…`）超出右栏宽度时按列裁切，未折行，也没有横向滚动；折行会改变行号与滚动映射，留到下一步统一处理。
- 大仓库已实测 2 万文件（`status` 中位 124 ms、截断到 5 000 条时 234 ms，见[大仓库实测](evaluations/m7-git-large-repo.md)）；10 万级条目、超大 diff 与网络文件系统仍未采样。
